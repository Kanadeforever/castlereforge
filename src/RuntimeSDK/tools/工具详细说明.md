# RuntimeSDK 工具详细说明

## `runtime_sdk_check.py`

### 用途

这是 RuntimeSDK 自制的合同、PE 和发行检查器，服务 ABI 回归与 build_all 交付验收。

它不运行游戏、不加载 DLL、不访问只读“参考资料”目录，也不会修改源码或产物。

### 当前检查内容

1. 必需 ABI 头、导出表、测试文件、构建脚本和说明文件存在；
2. 设计冻结的 magic、版本、结构大小和关键函数名存在；
3. 公共头不包含 `windows.h`、STL、`size_t` 或公开 `bool`；
4. `CastleRuntime.def` 只导出 `CastleRuntime_GetApi`；
5. build.bat 中包含中文的 `echo`/注释行以两个半角空格结束；
6. `--require-dll` 验证 Runtime PE32、DLL、入口、唯一导出和 KERNEL32-only；
7. `--require-release` 验证七个 ASI 的标准导出、Runtime 部署、SaveEnhance 随包说明；
8. 检查无 CRT `memcpy/memset` 对象确实进入 Runtime 正式链接命令；
9. 检查损坏 Runtime 的静默加载保护和错误模式恢复测试没有被移除；
10. 检查 Schedule 的 Bootstrap/Loader-ready 闸门及其“外层通知前零执行、通知后运行”回归没有被移除；
11. 检查 GetProcAddress 地址统一转换助手存在，并拒绝 Client/Entry Gate 恢复直接函数指针强转；
12. `--require-release` 拒绝 build 中的 obj/lib/exp/ilk/pdb 编译垃圾。

### 与编译测试的分工

文本检查只能证明“符号写进文件”，不能证明编译器得到正确布局。

`tests/abi_layout_test.c` 才负责真实验证：

- x86 指针大小；
- 每个公开结构 `sizeof`；
- 根函数表和关键字段 `offsetof`；
- 同一公共头可同时被 C/C++、MSVC/Clang 编译。

`build.bat` 会先运行四组编译，再调用本工具。两者任意一个失败，里程碑都不通过。

### 单独运行

```bat
python tools\runtime_sdk_check.py

python tools\runtime_sdk_check.py --require-release
```

工具会自动从自身位置向上寻找仓库根目录，不依赖当前工作目录。

### 输出与退出码

- 每项成功输出 `[PASS]`；
- 每项失败输出 `[FAIL]`；
- 最后输出 PASS/FAIL 数量；
- 全部通过返回 `0`；
- 合同不满足返回 `1`；
- 找不到仓库根目录返回 `2`。

### 维护规则

- ABI 新增稳定字段时，同时更新设计文档、公共头、布局测试和本工具；
- 不能删除旧检查来让错误构建“变绿”；
- 新工具若职责明显不同，可以继续拆到 `tools` 目录，但必须同步更新本说明；
- 工具内代码必须继续使用详细简体中文注释。
