# CastleScriptAnalyzer.py 工具详细说明

## 1. 工具定位

`CastleScriptAnalyzer.py` v0.1.5 是《幽城幻剑录》任务系统的只读研究事实导出器。

它负责从原版资源中提取：

- Map SCI；
- Entity/NPC SCI；
- EVE 指令与控制流；
- MSG；
- DAT/SYS 容器；
- GameVar 读写；
- Item/Ail2；
- 商店与炼化；
- Scene 跳转；
- Event 与对象绑定；
- v0.1.5 原版 SF2 Section0 TouchBox 事件空间锚点。

它不负责：

- 修改 Quest TOML；
- 生成运行任务数据库；
- 写 GameVar；
- 修改游戏资源；
- 代替实机判断玩家体验。

## 2. 自检

```text
python CastleScriptAnalyzer.py --self-test
```

成功应输出：

```text
CastleScriptAnalyzer v0.1.5 [SELFTEST] PASS
```

## 3. 当前与 Quest 数据的关系

从 dev6x 开始，任务数据不再经过 CSV 转换工具；dev6y 删除运行时独立 `routes.toml`；dev6z 将每条任务拆成“详细 Base + 同名 Addon”；dev6zd 又统一 Base/Addon 的 `quest_id` / `stage_id` 与公共覆盖字段，并支持标准多行 `player_notes`。Base 保存原版链与 `[[stage.route]]`，Addon 保存局部覆盖和人工插入；dev6zd 起运行时已取消 `[[warning]]`，旧失效规则只保留研究证据；现行 Base format_version=7、Addon format_version=2。

```text
研究工具输出事实
        ↓ 人工复核
src/Quest/templete/Castle_Quest/详细Base + 同名Addon
        ↓ ASI 直接读取/合并
游戏 Ctrl+F8 热重载
```

因此分析器输出的 CSV 是“研究证据”，不是“运行任务数据库的人工权威源”。

## 4. Event 编号规则

必须区分：

```text
EVE 文件槽号：0 基
Runtime Event / SCI EA/EB：1 基
```

工具对外任务关联应使用 Runtime EventID，避免人为再做一次偏移。

## 5. 资源优先级

有效资源视图继续遵守已有研究结论：默认优先使用当前实际生效资源，不能把被散装文件覆盖的 DAT 成员误当成当前真值。

## 6. v0.1.5 TouchBox 数据

v0.1.5 新增 Section0 接触判定几何导出，目标是回答：

```text
某个 TOUCH_EA Event
→ 当前原版实体是谁
→ 它的原版碰撞/接触矩形在哪里
```

运行时 dev6z 继承的自动 `TOUCH_EA` Marker 仍必须重新确认当前 RuntimeEntity 与 TouchBox 真实存在；离线导出坐标只能作为绑定/诊断证据，不能直接绕过运行时存在性门控。研究层全局 Route 也只用于取证，真正运行的导航边位于各 Quest TOML 的 `[[stage.route]]`。

## 7. 维护要求

如果以后修改本工具：

1. 保持只读；
2. 使用简体中文详细注释；
3. 更新本说明；
4. 更新《工具截至该版本的完整接档说明》；
5. 运行 `--self-test`；
6. 不把研究输出重新变成 Quest 运行维护的中转层。
