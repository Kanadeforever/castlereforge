# 存档增强工具详细说明

本文对应强制 RuntimeSDK 的当前源码。构建说明以 `src/SaveEnhance/readme.md` 为准；本目录说明
检查工具和源码辅助文件的职责。历史 test7 的私有手柄焦点或 INI 依赖已经退出当前验收要求。

## 候选检查器

`verify_saveenhance_candidate.py` 使用 Python 标准库，只读检查指定 RPG.exe、MiscInfo 和 ASI。
从仓库根运行：

```text
python src/SaveEnhance/tools/verify_saveenhance_candidate.py --rpg "参考资料/Castle/exe/RPG.exe" --miscinfo "参考资料/Castle/multimedia/public/Miscinfo.enc" --asi "build/mods/asi/Castle_SaveEnhance.asi"
```

需要留档时可增加 `--json-output "静态验证结果.json"`，该路径是唯一的可选报告输出。

检查范围：

- 原版 EXE SHA、PE32/i386、固定基址；
- 十个菜单补丁、两个分页点、六个CALL（含菜单LoadSlot隐藏通知）、SaveAction vtable、save gate和存读档原函数前缀；
- `%03d`、Save、TSF 路径证据；
- MiscInfo 解码后 SHA 和原版菜单页数；
- ASI 的 DLL 标志、非零入口及三个 SDK Client 导出；
- 仅静态依赖 KERNEL32，无 CRT/UCRT/VCRUNTIME；
- 既有环形游标和 Client 所需 Win32 导入齐全、名称未被装饰；
- 不存在任何 Get/WritePrivateProfile 导入，配置不再回到 INI；
- 完整 `.NEXTAUTOSLOT` 相对路径和当前 Runtime Save 策略标记存在；
- 旧“SaveEnhance 独立保留槽手柄焦点”标记不存在。

返回码：0 表示全部通过，1 表示检查失败，2 表示输入缺失。检查器记录当前 ASI 哈希，不把
不同编译器产生的二进制差异直接判错。静态通过不能证明游戏中的存读档、手柄焦点和音效行为。

## 可视反馈宿主测试

`test_savevisual.py`通过vswhere定位MSVC x86，编译`visual_host_tests.cpp`，后者直接包含正式`SaveVisual.cpp`，
没有另写一套被测算法。测试EXE可用CRT打印，正式ASI仍无CRT、仅静态依赖KERNEL32。

```text
python -B -X utf8 src/SaveEnhance/tools/test_savevisual.py --game-directory "参考资料/Castle"
```

游戏根目录含exe和multimedia，仅用于只读Sys.dat与Font24。模拟状态、EXE、OBJ隔离在本模块
`_build/visual-tests-随机值`，正常/失败退出清理；强制中断可能残留，下次模块构建清理。
运行器只在子进程去重PATH避免cmd超长，不改系统设置、不读取本机编译器地址记录。

test4有1033项检查、0失败：25帧独立解码对照、原字库11字、576源像素缩小不丢、红色周期、
两类最新状态独立、损坏/失败不移动标记、原子替换失败保留旧数据、三种owner坐标、选择高亮不闪断、
实际读档/loading隐藏、RGB565/24/32及负行距、裁剪/alpha保留、八方向描边、表面锁失败/解锁、三种画幅与Display代次。
test3另覆盖默认Display成功返回2、负值失败以及更新开关不阻挡可见槽号，修补test2模拟默认返回0的遗漏。
test4另测201种字重、基线微调、合并状态迁移及失败保留旧文件、真实两类红字像素、16/32位下三种画幅的原版光标遮挡。
遮挡测试确认透明孔仍显示文字，光标隐藏时不挖洞，坐标/显隐/动画状态不被改写。
退出0表示通过，编译/断言失败返回非零；不能代替真实游戏布局和输入回归。

## 当前辅助文件边界

`PatchUtil.h` 提供补丁描述和字节比较等旧基础定义。正式安装只调用 Runtime Hook：
菜单、分页、存档 CALL 和 save gate 的已知旧补丁恢复都在 Runtime 事务内；预检不直接写码。
不得重新调用头文件中的旧本地写入辅助函数。

`PluginLog.h` 把原有日志调用适配到 Runtime Log；每个插件仍有独立文件，路径固定为
`mods/logs/Castle_SaveEnhance.log`。日志失败不能改变存档安全判断。

`Win32Mini.h` 保留无 CRT 所需最小 Win32 声明。声明存在不代表业务仍直接调用：配置走 Runtime
TOML，WAV 读取走 File，音效文件路径走 Path，user32/winmm 走 Module，手柄快照走 Input，
自动保存和连按窗口的毫秒时间走 Clock。

`SaveVisual.cpp`单独使用Windows/DirectDraw头文件，不把整套图形ABI塞进Win32Mini。
原资源与旁挂最新状态使用明确Win32路径，显示走Runtime Overlay/Display，时钟来自Clock；
没有输入接口、按钮字段写入或其它插件私有调用。

SaveAction 由 Runtime Save 单一包装，SaveEnhance 只登记 0 与 91～99 槽的普通手动禁写策略。
Controller 根据原版 disabled 状态导航，SaveEnhance 不再私有接管手柄焦点。

当前统一写`multimedia/save/.SAVESTATUS`，旧`.LATESTSLOTS/.NEXTAUTOSLOT`仅作迁移来源，新文件成功后才清理。
旧exe/Save游标继续兼容读取；元数据不是通用`.state`。原TSF仍经游戏函数，Win32只处理原资源和旁挂文本状态。
静态验证包含UI只读地址、Overlay/Display标记、新状态/旧迁移路径和test4版本标记。
