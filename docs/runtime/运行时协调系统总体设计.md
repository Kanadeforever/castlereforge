# Castle Runtime 运行时协调系统总体设计与施工图

## 1. 文档地位

本文是 `Castle_Runtime.dll`、RuntimeSDK Client、官方 ASI 接入方式和公共服务的当前权威设计图。
代码施工、审查、迁移和验收应直接以本文为准。历史插件文档若仍描述“官方 ASI 无 Runtime 独立
运行”、同名 INI、ASI 目录日志或插件之间按文件名直连，以本文和当前源码为准并逐步修订。

目标平台固定为台湾第三版原版 `RPG.exe`、PE32/i386。当前已知游戏构建摘要：

```text
SHA-256 8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f
ImageBase 0x00400000
```

## 2. 产品定位

`Castle_Runtime.dll` 是官方 ASI 体系的基础引擎，负责统一：

- 插件发现、身份、初始化和固定驻留；
- 游戏写入、Hook 链和事务；
- 调度、窗口、输入、焦点、显示、渲染、覆盖层和存档 UI；
- 公共游戏状态及临时可变资源；
- 路径、文件、TOML、日志、外部 DLL 和计时器精度；
- 冲突拒绝、回滚、诊断和故障隔离。

Runtime 不实现各插件的产品算法。宽屏如何合成三 Camera、FPS 如何插值、任务如何判定、手柄如何
映射和自动存档何时触发，仍属于对应 ASI。

## 3. 部署与加载

正式目录：

```text
mods\asi\
├─ Castle_Runtime.dll
├─ NoCD.asi
├─ BUGFix.asi
├─ Castle_PadSupport.asi
├─ Castle_Widescreen.asi
├─ Castle_Backlog.asi
├─ MaxGrowthAndDrop.asi
├─ Castle_SaveEnhance.asi
└─ Castle_Quest.asi

mods\logs\
├─ Castle_Runtime.log
└─ <每个ASI各自的业务日志>.log
```

Runtime 必须与 ASI 同目录，只允许固定文件名 `Castle_Runtime.dll`。它保持 `.dll` 扩展名，使
ModLoader 和普通 ASI Loader 不会把它当 ASI 扫描。SDK ASI 的 Client 在 Loader Lock 外用同目录
相对路径加载 Runtime。

## 4. “独立运行”的当前定义

官方 ASI 从本版本起强制依赖 Runtime。所谓单独运行，是“Runtime + 一个业务 ASI”，可以脱离
Castle Mod Loader和其它业务插件，由任意兼容 x86 ASI Loader 加载。

官方 Client 必须设置 `CASTLE_CLIENT_FLAG_REQUIRE_RUNTIME`。缺少或损坏 Runtime 时：

- 不调用业务初始化；
- 不安装本地 Hook；
- 不创建旁路线程；
- 不在 ASI 目录写旁路日志；
- 返回 `CASTLE_ERROR_RUNTIME_REQUIRED` 或具体 Runtime Fault。

SDK 仍保留可选 standalone ABI，是为了不强行破坏第三方使用方式，不代表官方发布继续支持。

## 5. 初始化时序

### 5.1 DllMain

每个官方 ASI 的 DllMain 只保存 HMODULE、关闭线程通知并调用 Client attach/detach。Runtime 自己的
DllMain 也只保存模块句柄。禁止文件 I/O、LoadLibrary 业务依赖、线程、Hook 和插件回调。

### 5.2 普通 ASI Loader

```text
LoadLibrary(ASI)
    ↓
Client 安装或加入 RPG Entry Gate
    ↓
RPG 原入口前，Owner 调 BootstrapAll
    ↓
Runtime 按稳定 plugin_id 排序并登记全部 SDK ASI
    ↓
逐个 integrated_initialize
    ↓
全部返回后打开 Schedule 闸门
    ↓
恢复并执行 RPG 原入口
```

### 5.3 Castle Mod Loader

ModLoader 先 LoadLibrary 全部 ASI，再按同一顺序调用 `InitializeASI`。所有调用返回后，再调用
`CastleRuntimeClient_NotifyLoaderReady`。Runtime 在外层通知前不执行任何 Schedule 回调，避免 A
插件任务在 B 插件尚未初始化时提前运行。

ModLoader 只短暂适配两阶段通知，不拥有、不加载、不配置 Runtime；ASI 仍可由其它 Loader 使用。

## 6. 根 ABI

公共头必须是纯 C ABI、`#pragma pack(push, 4)`、固定宽度类型，不暴露 `windows.h`、STL、`size_t`
或 C++ `bool`。所有结构都有 magic、struct_size、version；新增字段只能尾部追加或发布新版本。

Runtime DLL 唯一导出：

```text
CastleRuntime_GetApi
```

每个 SDK ASI 标准导出：

```text
CastlePlugin_Query
InitializeASI
CastleRuntimeClient_NotifyLoaderReady
```

插件身份使用稳定 ID，不使用文件名、加载顺序或 HMODULE 作为长期协议。

## 7. 生命周期与故障模型

Client 原子状态机保证同一 ASI 业务最多初始化一次。Runtime 枚举后固定驻留 SDK 插件和自身，防止
Hook next 槽、Provider 回调或服务函数指针指向已卸载模块。

Runtime 文件存在但不可加载时，Client 临时设置线程错误模式以抑制损坏映像弹窗，返回前恢复原值。
故障不能转成官方 standalone。日志不可写也不能改变内存安全决定。

## 8. Hook 服务

Hook v1 支持：

- ExclusivePatch：单所有者固定写入；
- StatePatch：原版/启用两个已知状态；
- RelativeCallHook：E8 CALL 可组合链；
- PointerHook：IAT/vtable 函数指针链；
- NamedResource：没有自然地址的互斥资源；
- Transaction：整组预检、提交、失败逆序回滚；
- HookBinding：稳定 `next_slot`。

链排序键依次为 phase、priority、显式约束、稳定插件 ID。不同 ABI 签名拒绝串链。事务提交前不
调用插件代码；Runtime 持内部锁时也不调用插件回调。

## 9. Schedule 服务

Schedule v1 维护唯一后台线程，支持周期任务、一次性任务、启停、注销、预算和统计。Bootstrap
闸门关闭时只登记不执行；连续失败只隔离当前任务。

Runtime 同时唯一接管探索更新入口 `0x00409580`，发布 GamePhase 和探索管理器指针。Quest 不再
安装该入口 Hook，Controller/Backlog 的轮询也不再各自创建高频线程。

## 10. Window 服务

Runtime 只安装一个主 WndProc。Observer 全部先执行且不能消费；Filter 后执行，可返回 consume
和结果。窗口尚未创建、销毁或重建由 generation 表达。后装第三方 WndProc 时保持谨慎链回，
当前链头不是 Runtime 时不盲抢。

## 11. Input 服务

Input v1 只有一个权威 Provider。Controller 发布物理按钮、语义动作、轴、前台状态和控制模式；
Backlog、SaveEnhance 等只读快照，不再 GetModuleHandle/GetProcAddress PadSupport。

Overlay、Modal、Pointer 使用全局焦点租约，避免同一按键同时穿透多个插件。焦点冲突明确返回
ResourceConflict，不靠加载顺序。

## 12. GameState 服务

GameState v1 发布只读快照：World、DataCenter、Event、窗口、探索管理器、Camera、对话、Battle、
菜单、存档点、电影等。未知游戏构建返回 NotReady，不盲读固定地址。

临时写 Camera、DrawQueue、Dialogue、World 或 SaveUI 的插件必须取得 Mutation Lease。Widescreen
普通渲染和 FPSUnlock 额外帧通过 Runtime Render 统一取得需要的资源租约。

## 13. Save 服务

Runtime 唯一包装 SaveAction vtable。插件登记手动存档槽策略，重叠策略采用 deny-wins：任何一个
插件禁止，就不能被另一个插件重新允许。

当前 SaveEnhance 登记：

```text
0      禁止普通菜单覆盖
91~99  禁止普通菜单覆盖
1~90   保持允许
```

Controller 只读取原版 `disabled` 状态，不识别 SaveEnhance 名称、槽号来源或 Hook 顺序。

## 14. Display 服务

Display 是画面几何的唯一权威。默认后端提供原版 640×480；Widescreen 注册专业 Provider，每帧
发布 output、logical、center、effective/original Camera、左右实际世界宽度、模式和投影范围。

Quest 使用 `WorldToScreen`，不得固定加 107/240、读取宽屏配置或复制 CameraPlan。对白、Battle、
Hard4:3 和 Transition 是否允许世界投影由 Display 状态回答。

## 15. Render 服务

Runtime 唯一接管 `0x0044A9C6` RenderQueue CALL 和 `0x0044A9E6` Present CALL。Widescreen 发布与
Display Provider 绑定的 Render Provider。FPSUnlock 通过 `BeginExtraWorldFrame` / `EndExtraWorldFrame`
申请全局互斥额外帧，不读取当前 CALL 目标。

Render 负责时序和资源租约，不实现宽屏像素合成或 FPS 插值。

## 16. Overlay 服务

Runtime 唯一接管 renderer Present 入口 `0x004064E0`。Quest 等覆盖层登记 before-present 回调，
按 phase、priority、plugin ID 稳定排序。任一回调失败不会阻断原 Present；连续失败会停用该回调。

## 17. Path 与 File

Path 提供 Runtime/ASI 根、插件模块路径、相对路径构造、规范化和不区分大小写比较。拒绝 `..`、
绝对盘符、UNC、冒号和根逃逸，不修改 CurrentDirectory、PATH 或 SetDllDirectory。

File v1 在 ASI 根内提供：读取、原子写、删除、建目录和枚举。写入固定使用同目录临时文件、
FlushFileBuffers、MoveFileEx(REPLACE_EXISTING|WRITE_THROUGH)，并由 Runtime 串行化。

File 不用于原版 TSF、Overrides、ModLoader 配置或真实存档目录的历史兼容文件。

## 18. TOML 服务

TOML v1 使用 File 读取插件相对文档，Runtime 持有固定容量文档缓冲。当前配置 ABI 支持普通表、
ASCII 裸键、bool、32 位整数和 UTF-8 双引号字符串；BOM 可选。缺键返回调用者默认值，错误类型
返回 InvalidArgument。

所有正式配置已改为同名 `.toml`，每个键都有独立中文注释。插件不再调用 GetPrivateProfile，也
不在启动时重写用户配置。

Quest 的 Q*.toml/Addon 是复杂领域数据库，当前仍由 Quest 解析；Runtime 标量 v1 不谎称支持数组表。

## 19. Log 服务

Runtime 自己写 `mods/logs/Castle_Runtime.log`，仅记录协调、冲突、回滚和基础设施状态。每个插件
仍拥有独立业务日志，由 Log 服务按 ASI 文件名放入同一目录。日志使用 UTF-8 BOM、CRLF、共享读写
和同步刷新。

业务插件不得自行打开日志文件。Runtime 日志失败时继续维护内存诊断环。

## 20. Module 与 Clock

Module 统一插件相对 DLL、系统白名单 DLL、导出查询和固定驻留。Controller 的 SDL3 与 SaveEnhance
的 user32/winmm 已接入。系统白名单当前包括 kernel32、user32、gdi32、winmm、ddraw。

Clock 统一 `timeBeginPeriod(1)` / `timeEndPeriod(1)`。第一个租约真正开始 1ms，最后一个租约释放
才结束；FPSUnlock 已接入。重复释放和未知租约拒绝。

## 21. 配置编辑器

ModLoader 的 ASI 行只在存在同名 `.toml` 时显示“编辑”。编辑器：

- 只接受 UTF-8/UTF-8 BOM；
- 使用 `#` 注释；
- 检查 Runtime TOML v1 的表、裸键、整数、bool 和字符串；
- 语法错误定位到真实逻辑行；
- 使用临时文件、Flush 和原子替换；
- 不修改 `mods.ini`、插件顺序或启用状态。

Loader 自己的 `CastleModLoader.ini` 与 `mods.ini` 仍是 pre-Runtime 配置，职责不同，暂不改 TOML。

## 22. 当前插件迁移矩阵

| 插件 | 已接服务 | 关键冲突处理 |
|---|---|---|
| NoCD | Client、Hook、Log | 代码与备用盘符同事务 |
| BUGFix | Client、Hook、Log | 历史修复与 Crash 双路径分事务 |
| MaxGrowthAndDrop | Client、Hook、Log、TOML | 成长/掉宝独立 StatePatch 事务 |
| Controller | Hook、Schedule、Input、Module、TOML、Log | 权威输入 Provider；不拥有 SaveAction |
| Backlog | Hook、Window、Schedule、Input、GameState、TOML、Log | 焦点/Dialogue 租约 |
| Widescreen | Hook、Display、Render、GameState、TOML、Log | Render 中央入口归 Runtime |
| SaveEnhance | Hook、Save、Input、Module、Path、File、TOML、Log | SaveAction deny-wins；WAV 经 File/Path |
| Quest | Schedule、Overlay、Display、GameState、TOML、Log | 无 Present/探索入口私有 Hook |
| FPSUnlock | Hook、Render、Clock、GameState、Module、TOML、Log | 未完成；单独构建，不进 build_all |

## 23. 文件写入边界

当前官方插件的普通日志和配置写入均已收口。SaveEnhance 仍直接维护
`multimedia\save\.NEXTAUTOSLOT`：它是兼容既有实机语义的三字节全局轮换游标，位于 ASI 根之外，
不属于 File v1，也不是 `SaveXXX.state`。本轮保持路径和格式不变，避免无收益的数据迁移风险。

## 24. 共享增强 `.state` 的冻结边界

当前没有任何插件实际创建或读取 `SaveXXX.state`。Quest 只在文档中提出未来需求；SaveEnhance
现有 `.NEXTAUTOSLOT` 也不是 `.state`。

未来第一个真实消费者出现时再实现专用 State 服务，要求：

- 与 TSF 同名、TOML 格式、原版 TSF 永不修改；
- Runtime 唯一读文件、维护内存树和原子落盘；
- `modules.<稳定插件ID>` 命名空间所有权；
- 未知模块和字段完整保留；
- Save/Load/NewGame 生命周期明确；
- 并发提交顺序由 Runtime 协调；
- 缺失或损坏 `.state` 不阻断原版 TSF；
- 实现前增加 ABI、解析、事务、损坏恢复和实机测试。

因为当前无消费者，本版不为一个空功能新增 Save/Load Hook，这符合“根基优先稳定、避免连锁副作用”。

## 25. 构建与发行

Runtime 使用 MSVC x86、无 CRT、静态依赖仅 KERNEL32。ABI 布局同时由 MSVC/clang-cl 的 C/C++17
验证。根 `build_all.bat` 当前 10 步：Runtime、Backlog、Controller、Widescreen、SaveEnhance、
BUGFix、NoCD、MaxGrowthAndDrop、Quest、ModLoader。

FPSUnlock 已迁入 SDK，但因项目未完成不进入 build_all。总构建开始前删除自己负责的旧正式产物，
防止陈旧文件造成假绿灯；最终配置、ASI、Runtime 位于 `build/mods/asi`，日志目录为空壳
`build/mods/logs`，构建垃圾为零。

## 26. 自动验证

Runtime 当前自动测试包括：

- 4 路 ABI 编译；
- PE32、入口、唯一导出和 KERNEL32-only；
- Hook 事务、链、回滚、Path、Schedule、Window、Display、Render；
- Log、File、TOML、Module、Clock、Input、GameState、Save、Overlay；
- 正常 Runtime、无 Runtime、损坏 Runtime、强制 Runtime 缺失；
- ModLoader Loader-ready 闸门；
- build 发行文件、TOML、Quest 数据、日志目录和零垃圾。

静态与宿主测试不能替代 RPG.exe 实机。涉及游戏地址和渲染时序的改动必须按公共验收标准联合测试。

## 27. 施工纪律

- 新服务先写 ABI、结构大小、线程和失败语义，再写实现；
- 公共 ABI 不暴露实现对象；
- 热路径不读文件、不加载 DLL、不写高频日志；
- 回调时不持 Runtime 锁；
- 新接口不改变旧接口语义；
- 未知构建默认 NotReady/fail-closed；
- 文档、源码注释、测试和发行检查必须同次更新；
- 用户实机确认前只称候选；
- 提交前检查并保留用户已有改动，提交说明使用简体中文。
