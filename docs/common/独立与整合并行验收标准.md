# 独立与整合并行验收标准

## 一、“独立”的最新定义

官方 ASI 已强制依赖 `Castle_Runtime.dll`。本文的独立验收指“Runtime + 一个被测 ASI”，
证明该插件不依赖 Castle Mod Loader 或其它业务插件；不再测试“删除 Runtime 后仍提供功能”。

原始光盘版 RPG.exe 没有 NoCD 无法进入游戏，因此实机最小组合通常是：

```text
Castle_Runtime.dll + NoCD.asi + 被测ASI
```

测试 NoCD 自身时只需 Runtime + NoCD。换用其它 ASI Loader 时也必须保留 Runtime DLL。

## 二、Runtime 必需性验收

- Runtime 不存在：官方 ASI 不执行业务写入；
- Runtime 是目录、x64、损坏 PE 或缺少导出：不弹阻塞系统对话框；
- ABI 主版本不匹配：进入 Runtime Fault；
- 以上情况都不能调用 standalone 业务回调；
- 删除坏文件并放回正确 DLL 后，下次进程可正常整合；
- Client 探测前后的线程错误模式完全一致。

## 三、单插件验收

- Castle Mod Loader 加载；
- 其它普通 x86 ASI Loader 加载；
- 修改 ASI 文件名但稳定插件 ID 不变；
- 重复触发 InitializeASI；
- TOML 缺失、空文件、错误类型、越界数值；
- 可选资源或 Provider 缺失；
- 正常退出和重新启动；
- 未知游戏机器码必须拒绝写入；
- 日志只出现在 `mods/logs`，且每个插件一个文件。

## 四、全插件并行验收

- 全部正式官方 ASI 同时启用；
- 至少三种 ASI 加载顺序；
- ModLoader 两阶段和普通 Loader Entry Gate 各一轮；
- 所有插件初始化完成前 Schedule 不运行；
- Loader-ready 后任务按稳定规则运行；
- 任一插件初始化失败只隔离自身；
- 相同 Hook 签名形成确定链；
- 不兼容签名明确拒绝；
- Provider 未 ready 时消费者安全降级；
- 不出现按文件名识别其它 ASI 的长期协议。

## 五、Hook 与事务

- target 使用 module+rva+size；
- CODE/DATA 标记正确；
- expected/replacement 大小一致；
- StatePatch 只接受两个已知状态；
- CALL 必须验证 E8 和原始目标；
- IAT/vtable 使用稳定 next 槽；
- phase、priority、约束和 plugin ID 形成确定顺序；
- 事务预检后地址变化时逆序回滚；
- 一个事务失败不撤销其它已提交插件；
- 官方插件集成路径不直接 VirtualProtect 冲突入口。

## 六、TOML、File 与 Log

- 所有正式同名配置为 `.toml`；
- 每个配置键正上方有独立中文说明；
- UTF-8 与可选 UTF-8 BOM 正常；
- ANSI/UTF-16 配置由 ModLoader 编辑器明确拒绝；
- 非法表、键、字符串转义和类型拒绝保存；
- ModLoader 使用同目录临时文件、Flush、原子替换；
- File 拒绝 `..`、盘符、UNC、冒号和根目录逃逸；
- 原子写入可完整读回，失败不截断原文件；
- Runtime 日志与每个业务日志分开；
- 日志目录固定为 `mods/logs`。

## 七、Module 与 Clock

- SDL3 从插件相对路径加载；
- user32/winmm 等只通过系统白名单；
- 不修改 CurrentDirectory、PATH 和 SetDllDirectory；
- 共享函数地址存在期间模块固定驻留；
- 多个 1ms 申请共享引用计数；
- 最后一个租约释放才结束精度；
- 重复释放和未知租约被拒绝。

## 八、Input、Window 与 Schedule

- Input 只有一个权威 Provider；
- Backlog/SaveEnhance 不按文件名直连 PadSupport；
- Overlay/Modal/Pointer 焦点全局互斥；
- Window Observer 先于 Filter，Observer 不能消费；
- WM_DESTROY/WM_NCDESTROY 不被误吞；
- 窗口重建 generation 增长；
- Runtime 最多一个后台调度线程；
- 回调时不持 Runtime 锁；
- 停用、注销、失败隔离和预算统计正确。
- 有手柄启动默认隐藏普通鼠标；无手柄启动保留键鼠；实体鼠标优先，明确手柄输入可回切；
- 普通右摇杆漂移不能切模式；Back/RT/调查/Target/明确菜单焦点仍按规格显示；
- RB 组合只在战斗顶层和完全待机武装，ABXY/方向上/下跨 Context 锁到释放帧；
- RB+B 打开道具后，同一手势不能穿透成子菜单退出；现有单键 RB 页面不得回归。

## 九、GameState、Save、Display、Render 与 Overlay

- GameState 快照只读，未知构建返回 NotReady；
- Camera/Draw/Dialogue/World/SaveUI 修改必须持对应租约；
- SaveAction 只有 Runtime 一个包装层；
- 0 与 91～99 的手动禁写采用 deny-wins；
- Controller 读取原生 disabled，不识别 SaveEnhance；
- Display 的有效 Camera 和本帧 geometry 是投影权威；
- Quest 不固定加 107/240、不复制 CameraPlan；
- RenderQueue/Present 中央入口只由 Runtime 拥有；
- FPSUnlock 通过额外帧租约，不读取当前 CALL 目标；
- Quest 等覆盖层通过 Overlay 登记，失败不阻断原 Present。
- 854/1120 输出中鼠标图标可遍历完整画面，但命中只接受当前实际内容；
- 自由探索真实左右世界按 Display/Camera 换算，地图缺口、黑边和模糊侧区不得命中；
- 对话、战斗、标题与菜单仍只接受中央 640×480 UI，鼠标不得出现中央/宽屏双影。

## 十、构建与发行

- MSVC/clang-cl 的 x86 C/C++17 ABI 全过；
- Runtime 无 CRT、静态依赖仅 KERNEL32；
- 所有正式 ASI 为 PE32/i386、DLL、非零入口；
- 标准导出未修饰；
- build_all 不读取开发者物理工具路径；
- build_all 构建前清除自己的旧正式产物，不能用陈旧文件假通过；
- Quest 数据目录完整；
- SaveEnhance 音效目录和说明完整；
- `build/mods/logs` 存在；
- build 无 obj/lib/exp/ilk/pdb；
- FPSUnlock 保持单独构建，不进入 build_all。

## 十一、实机顺序

1. Runtime + NoCD；
2. Runtime + NoCD + 每个单独插件；
3. Extra 三插件；
4. Backlog + Controller；
5. Controller + SaveEnhance，重点测存档按钮；
6. Widescreen + Quest，重点测 Marker 与对白/战斗 4:3；
7. 加入 FPSUnlock 实验版，重点测宽屏额外帧；
8. 全部正式插件；
9. 标题、新游戏、读档、返回标题、再次新游戏；
10. 检查所有日志、TOML 和存档目录。

只有静态、构建和实机联合结果都完成，才可标记最终稳定；否则只能称发布候选。
