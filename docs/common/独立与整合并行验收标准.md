# 独立与整合并行验收标准

## 1. 验收原则

同一 ASI 必须通过三条互斥路径：独立、整合、Runtime 故障。测试报告要分别记录，不能用整合模式成功
代替独立模式，也不能把“损坏 Runtime 后仍有功能”当优点。

## 2. 独立模式矩阵

前提：ASI 同目录没有 `Castle_Runtime.dll`。

- 单插件由 Castle Mod Loader 加载；
- 单插件由其它 ASI Loader 加载；
- 修改 ASI 文件名后加载；
- 重复触发 InitializeASI；
- 配置缺失、默认生成、合法/非法值；
- 可选依赖缺失；
- 正常游戏退出；
- Loader 主动 FreeLibrary（若声称支持）；
- 原始 EXE 与已知旧补丁 EXE；
- 未知机器码必须拒绝写入。

通过标准：用户核心功能与迁移前一致，日志明确写 Standalone，不加载 Runtime，不出现双初始化。

## 3. 整合模式矩阵

前提：同目录放置唯一 `Castle_Runtime.dll`。

- Runtime + 单插件；
- Runtime + 全部官方插件；
- 代表性不同加载顺序；
- MODLoader 两阶段路径；
- 普通 Loader Entry Gate 路径；
- 同一插件 InitializeASI 重复调用；
- 文件改名但稳定 ID 不变；
- 可选领域接口缺失；
- Provider 尚未 ready；
- 同资源兼容链；
- 同资源不兼容签名；
- 事务预检后地址变化，必须回滚；
- Schedule 某任务失败/超预算，不能拖死其它任务；
- Window 后装 wrapper 和窗口重建；
- Display Provider 切换与严格 generation；
- Render 额外帧租约冲突。

通过标准：所有 SDK 插件自动整合；没有插件执行 Standalone 写入；最终行为不依赖文件加载顺序。

## 4. Runtime 故障矩阵

分别测试：

- 同名文件不是 PE；
- x64 DLL；
- 缺少 `CastleRuntime_GetApi`；
- ABI 主版本不匹配；
- Runtime 初始化失败；
- Runtime 文件不可读；
- Runtime 路径是目录。

通过标准：插件进入 Runtime Fault，业务写入为零，错误可诊断；损坏映像不得弹出阻塞游戏或自动构建的 Windows 系统对话框；探测前后的线程/进程错误模式必须一致；删除损坏文件后下次启动才能回到独立模式。

## 5. Hook 事务验收

- 每项 target 使用正确 module+rva+size；
- CODE/DATA 二选一；
- expected/replacement 大小相同；
- StatePatch 只接受两个状态；
- CALL 当前 opcode 不是 E8 时拒绝；
- expected original target 错误时拒绝；
- 链签名不一致时冲突；
- 同签名按 phase/priority/ID 稳定排序；
- next 槽地址稳定；
- 一个事务失败只回滚本事务；
- 已提交其它插件资源不受影响。

## 6. Path 验收

- Runtime 与 ASI 同目录；
- UTF-8/UTF-16 同结果；
- 查询长度不写越界；
- 小缓冲返回所需长度；
- `folder/file.ini` 正常；
- `folder/./file.ini` 规范化；
- `../`、绝对盘符、UNC、冒号拒绝；
- 大小写路径比较符合 Windows；
- 不改变 CurrentDirectory/PATH/SetDllDirectory；
- 非 ASI 根目录模块不能构造插件相对路径。

## 7. Schedule 验收

- 整个 Runtime 最多一个后台线程；
- 两个 8ms 任务使用同一线程；
- 回调时不持 Runtime 锁；
- 停用后不再调用；
- 注销后旧句柄无效；
- 一次性任务槽可复用；
- 连续失败达到阈值只隔离本任务；
- 执行次数、漏 tick、预算、失败统计正确；
- 游戏阶段能力未启用时返回 OPTIONAL_UNAVAILABLE。

## 8. Window 验收

- 只安装一个 Runtime 主 WndProc；
- Observer 全部先于 Filter；
- Observer 不能消费；
- Filter consume/result 生效；
- WM_DESTROY/WM_NCDESTROY 不被错误吞掉；
- 调用插件代码时不持锁；
- 后装第三方 WndProc 正常链回；
- 当前链头不是 Runtime 时不强抢；
- 窗口销毁/重建 generation 增长；
- 注销后旧 client 句柄无效；
- Runtime 静态导入仍只有 KERNEL32。

## 9. Display/Render 验收

- 未知游戏构建默认 Display/Render 不盲读固定地址；
- 已确认构建默认 640×480 可用；
- 外部 Display 只能有一个权威 Provider；
- 未发布几何前不能 ready；
- provider_generation 切换；
- requested_generation 过期返回 STALE；
- 16:9、21:9、窄地图 CameraPlan；
- 对白/Battle/硬4:3/Transition 不可投影；
- WorldToScreen 与 ScreenToWorld 同代次互逆；
- Render Provider 与同插件 Display Provider 绑定；
- 额外帧租约全局互斥；
- 过期租约不能调用或结束。

## 10. 构建与发行验收

- 所有公共头能被 MSVC/clang-cl 的 C/C++17 包含；
- ABI sizeof/offsetof 全通过；
- Runtime 唯一导出正确；
- 每个新格式 ASI 导出 Query/Initialize；
- PE32/i386、DLL、非零入口；
- Runtime 静态依赖仅 KERNEL32；
- `build` 不含 obj/lib/exp/ilk/pdb；
- Runtime 位于 `build/mods/asi`；
- 插件资源目录和提醒文档完整；
- FPSUnlock 未完成时不进入 build_all；
- GitHub Actions 使用同一 build_all，不依赖开发者本机绝对路径。

## 11. 实机联合顺序

1. 只装 Runtime + 一个简单 Extra；
2. Extra 三插件全开；
3. 加 Backlog；
4. 加 Controller；
5. 加 SaveEnhance，重点测 SaveAction 链；
6. 加 Widescreen，重点测 Display/Render；
7. MODLoader 与另一 ASI Loader 各跑一轮；
8. 标题、新游戏、读档、返回标题、再次新游戏；
9. 对话、Battle、菜单、存档点、宽屏过渡；
10. 正常退出并检查日志与实际模式一致。

没有完成实机联合验收时，只能称“静态/构建候选通过”，不能宣称最终游戏稳定版。
