# 本版本更新记录

> 版本：**v0.10-poc10 — 16:9 / 21:9 双模式版**  
> 稳定基线：**v0.9-poc9 已通过实机验收**

## 本轮目标

在不改变 v0.9 已验收视觉规则的前提下，只增加一个显示比例开关：

```ini
[Display]
Ultrawide=0
```

- `Ultrawide=0`：默认，854×480（16:9）。
- `Ultrawide=1`：1120×480（严格 21:9）。

不允许任意自定义宽度。本轮只维护两个经过明确设计的固定模式。

## 本轮核心改动

### 1. 输出几何运行时参数化

v0.9 写死：

```text
OutputWidth=854
SideWidth=107
StagingWidth=982
```

v0.10 改为启动时根据 INI 选一组固定几何：

```text
16:9：107 + 640 + 107 = 854
      staging = 854 + 64 + 64 = 982

21:9：240 + 640 + 240 = 1120
      staging = 1120 + 64 + 64 = 1248
```

原版 renderer 的 768×576 backing **完全不改**。

### 2. 21:9 仍只需要三次 world render

普通地图仍然是：

```text
左 Camera
中央 Camera
右 Camera
```

16:9 左右各取 107；21:9 左右各取 240。因为 240 仍小于单次原版 640 宽 renderer，所以不需要增加到五次渲染。

### 3. Camera 安全边界同步扩大

原版 Camera 只保证 640 可见宽度不越界。插件现在按当前 `SideWidth` 额外夹住中心 Camera：

```text
center >= minX + SideWidth
center <= maxX - 640 - SideWidth
```

所以：

- 16:9 使用 107 安全边距；
- 21:9 使用 240 安全边距。

地图本身不足当前输出宽度时，不会把 Camera 推出地图；插件会把地图在640之外实际拥有的额外宽度左右平分，让小地图尽量居中，只显示真实存在的世界。

### 4. 电影式模糊也变成比例自适应

不能把 v0.9 的 214×120 模糊图直接横拉成 21:9。本版按当前输出宽度自动得到低分辨率工作图：

```text
854  -> 214×120
1120 -> 280×120
```

同时根据当前目标宽高比重新计算从中央 640×480 中应取的纵向 crop：

```text
16:9：约 640×360
21:9：约 640×274
```

因此对话和 Battle 在 21:9 下仍然是正确的“中央 4:3 + 两侧电影式背景”，而不是把 16:9 模糊图硬拉宽。

### 5. v0.9 已验收规则全部冻结

本轮没有改变：

- 所有对话框/提示/选择框统一电影式侧区；
- 对话链锁存到 Event+消息结束或场景切换；
- Battle 中央 640 + 电影式侧区；
- 标题/Bink/主 Interface 中央 640 + 黑边；
- 左右 world 重放期间临时屏蔽消息状态，防止第二套立绘/对话框；
- `EnterDurationMs / ExitDurationMs` 毫秒配置。

## 默认行为

为了确保升级后不改变既有用户体验，默认：

```ini
Ultrawide=0
```

也就是继续使用已经实机验收的 854×480。
