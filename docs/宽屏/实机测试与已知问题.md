# 实机测试与已知问题

> 测试候选：v0.11-poc11
> 当前最后实机稳定版：v0.10-poc10

## 1. 测试步骤

### 1.1 默认模糊模式回归

使用：

```ini
[Cinematic]
BlurredSides=1
```

预期应与 v0.10 已验收行为一致：

- 普通探索真宽屏；
- 任意对话框中央640 + 左右强模糊推入；
- Battle中央640 + 左右强模糊；
- 退出时左右滑出；
- 不出现重复立绘/UI。

这是第一项，因为默认模式必须证明没有被本轮新增分支破坏。

### 1.2 纯黑模式

改成：

```ini
[Cinematic]
BlurredSides=0
```

重新启动游戏。

测试：

- 普通 NPC 对话；
- 自动剧情；
- 提示语；
- 选择框；
- Battle。

预期：

- 触发时机与模糊模式完全一样；
- 推入/退出速度完全一样；
- 中央640完全一样；
- 左右最终为纯黑，不生成可见模糊背景。

### 1.3 动画对比

为了明显比较，可以临时设置：

```ini
[Transition]
EnterDurationMs=500
ExitDurationMs=500
```

分别测试 `BlurredSides=1` 和 `0`。

两者运动轨迹应一致，唯一可见差别是面板内容。

### 1.4 16:9 / 21:9 都要抽查

```ini
Ultrawide=0
```

和：

```ini
Ultrawide=1
```

至少各看一次黑边模式，确认侧区宽度分别正确为107和240。

### 1.5 日志

启动应出现：

```text
[配置] BlurredSides=1
```

或：

```text
[配置] BlurredSides=0
```

并有对应中文样式说明。

如异常请保留 `Castle_Widescreen.log`。

## 2. 已知问题与风险

### 2.1 v0.11 尚未实机验收

新增功能很小，但在用户确认前不能把 v0.11 宣布为新的稳定封版基线。

默认 `BlurredSides=1` 理论上应完全保持 v0.10 视觉行为。

### 2.2 黑边模式仍有移动边缘柔化

用户要求两种模式除“模糊 / 纯黑”外其它完全一致。

所以 `BlurredSides=0` 进入或退出过程中，10 像素移动边缘仍会使用相同 alpha 柔化。

完全进入后左右区域为纯黑。

### 2.3 同一 active Event 的长空档

消息侧区锁存仍延续 v0.10：只要 active Event 没结束，同一 Event 中消息框暂时消失也保持侧面板。

这是为了避免对白之间来回推入退出。

如果某个 Event 在对白后有很长的纯演出空档，侧区可能继续保持到 Event 结束或换场景。

### 2.4 Battle 仍不是世界真宽屏

当前 Battle 继续中央640 + 统一侧面板。

这是已选择的稳定路线，不属于 v0.11 新问题。

### 2.5 标题 / Bink / 主 Interface

仍是原有黑边硬4:3。

`BlurredSides` 对这些区域没有实际视觉区别，因为它们本来就不用电影式模糊。

### 2.6 INI 不支持热重载

修改后必须重新启动游戏。

### 2.7 纯黑模式的模糊缓冲仍会分配

为了让两种模式使用完全同一套已验收内存布局和安装路径，v0.11 没有把模糊缓冲分配也做成条件分支。

但是纯黑模式会跳过每帧缩图和模糊计算。

这几块缓冲很小，保留它们可以减少额外工程分叉。

### 2.8 旧失败路线继续禁止

不要恢复：

- 扩大原版768×576 renderer backing；
- 11个低层 blitter 全局改宽；
- Battle 整队列重复；
- 玩家/非玩家对白视觉分类。
