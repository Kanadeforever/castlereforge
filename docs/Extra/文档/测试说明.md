# 《幽城幻剑录》v0.3.2 测试说明

## 0. 启动入口与插件回归

2026-08-28 目录整理没有改变测试项目。构建时先分别运行 `src/Extra/build.bat` 与 `src/AnytimeSave/build.bat`，或直接运行根 `build_all.bat`；再确认四个正式插件启动后都能生成本轮新日志：`BUGFix.log / AnytimeSave.log / NoCD.log / MaxGrowthAndDrop.log`。如果某个 ASI 已被 Loader 映射但日志完全没有创建，应优先怀疑 DLL 入口/Loader，而不是先怀疑补丁地址。

本次目录整理已完成正式构建回归：四个 ASI 均生成成功并通过构建脚本的三项 PE 检查。Probe 在当前 MSVC 19.51 下仍有自定义 `memcpy/memset` 的 `C2169` 编译兼容问题；它不参与根一键构建，也不影响正式功能验证。

当前交付产物已静态确认 `AddressOfEntryPoint` 全部非 0；`BUGFix` 原有 7 个固定补丁地址仍与 v0.1.0 保持一致；v0.3.2 另外合并 CrashFix test2 的两条调用路径。`NoCD / MaxGrowthAndDrop` 预编译文件与 v0.3.1a 哈希完全相同。

建议先看三份日志：

- `BUGFix.log`：应出现冥狱杀阵、抗性两项固定修复“已生效”，以及“Crash 双调用路径 Route A/Route B 已安装”；
- `NoCD.log`：应出现“原版光盘扫描函数已安全跳过”以及备用盘符；
- `MaxGrowthAndDrop.log`：应显示 INI 两个开关状态，并分别报告成长/掉宝补丁成功。

功能级回归建议：无光盘环境正常启动；MaxGrowth/MaxDrop 分别切 0/1 后日志状态与游戏行为一致；BUGFix 在已有复现场景下验证抗性和冥狱杀阵问题不回归。

Crash 合并专项：

1. 进入游戏并读一个正常存档；
2. 返回标题；
3. 再开始新游戏；
4. 预期不再在 `0x004067A0` 崩溃；
5. `BUGFix.log` 应至少出现 Route A 或 Route B 的首次路径观察；如果确实遇到 stale controller，还应出现“Crash命中/Crash处理”。

不需要也不应该再放 `CrashFix.ini`。

## 1. 首要回归：磐沙堡楼梯

在此前会坏档的楼梯/多层位置测试：

1. 进入场景后先正常活动片刻，让日志出现“冻结入口级原版安全锚点”；
2. 到楼梯危险位置打开天書并保存；
3. 完全退出游戏；
4. 重新启动读档。

预期：

- 存档成功；
- 不生成 `.TSA/.YCS`；
- 读档回到场景入口/早期稳定位置，而不是楼梯保存坐标；
- 可以继续正常移动、上/下楼梯、进门、切图；
- 不形成死档。

日志应有类似：

```text
[回退] 已在默认 Scene Mode 连续稳定 8 Tick 后冻结入口级原版安全锚点。
[存档门] 原版拒绝，但已有安全回退；已扩展允许……
[保存] 原版 TSF 写入成功；场景恢复头已使用入口级安全锚点规范化。未创建任何旁挂文件。
```

## 2. 原版合法存档点

在原版本来就能存档的正常地点保存/读取。

预期：行为与没有 AnytimeSave.asi 完全一致；日志不应把这次存档写成“扩展允许”。

## 3. 原版禁存但普通稳定区域

找一个不是楼梯、不是明显转场的原版禁存区域。

预期：地图稳定 8 Tick 并建立 fallback 后，天書可以开放；读档回入口/早期安全点，但当前角色/队伍/道具/剧情进度应保持本次保存的原版持久状态。

## 4. 立刻打开菜单

刚切入新地图就立刻打开菜单。

如果 fallback 尚未冻结，插件应拒绝扩展开放，并写：

```text
[存档门] 当前地图尚未建立入口级安全锚点；本次暂不扩展开放。
```

这是正常安全行为。

## 5. 连续覆盖同一槽

连续保存同一槽 2～3 次。

预期：没有 TSA pending、CRC 或旁挂竞态；每次都只有原版 TSF Writer。

## 6. 四插件日志

确认每次游戏启动后以下日志旧内容都被清空：

- `BUGFix.log`
- `AnytimeSave.log`
- `NoCD.log`
- `MaxGrowthAndDrop.log`

编码：UTF-8（带 BOM）；换行：CRLF；正文：简体中文。

## 7. 诊断 Probe

需要继续研究新反例时才加载 `AnytimeSaveProbe.asi`。

不要与正式 `AnytimeSave.asi` 同时加载。

## 8. 静态验证基线

本包交付前安全回退静态策略测试为 **24/24 PASS**；实机仍以本文件第 1～5 节为准。
