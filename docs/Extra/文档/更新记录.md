## v0.3.2 — 2026-08-20

主题：**把已稳定实机验证的 CrashFix v0.1.0-test2 核心逻辑并入 BUGFix.asi；不带入任何 CrashFix INI。**

- 用户确认 CrashFix test2 运行稳定，要求并入现有 `BUGFix.asi`。
- 合并后仍只有一个 `BUGFix.asi`，无 INI；不再需要独立 `CrashFix.asi / CrashFix.ini`。
- 保留历史 7 个固定 BUG 修复点完全不变：冥狱杀阵 1 点 + 抗性错位 6 点。
- 新增 Crash 双调用路径：
  - updater `0x004067A0` 入口签名校验；
  - Route A patch block `0x00409541`，12 bytes；
  - Route B patch block `0x00409587`，16 bytes。
- Route A 在 `runtime+0x35` 已启用但 controller 为 NULL/坏指针时，清 `runtime+0x04/+0x35` 并跳过 updater；Route B 的 NULL 保持原版正常跳过语义，只有 non-NULL stale pointer 才清理。
- 有效 controller 仍完全调用原版 `0x004067A0`，没有改背景算法。
- 两路 Hook 任一签名不匹配都独立 fail-closed；Route B 安装失败会回滚 Route A。
- 正常 `FreeLibrary` 时先恢复两条 E9 Hook 再释放 stub，避免 DLL 卸载后留下悬空跳转。
- `CrashFix.ini`、General/Enable、Log、Fixes 开关全部没有合并。
- `BUGFix.log` 继续每次启动清空、UTF-8 BOM、CRLF、简体中文，并新增 Crash 安装/路径观察/命中信息。
- `AnytimeSave.asi / NoCD.asi / MaxGrowthAndDrop.asi / MaxGrowthAndDrop.ini` 的**预编译文件直接沿用 v0.3.1a 原文件，SHA-256 完全不变**，避免本轮合并意外回归。
- 更新后的共享源码重新用 Clang x86 严格交叉构建四个正式 ASI，全部 PE32/i386、非零入口、仅导入 KERNEL32.dll。
- BUGFix 静态分析 0 diagnostic；`ValidateRouteA/B` 反汇编确认 `ret 4`，__stdcall 清栈成立。


## v0.3.1a — 2026-08-19

主题：**修复 v0.3.1 预编译 ASI 零入口点，并完成三个非存档插件的专项回归审计。**

- 用户要求复核新增日志/存档开发是否误伤 `BUGFix / NoCD / MaxGrowthAndDrop`。
- 审计发现 v0.3.1 完整包内四个正式 ASI 和 Probe 的 PE `AddressOfEntryPoint` 均错误为 `0`。
- `AddressOfEntryPoint=0` 时，正常 Windows DLL Loader 不会调用源码里的 `DllMain`；因此 v0.3.1 **预编译 ASI 产物整体作废**。
- 根因是最后封包使用的容器交叉链接产物误用了无入口模式；源码 `build.bat` 本身已经写有 `/ENTRY:DllMain`。
- v0.3.1a 重新严格编译/链接全部五个 ASI，并逐个确认非零入口：
  - `BUGFix.asi`：`0x00001000`；
  - `AnytimeSave.asi`：`0x00002110`；
  - `NoCD.asi`：`0x00001000`；
  - `MaxGrowthAndDrop.asi`：`0x00001000`；
  - `AnytimeSaveProbe.asi`：`0x000037C0`。
- `build.bat` 与 `build_probe.bat` 新增 PE 原始头硬检查：必须同时满足 x86、DLL 标志、`AddressOfEntryPoint != 0`，否则构建直接失败。
- `BUGFix.cpp` 相对 v0.1.0 的 7 个功能补丁地址/原字节/目标字节完全未变。
- `NoCD.cpp` 的 CD 扫描函数指纹、入口 `RET`、备用盘符地址与资源读取策略未变。
- `MaxGrowthAndDrop.cpp` 的 5 个成长补丁、2 个掉宝补丁、INI 键和默认开关行为未变。
- `PatchUtil.h` 的固定字节补丁路径与 v0.1.0 行为等价；新增 CALL Hook 能力只服务于 `AnytimeSave`。
- 四插件所有目标写入区间交叉检查为 **0 重叠**。
- 日志文件各自独立；日志打开失败会退化为 no-op，不作为核心功能是否执行的前置条件。
- 安全回退存档架构本身不变；本轮是二进制入口/交付质量修复，不重新引入 TSA/YCS。

## v0.3.1 — 2026-08-19（历史架构节点；旧预编译包作废）

主题：**停止 TSA/YCS 精确恢复实验；收缩为只生成原版 TSF 的安全回退存档。**
