# 《幽城幻剑录》v0.3.2 逆向分析与验证记录

当前测试 EXE SHA-256：`8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f`

此前额外完成 PE 交付审计：v0.3.1 旧包预编译 ASI 的入口点为 0，属于链接/封包错误，不是 RPG.exe 地址研究结论错误。v0.3.1a 已重新生成非零入口产物；非存档补丁表与历史组合 EXE 的字节对应关系继续成立。

## 1. 原版存档许可

`0x40A0C0`：

```asm
mov eax,[ecx]
mov eax,[eax+380h]
ret
```

读取 MapSCI source `+0x380`。

旧随时存档把中间读取改为 `mov eax,1`，即无条件允许。

## 2. Scene Mode 漏存证据

- `0x40AC00`：按 Map SCI record byte0 初始化 `scene_container+4`；
- `0x40DA50`：EVE opcode `0x3D` 动态写 `scene_container+4`；
- `0x40AE50`：使用 `[scene_container+4] * 0x38` 选择当前 Map runtime entry；
- 原 TSF 已确认字段没有独立保存该动态 index。

这条链解释了“楼梯/多层场景保存的 X/Y 与读档后默认 runtime record 不一致”的结构风险。

## 3. World block

当前 EXE 已确认：

```text
0x44B060 分配 0x27D8
0x44B077 -> [0x978508]
0x44B130 写 Scene Descriptor
0x44B150 写 X/Y/state/actor index
0x44B1A2 manager+0x140 = World ptr
0x44B1B0 manager+0x13C = 0x27D8
```

World 前 `0xC8` bytes 为场景恢复头；之后才是 5000 个 int16 GameVar。

## 4. vanilla fallback 实机 PASS

用户在磐沙堡楼梯危险区域使用 dev1 保存。旁挂没有生成，但 TSF 读档后人物回到场景入口而不是保存位置，并且原先的楼梯坏档没有复现。

因此“把原版 TSF 的场景恢复头规范化到入口级稳定状态”已经有实机正向证据。

## 5. TSA 实验为何停止

### dev1

`.YCS` 写出失败。

### dev2

改名 `.TSA`、绝对 Unicode 路径、延迟提交；实机日志只到“已排队”，没有第一次真实 I/O。

### dev3

Writer 返回后立即第一次 I/O。用户实机日志：

```text
[TSA] 重新打开 TSF / 计算 CRC 尚未成功；第 1 次尝试，Win32 错误码=2
[TSA] ...第 30 次尝试，Win32 错误码=2
[TSA] ...第 44 次尝试，Win32 错误码=2
```

错误码 2 = `ERROR_FILE_NOT_FOUND`。

结论：插件推导的 TSF 绝对路径不等于游戏自己的实际文件系统路径。继续解决需要进入原版文件抽象层逆向；当前正式路线不再依赖该功能。

## 6. v0.3.1a 收缩后的 Hook

只保留：

1. `0x40CCC2` 正常菜单 save-gate CALL；
2. `0x40B078` Map Tick CALL；
3. `0x43B34C` Save Writer CALL。

删除：

- Load Reader Hook；
- 6 个 World Restore CALL Hook；
- TSA/YCS schema；
- TSF CRC；
- 绝对路径构造；
- pending/重试队列；
- exact resume。

## 7. v0.2.x 失败结论保持

地点名、VM blocked、deferred Event、entity transition 等启发式总门：

- v0.2.0 过严；
- v0.2.1 仍漏楼梯坏档。

因此当前正式 gate 不再使用这些黑名单/全局 flag。


## 8. v0.3.2 CrashFix test2 并入 BUGFix 的已确认边界

用户确认独立 CrashFix v0.1.0-test2 运行稳定后，本版将其核心修复并入 BUGFix；INI/配置框架未合并。

崩溃链：

```text
读档 → 返回标题 → 新游戏 → MP0000 / NewGame 生命周期
→ 旧 Legacy Background Controller 引用进入 0x004067A0
→ mov eax,[ecx+20h]
→ Access Violation
```

当前 EXE 静态签名重新核对：

```text
0x004067A0: 8B 41 20 57 85 C0 0F 8E ...
0x00409541: 8B 4E 04 6A 00 6A 00 E8 53 D2 FF FF
0x00409587: 8B 4E 04 85 C9 74 09 6A 00 6A 00 E8 09 D2 FF FF
```

Route A 与 Route B 都在调用 updater 前检查 `runtime+0x04`。有效对象继续原版；stale 对象清 `runtime+0x04/+0x35` 并跳过。Route B 的 NULL 原本就是正常 `je` 分支，因此 NULL 不算命中。

本版没有采用 VEH 吞异常，也没有直接把公共 `0x004067A0` 改成“无效 ECX 就 ret”；仍保持 test2 的窄调用点策略。
