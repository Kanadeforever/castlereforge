
```text

```

```text

0x00440EB9  78 -> 74
0x00440EDF  7C -> 78
0x00440F05  80 -> 7C
0x00440F2E  84 -> 80
0x00440F57  88 -> 84
```

## 3.3 修复“读档返回标题后再新游戏”Legacy Background Controller 崩溃

来源：独立 `CrashFix v0.1.0-test2`，用户已确认运行稳定后并入。

崩溃点：

```text
0x004067A0  8B 41 20   mov eax,[ecx+20h]
```

两条已确认 caller：

```text
Route A patch  0x00409541  12 bytes  resume 0x0040954D
Route B patch  0x00409587  16 bytes  resume 0x00409597
```

语义：

- `runtime+0x04` = Legacy Background Controller*；
- `runtime+0x35` = background ownership/enable 相关标志；
- controller 非 NULL、4-byte 对齐、完整 0x30 bytes 可读：完全走原版 updater；
- Route A 遇到 NULL 或 stale：清 `+0x04/+0x35` 并跳过本次 updater；
- Route B 的 NULL 原本就是正常 `test/je` 分支，仅 non-NULL stale 才清理；
- updater + Route A + Route B 三处签名任一不匹配：Crash 子修复不安装；
- B 安装失败：立即恢复 A，避免半安装；
- 正常 FreeLibrary：先恢复 B/A 两条 E9，再释放 stub。

没有合并：`CrashFix.ini`、General/Enable、Log、Fixes 开关、game2 ESC 影片假死旁支。

## 3.4 日志

# 五、NoCD.asi

## 5.1 历史免 CD 的真实问题

旧免 CD 不是简单“跳过光盘”，而是放宽驱动器类型并接受第一个有效驱动器，现代机器往往导致备用盘符被写成 `C:`。

它长期可用的主要原因：原资源读取先尝试本地 `..\MultiMedia\...`，失败才回退光盘绝对路径。

## 5.2 当前 NoCD

当前实现直接绕过纯光盘扫描函数入口 `0x00402A10`，同时保留：

- 本地 MultiMedia 优先读取；
- 后续地图/影片资源解析；
- 版本/函数指纹验证；
- RPG.exe 所在驱动器作为合理备用盘符。

这是“保留免 CD 功能目标，但修正旧实现历史瑕疵”。

## 5.3 日志

`NoCD.log`：每次启动清空，UTF-8 BOM + CRLF + 简体中文。

# 六、旧“随时存档”补丁的结构性问题

原版 `0x40A0C0`：

```asm
mov eax,[ecx]
mov eax,[eax+380h]
ret
```

旧补丁把中间读取改成：

```asm
mov eax,1
nop
```

等价于无条件通过场景存档许可。

固化研究已闭合 `MapSCI source +0x380` 就是场景存档许可来源之一。因此旧补丁不是只解灰一个 UI，而是绕过制作组给场景设置的真实安全边界。

原 TSF 是持久状态存档，不是完整 runtime snapshot。已知没有完整保存 EventVM、wait/continuation、camera、Battle transient 等状态。

# 九、Scene Mode 漏存链已闭合

## 9.1 初始化

`0x40AC00`：根据 Map SCI record byte0 初始化 `scene_container+4`。

## 9.2 运行中动态修改

EVE opcode `0x3D` / `0x40DA50`：直接把脚本参数写到 `scene_container+4`。

## 9.3 消费者

`0x40AE50`：使用：

## 9.4 TSF 缺口

原 TSF 已确认字段没有独立保存这个动态 selected index。


这条链非常符合楼梯/多层场景坏档表现。

# 十、World block 与 200-byte fallback

当前 EXE 已确认：

```text
0x44B060  分配 0x27D8
0x44B077  写全局 [0x00978508]
0x44B130  写 Scene Descriptor
0x44B150  写 X/Y/state/controlled actor index
0x44B1A2  runtimeManager+0x140 = World ptr
0x44B1B0  runtimeManager+0x13C = 0x27D8
```

World：

```text
0x0000..0x00C7 = 200-byte scene restore header
0x00C8..        = 5000 个 int16 GameVar 开始
```

因此 v0.3.1a 只把前 200 bytes 回退到安全锚点，不把 GameVar 全体回滚。

Map Tick 采样时，World 中的角色 X/Y/state/index 可能尚未由 Save 准备函数刷新，因此插件会从 live controlled actor 读取这四项并覆盖进锚点副本。

# 十五、入口级 fallback 如何建立

每张地图身份变化时清空旧 tracker。

只在：

```text
selectedIndex == defaultIndex
```

且原版 Map Tick 已完成后观察。

连续稳定 8 Tick：

- 第 1 Tick 保存为候选入口样本；
- 后续 Tick 只用于证明同一 default-mode 状态持续；
- 第 8 Tick 后把第一个样本冻结；
- 本地图生命周期内不再更新。

这样 fallback 不会一路跟着玩家滚到楼梯边缘。

# 十六、当前 fail-closed 规则（沿用 v0.3.1a）

扩展保存已经开放后，如果 Writer 阶段发生：

- 地图 runtime 身份变化；
- rawSource/recordCount/fingerprint 不匹配；
- runtime manager World 长度不是 `0x27D8`；
- World 指针为空；
- 200-byte World 范围不可读；

本次保存直接返回失败，不调用原版 Writer 写危险当前位置。

这是安全优先设计。

# 二十、失败方案 / 踩坑汇总

1. 旧 `mov eax,1` 无条件随时存档：会制造楼梯/多层坏档。
2. v0.2.0 宽泛 Event flag 安全门：过严。
3. v0.2.1 少量黑名单安全门：仍漏楼梯坏档。
4. 只看“新图/纯数字存档名”：只能是风险信号，不能解释全部根因。
5. 把 `0x89F81E` 等特定协议状态当全局危险旗标：错误。
6. 把 actor packed field 某个 byte 直接解释成楼梯层：证据不足，已降级。
7. dev1 相对 ANSI sidecar：失败。
8. dev2 TSA 只依赖后续 Map Tick 首次提交：执行机会缺口。
9. dev3 绝对路径 TSA：真实 I/O 错误码 2，路径模型与原版文件系统不一致。
10. 继续扩大 TSA 路径逆向会增加正式插件复杂度，当前已停止。
11. v0.3.1 最终容器封包误用了 `AddressOfEntryPoint=0` 的无入口交叉链接产物：属于严重交付回归；v0.3.1 旧包预编译 ASI 全部作废。v0.3.1a 已修并把非零入口加入构建硬门。
