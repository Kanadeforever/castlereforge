# 《幽城幻剑录》v0.3.2 工具类与诊断工具说明

> **现状同步（2026-08-28）：** 本文描述 v0.3.2 历史工具副本。当前 SaveEnhance 已有
> 独立的 `PatchUtil.h / PluginLog.h / Win32Mini.h / Castle_PadSupport_API.h` 与验证器，
> 以 `src/SaveEnhance/tools/工具详细说明.md` 为准；不要再假设它与三个 Extra 插件完全同版。

> 2026-08-28 目录整理后，正式源码不再共用一个物理 `src/Extra/source` 目录。`BUGFix / NoCD / MaxGrowthAndDrop` 各自在 `src/Extra/<功能名>/source` 携带一套头文件，安全存档增强功能在 `src/SaveEnhance/source` 携带同版本副本。本次只复制和移动现有文件，没有改变工具实现。

## 1. PatchUtil.h

四个正式插件使用同一版本的内存补丁工具；当前每个功能目录各自保存一份，便于独立构建和接档。

能力：

- 获取 RPG.exe 基址；
- 固定字节比对；
- VirtualProtect 安全写入；
- FlushInstructionCache；
- 一组补丁先全验证再写；
- x86 `CALL rel32` 运行时重定向。

v0.3.2 的 BUGFix 双路径 Crash 修复没有把 CrashFix 旧工程整套 patch.c 搬进来，而是继续复用当前稳定的 `WriteBytes`/机器码校验，并在 BUGFix.cpp 内只实现 E9 stub 所需的最小分支构造与正常卸载恢复。

所有写入前都要求目标字节属于已确认状态，避免不同 EXE 上盲写。

## 2. Win32Mini.h

只声明插件实际需要的少量 Win32 类型/API，不包含完整 `windows.h`。v0.3.2 新增 `VirtualAlloc / VirtualFree / GetLastError`，只服务于 BUGFix 合并后的 Crash 双路径 stub。用于：

- 正式 MSVC x86 构建；
- 当前研究环境 Clang 32 位 PE 第二套复核；
- 控制最终只依赖 `KERNEL32.dll`。

## 3. PluginLog.h

四个正式插件使用同一版本的日志工具；当前每个功能目录各自保存一份。

统一规则：

- `CREATE_ALWAYS`：每次启动先清空旧日志；
- UTF-8 BOM；
- 所有换行明确写 CRLF；
- 简体中文正文；
- 日志位于 ASI 同目录；
- 不依赖 CRT；
- v0.3.2 新增 `Hex32()`，用于 BUGFix.log 记录 Crash 路径中的 runtime/controller 地址，仍然逐字符输出、不依赖 sprintf。

## 4. AnytimeSaveProbe.asi

历史研究包曾附带只读诊断工具 `v0.3.1a-probe1`。当前 `src/SaveEnhance` 源码目录已不再携带 Probe；以下内容保留为历史工具说明，相关实机日志与分析证据仍在 `docs/Extra/参考资料`。

用途：在原版拒绝存档的地点记录：

- Map record_count / selected_index；
- Map runtime entry；
- 玩家坐标/状态；
- 碰撞 controller；
- 附近实体；
- Event VM 原始区。

Probe 不开放原版禁存点，不写 TSF，只负责采样。

日志同样每次启动清空、UTF-8 BOM、CRLF、简体中文。

**Probe 与正式 AnytimeSave 不可同时加载。**

2026-08-28 整理期间曾验证 Probe 在当前 MSVC 19.51 下会于自定义 `memcpy/memset` 定义处报 `C2169`。当前源码包已移除该诊断工具；若以后需要恢复，必须从历史研究包取回并单独解决编译器兼容问题。

## 5. PE 入口点构建后检查

`src/Extra/BUGFix/build.bat`、`src/Extra/NoCD/build.bat`、`src/Extra/MaxGrowthAndDrop/build.bat` 与 `src/SaveEnhance/build.bat` 会在各自 ASI 链接后直接读取 PE 头，检查 x86、DLL 标志和非零 `AddressOfEntryPoint`。`src/Extra` 根目录不再保留构建脚本，仓库根 `build_all.bat` 直接调用三个 Extra 功能入口。这是 v0.3.1a 首次固化、v0.3.2 继续强制执行的交付工具规则，用来防止“DLL 文件存在、导入表正常，但 DllMain 永远不执行”的空壳产物再次进入包。
