# 插件 INI 编辑器说明

## 1. 触发条件

只有以下严格同名组合才在 ASI 行右侧显示“编辑”：

```text
mods\asi\插件名.asi
mods\asi\插件名.ini
```

Overrides 不显示 INI 编辑按钮。INI 编辑器只编辑现有文件，不负责替第三方插件创造配置语义。

## 2. about3 的自动换行修复

`about2` 已经移除了横向滚动样式，但自动换行设置发生在 RichEdit 仍是 `0×0` 的创建阶段。Windows 实机证明：这不足以让最终实际宽度生效，因此出现“没有横向滚动条，但长行仍被右边裁掉”的现象。

`about3` 改为：

1. 先通过 `MoveWindow` 给 RichEdit 设置真实编辑区尺寸；
2. 然后调用 `refresh_ini_word_wrap_()`；
3. 通过 `EM_SETTARGETDEVICE` 强制清掉旧排版目标，再恢复“按当前控件宽度自动折行”；
4. 每次 `WM_SIZE` 重新布局后都重复此步骤。

因此长注释、长路径和长值会随窗口当前宽度视觉折行。视觉折行不会向原文本插入 CR/LF，所以保存后的 INI 逻辑行不会被偷偷拆开。

## 3. 为什么分色逻辑也必须跟着修改

RichEdit 开启自动换行后，“显示出来的一行”不等于“INI 文件中的一行”。如果继续使用会受视觉折行影响的行号 API，长行折成两段后就可能造成：

- 注释后半截被当成下一行重新解析；
- 变量/值颜色错位；
- 保存错误跳转到错误位置。

about3 不再用视觉行号驱动分色，而是在 RichEdit 自己的字符位置（cp）坐标里使用 `EM_FINDTEXTEXW` 搜索真实 `\r` / `\n`，以真实换行符切分“逻辑行”。读取仍使用 `EM_GETTEXTRANGE`，着色仍使用 `EM_EXSETSEL + EM_SETCHARFORMAT`。

这样一条很长的注释即使视觉上折成三四行，仍被视为同一个 INI 逻辑行并整行着为绿色。

## 4. 语法颜色

- `;` / `#` / `//` 整行注释：绿色；
- `[Section]`：紫色；
- `=` 左侧变量名：蓝色；
- `=`：灰色；
- 值：橙色；
- 明显结构错误：亮红色。

颜色只帮助阅读，不改变文件内容。

## 5. 未保存和错误提示

about3 强化了编辑器底部状态提示：

- 内容发生修改后显示亮红色 `● 未保存修改`；
- 保存校验失败后显示亮红色 `● 保存失败：...`；
- 保存失败仍会弹出详细错误说明，并选择到真正的 INI 逻辑错误行；
- 保存成功后恢复正常状态文字。

这样即使不立即看弹窗，也能明显看到当前文件还没有安全保存。

## 6. 保存前结构校验

当前是“通用 INI 结构校验”，包括：

- 节名为空；
- `[` 后缺少 `]`；
- 普通设置行缺少 `=`；
- 等号左边变量名为空；
- 不允许的控制字符等。

校验器不会猜测第三方 ASI 自己定义的键名、枚举或数值范围，因此不会把合法的插件私有设置误判成非法。

## 7. 编码保持与安全写盘

支持并保持：

- ANSI；
- UTF-8 无 BOM；
- UTF-8 BOM；
- UTF-16LE；
- UTF-16BE。

ANSI 文件如果加入当前代码页无法无损表示的新字符，会拒绝保存，避免静默变成 `?` 或近似字符。

写盘流程为：

```text
原 INI
  ↓
同目录 .castle.tmp
  ↓
FlushFileBuffers
  ↓
MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)
```

因此校验失败或临时写入失败时不会先截断原文件。


## about5 继承说明

about5 只修改 About 标题栏；INI 编辑器继续沿用 about3/about4 的自动换行、语法分色、亮红未保存/错误状态、原编码保持和保存前结构校验，不改文件格式语义。
