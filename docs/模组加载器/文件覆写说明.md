# 文件覆写（Overrides）说明

## 机制

`mods\overrides\某Mod\...` 模拟原游戏路径。游戏读取原文件时，Loader 在文件 API 层查找启用的替代文件；不覆盖磁盘原文件。

## 优先级

GUI 越靠下优先级越高；运行时逆序查找，第一个存在的替代文件获胜。

## 与 SetDllDirectory 的关系

Overrides 本身并不依赖 DLL 搜索机制。dev9 保留 `SetDllDirectoryW(mods)` 是因为该整体运行时环境已经由用户实机证明能同时保持转区与 cnc-ddraw 截图，不是 Overrides 的实现前提。

## ddraw

dev9 封存基线继续保留对已加载 `ddraw.dll` 的既有 Win32 IAT 兼容桥，但：

- ddraw 不注册为 `game.log` 的原版 caller；
- cnc-ddraw 自己写截图文件不会冒充 RPG.exe 原版资源访问；
- 不 Hook `DirectDrawCreate` / `SetDisplayMode` / DirectDraw COM 接口；
- 不再继续研究其它 ddraw wrapper 兼容性。

## 安全边界

- 只重定向读取型 `OPEN_EXISTING`；
- 写入/创建不重定向；
- ANSI 游戏路径按 CP950；
- 模板目录不参与正式覆盖。

`dev9-about5` 不改 Overrides 代码或运行时 DLL。
