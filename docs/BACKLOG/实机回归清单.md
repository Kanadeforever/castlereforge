# Castle Backlog v0.3.1-test1 实机回归清单

> 本清单与《完整接档说明.md》对应。先测崩溃，再测输入；任何崩溃出现时停止后续项目并保存 `Castle_Backlog.log`。

## 一、NPC 历史崩溃

- [ ] 与 NPC A 连续产生至少 3 条有姓名页面，退出对话，再按 B 打开 BACKLOG。
- [ ] 关闭后与 NPC B、NPC C 各产生数条有姓名页面，再回自由探索打开。
- [ ] 历史列表同时出现不同 NPC 姓名时不崩溃。
- [ ] 连续滚动到更旧/更新的不同 NPC 记录不崩溃。
- [ ] 反复“打开 → 关闭 → 新 NPC → 再打开”至少 10 次不崩溃。
- [ ] 若日志出现 `F-Name 对象没有通过已加载 SF2 协议检查`，游戏仍稳定；该次允许只显示姓名文字而没有姓名牌。

## 二、姓名框与正文布局

- [ ] 有姓名条目正文不再向右缩 96 像素。
- [ ] 左侧姓名位于正文上方约 35 像素。
- [ ] 右侧姓名位置正确。
- [ ] F-Name 可用时有姓名牌，且姓名文字与姓名牌对齐。
- [ ] 无姓名条目只有 F-Talk，不凭空出现姓名牌。
- [ ] 长句不提前撞右边界。

## 三、INI

- [ ] `Open=B` / `Exit=B` 正常。
- [ ] `Up=UP` / `Down=DOWN` / `Left=LEFT` / `Right=RIGHT` 正常。
- [ ] 临时把某项改成 `VK_B`，仍能兼容识别。
- [ ] 临时把某项改成旧 `0x42`，仍能兼容识别。
- [ ] `PanelStrideY=110` 比默认更紧。
- [ ] `PanelStrideY=125` 比默认更松。
- [ ] 极端小于 80 或大于 160 的值被源码安全裁剪。

## 四、鼠标

- [ ] BACKLOG 关闭时，滚轮向上可打开。
- [ ] BACKLOG 打开后，滚轮向上查看更旧记录。
- [ ] BACKLOG 打开后，滚轮向下查看更新记录。
- [ ] BACKLOG 打开后，鼠标右键退出。
- [ ] 右键退出时底层地图/UI 不同时收到一次右键点击。
- [ ] Alt+Tab 到其它程序后滚轮/右键不会累积成切回游戏后的误操作。

## 五、单独使用，不安装 PadSupport

- [ ] BACKLOG 正常加载。
- [ ] 键盘和鼠标全部正常。
- [ ] 不需要 `SDL3.dll`。
- [ ] 手柄不会被 BACKLOG 自己打开或响应。

## 六、配合 Castle_PadSupport.asi

- [ ] 日志出现 `已接入 Castle_PadSupport`；若出现签名无法唯一识别，则当前 PadSupport 二进制需要补签名，不能把该项算通过。
- [ ] 普通 Controller 模式按 LB 打开。
- [ ] 打开后按 LB 退出。
- [ ] `SwapConfirmCancel=0` 时 PadSupport 的 East/B 取消可退出。
- [ ] `SwapConfirmCancel=1` 时 PadSupport 的 South/A 取消可退出。
- [ ] D-Pad 上下浏览正常。
- [ ] D-Pad 左右按原 `PageSize` 跳页正常。

## 七、PadSupport 模式屏蔽

- [ ] LT 调查模式中 LB 不打开 BACKLOG。
- [ ] LT 调查模式中 D-Pad/取消不控制 BACKLOG。
- [ ] RT 临时鼠标模式中 LB/D-Pad/取消不控制 BACKLOG。
- [ ] Back 常驻鼠标模式中 LB/D-Pad/取消不控制 BACKLOG。
- [ ] 在屏蔽模式里一直按住 LB，再退出该模式：BACKLOG 不会立刻被误打开。
- [ ] 松开 LB 后重新按一次，才允许正常打开。

## 八、关闭与原剧情恢复

- [ ] 从自由探索打开/关闭后角色移动恢复。
- [ ] 在原版对话仍存在时打开/关闭，原剧情页面和逐字进度恢复。
- [ ] 退出 BACKLOG 后不会因为先前在历史里按过确认键而推进下一句。
- [ ] 与宽屏插件同时使用时，关闭后视觉状态正常。
