# 地址与协议证据

## 目标版本

支持白名单包含：

- `b10c65f56051e5a625b6c34857bcb73bd002efe3c158b6bd0cc2bb17fa871dcf`；
- `8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f`。

当前仓库参考 EXE 是第二项。SHA 只允许进入能力预检，不能代替机器码检查。

## 消息页

`0x403B90` 建立消息：`0x46F660` 为当前 MSG 资源基址，`0x46F67C` 为 record 偏移，`0x46F680` 为当前页面偏移，`0x46F684` 为本页字节长度。

`0x4040B0..0x4043D3` 按两字节单元解释正文和控制码，并把已显示内容复制到 `0x46F664` 指向的 512 字节缓冲。`0x4046F0` 在下一页时执行 `page_offset += total_bytes`、清长度/进度并重新扫描下一页。因此 Backlog 捕获公式与原版复制公式一致。

## 说话人

EVE `0x05/0x33` 共用 Execute `0x40CB70`：先调 `0x403B90(event_id,message_index,option)`，再把 record `+4/+5/+6` 传给 `0x403C60`。

`0x403C60` 保存：

- `0x46F675`：speaker/是否带姓名表现；
- `0x46F674`：style；
- `0x46F676`：variant；
- `0x46F668`：从 `NameList.Lis` 选出的姓名指针。

speaker 非零时它用 `%d-2.SF2` 与 `F-Name.SF2` 构造原版资源。speaker 为 0 时关闭姓名表现。`v0.1.0` 曾在浏览历史时调用它；用户实机证明跨人物重建后会触发 SAF FrameID 越界。`v0.2.0` 只把这些字段和 `0x46F668` 姓名文字复制进历史，浏览期间禁止调用本函数。

## 绘制

`0x404800` 入口读取 `0x46F679`。current 非零时绘制对话外观；current≥4 时从 `0x46F664` 绘制正文。speaker 非零还绘制人物/姓名资源和 `0x46F668` 姓名。

Backlog 不改函数入口和外层 CALL。现代模式只接管两个内部 E8：

- `0x40486E` 原目标 `0x407510`：ECX 是通用 F-Talk 对象，五个栈参数原样透传。包装器临时调整对象 `+4` 的 Y，在 `-330/-220/-110/0` 四个相对位置绘制，随后恢复坐标；
- `0x4049FF` 原目标 `0x402EE0`：thiscall 后有八个参数，其中第 4/5 个是文字 x/y、第 7 个是原始字节串。包装器保留字体、表面、裁剪和 flags，只替换每条的 x/y/text。

浏览时 `0x46F675=0`，所以 `0x404800` 的人物/姓名资源分支整体跳过。姓名从历史独立缓冲交给 `0x402EE0`，人物资源完全不参与。

## 状态更新

`0x403E30` 在 target/current 就绪后按 `0x46F640` 的 0..3 分发表进入普通文字、等待、浮动选择或剧情两项选择。mode 大于 3 会跳过这些业务分支，随后仍回到原版公共尾路径。因此 `0xFFFFFFFF` 可作为查看期间只读 mode；关闭必须恢复原值。

## 场景 vtable

`0x460298` 内容：

```text
vtable[0] = 0x40B150  场景逻辑更新
vtable[1] = 0x40B050  场景绘制
```

插件替换 vtable[0] 并链式调用原当前值；另外窄 Hook 两个消息绘制 CALL。vtable[1] 保持不变，宽屏仍能识别 world manager。

## 原版暂停门

- `0x89F81D`：Event yield；
- `0x89F81E`：Event block，`0x40B2D0` 非零时不推进 VM；
- `0x468BB9`：地图输入到动作桥，事件激活时会清零；
- `0x89F808`：地图 action/busy；
- `0x89F820`：当前事件表；
- `0x468BF0`：当前地图角色/键位模式，原版 Space 业务要求非零。

SHOW_MESSAGE 本来就设置 Event 阻塞；Backlog 查看复用相同门，并保存/恢复原值。

## v0.3.3-test3 新增绘制旁路证据

剧情旁路新增三个独立 CALL：
- `0x404859`：当前说话人物 `%d-2.SF2` 绘制；
- `0x404899`：当前剧情 `F-Name.SF2` 绘制；
- `0x4048E6`：当前剧情姓名文字绘制。

历史通用框与正文仍为：
- `0x40486E`：`F-Talk.SF2`；
- `0x4049FF`：正文。

五个 CALL 分别保存各自安装前目标，不能跨对象复用前置 wrapper。
旧文档中“Backlog 活动时把 speaker_active 设为 0”以及“统一写 mode=0xFFFFFFFF”均为旧实现，
**不再适用于剧情旁路模式**；只有自由探索 synthetic 载体允许写 Backlog 自己拥有的消息状态。


## v0.3.3-test4 调度证据与结论

本轮没有新增 RPG.exe 地址。修复来自已通过/失败版本的行为对照：

- v0.3.2：synthetic dialogue 活动时仍链式调用 `SceneWorld update`，实机可进入 `F-Talk` / 正文绘制；
- v0.3.3-test3：synthetic 状态建立后立即截断 `SceneWorld update`，实机确认“Backlog 已打开但无框无正文”；
- 因此 synthetic dialogue 不只是若干全局字段，还依赖原版消息更新步骤把绘制载体维持在可 draw 状态。

剧情旁路与 synthetic 的所有权不同，所以 test4 只恢复 synthetic 的 update；真实剧情仍完全冻结。

## v0.3.4-test2 坐标与游标证据

- 原版正文 Y=`0x17C=380`，姓名相对正文 Y=-35；四槽最上位移是 `-3*PanelStrideY`；
- test1 默认 118 得到姓名 Y=-9，已构成确定负坐标；test2 上限 110，最上姓名 Y=15；
- `0x407270` 写 object `+0x50` layer 指针与 `+0x54` layer index；
- `0x4072D0` 写 `+0x58` subresource 指针与 `+0x5C` index；
- `0x407510` 每层调用上述函数，所以同一对象多画必须保存/恢复四字段。

现行代码在每次 F-Talk/F-Name 绘制前恢复游标快照，并在整轮结束后再次恢复。

## v0.3.4-test3 三条安全公式

步长大于 110 时容量改为三条，最上姓名 `Y=345-2*stride`。在允许上限 160 时等于 25；
因此 111～160 不需要夹回 110。步长不大于 110 时仍用四条，最上姓名 `Y=345-3*stride`。
