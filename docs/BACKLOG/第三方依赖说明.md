# 第三方依赖说明

## 当前依赖边界

Castle Backlog 官方版需要同目录 `Castle_Runtime.dll`，可以脱离 Castle Mod Loader 和其它业务
ASI 运行。它使用 RPG.exe 原有对话资源，并静态依赖 KERNEL32/USER32；不携带 SDL3，也不直接
打开手柄设备。

Runtime 提供：

- Hook：五个对话绘制 CALL 和 SceneWorld vtable 链；
- Schedule：8ms 输入轮询；
- Window：鼠标 Observer/Filter；
- Input：统一手柄快照和焦点租约；
- GameState：Dialogue Mutation Lease；
- TOML 与 Log：配置读取和 `mods/logs/Castle_Backlog.log`。

## PadSupport 联动

PadSupport 是可选的业务插件，不是 Backlog 的硬依赖。Controller 存在并注册 Runtime Input
Provider 后，Backlog 读取 LB、方向键、取消语义和 `allows_external_ui_input`；没有 Provider
时保留键盘和鼠标。

Backlog 不再包含 `Castle_PadSupport_API.h` 副本，也不查询 `CastlePad_GetApi`。官方源码禁止：

- 按 `Castle_PadSupport.asi` 文件名查模块；
- 扫描 PadSupport 函数机器码或内部状态；
- 自行初始化 SDL3；
- 维护第二份手柄设备状态。

旧 `CastlePad_GetApi` v1 仍由 Controller 为第三方兼容保留，但不是官方 Backlog 的接入路径。

## 运行与验收

原始光盘 EXE 无 NoCD 无法启动，因此单插件验收组合是 Runtime + NoCD + Backlog；换用其它
ASI Loader 时依旧保留 Runtime DLL。缺少或损坏 Runtime 时 Backlog 必须保持停用，不安装本地
Hook、不创建线程或旁路日志。

Backlog 的 SF2、剧情状态和布局算法仍属于本插件。Runtime 只协调基础设施，不提供或修改其
业务资源。已知历史崩溃原因和实机结论见《完整接档说明.md》，当前静态检查使用
`src/Backlog/tools/backlog_check.py`。
