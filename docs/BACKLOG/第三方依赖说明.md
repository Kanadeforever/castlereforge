# 第三方依赖说明

## 1. 运行时硬依赖

Castle Backlog 本身只依赖 RPG.exe、Win32 `kernel32/user32` 与游戏已经存在的资源。
**Backlog 不再加载 SDL3.dll，也不拥有任何手柄设备。**

键盘和鼠标始终由 Backlog 自己处理：
- Virtual-Key 名称配置；
- 鼠标滚轮打开/上下浏览；
- 鼠标右键退出。

## 2. Castle_PadSupport.asi 是可选协作依赖

单独安装 Backlog 时完全没有手柄输入，这属于设计行为。

若同时安装支持 Public API v1 的 `Castle_PadSupport.asi`，Backlog 运行时只做：

1. `GetModuleHandleA("Castle_PadSupport.asi")`；
2. `GetProcAddress(..., "CastlePad_GetApi")`；
3. 请求 `CASTLE_PAD_API_VERSION_1`；
4. 检查 `magic / struct_size / api_version / capability_flags`；
5. 只调用函数表，不扫描 PadSupport 内部内存。

Backlog 使用的公开能力：
- 物理 `LB`：打开/退出；
- 物理 D-Pad：历史导航；
- 语义 `CANCEL`：退出，自动遵守 PadSupport 的 `SwapConfirmCancel`；
- `AllowsExternalUiInput()`：调查模式、RT 临时鼠标、Back 常驻鼠标时阻断 Backlog 手柄输入。

## 3. 已废弃方案

以下方案均不得恢复：
- Backlog 自己初始化 SDL3；
- 扫描 `PadInput_Down()` / `ControlModes_BlocksMapMovement()` 短函数机器码；
- 搜索 `PadInputState` / `ControlModeState` 数据布局；
- 写死 PadSupport 模块基址偏移。

这些方案已在 v0.3.1/v0.3.2 实机证明会因编译器优化或结构变化失效。

## 4. 公共接口头文件

Backlog 源码随附 `Castle_PadSupport_API.h` 的 v1 契约副本。
该文件必须与 PadSupport 发布的同名公共头保持 ABI 一致。
