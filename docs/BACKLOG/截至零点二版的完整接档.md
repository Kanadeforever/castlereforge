# 截至零点二版的完整接档

## 一、当前结论

Castle Backlog `v0.2.0` 已把首个实机可工作的底层记录系统升级为现代整屏列表。源码位于 `src/backlog/源码`，检查器位于 `src/backlog/工具`，正式文档位于 `docs/backlog`，可直接测试的 ASI/INI/文档/工具包位于 `src/backlog/编译内容`。

当前状态必须准确写成：

- 用户已实机确认 `v0.1.0` 的记录、打开、固定底框浏览和退出主链可以工作；
- 同次实机发现旧版倒换带人物记录时会报 `FrameID >= m_SafHeader->TotalFrameNumber`，现已闭合为跨人物重建 SAF/SF2 后沿用旧动画 FrameID 的错误；
- `v0.2.0` 浏览时完全不调用 `0x403C60`、不卸载或加载人物 `%d-2.SF2`，只把当前人物显示标志临时清零，退出直接恢复原指针和标量；
- 新展示为同屏四条纵向记录：每条复用原版 `F-Talk.SF2` 框、原字体姓名文字和正文，不显示人物图；
- 核心架构、游戏地址、输入门、文本捕获、环形历史、键盘改键、SDL3 可选手柄、热插拔、宽屏兼容和手柄插件防穿透均已实现；
- x86 编译、链接、PE 导入、目标 EXE SHA/机器码、源码包结构和 INI 静态检查已通过；
- `v0.2.0` 已静态/编译 PASS，但新的四框纵向位置、姓名列、长文本和旧 FrameID 报错消失仍需下一轮实机确认；
- 当前唯一需要外部继续推进的项目是按《测试与已知限制》的现代模式清单进行实机回归，并带回 `Castle_Backlog.log`。

| 要求 | 本版实现 |

| 方向上/下逐条 | 上移到更旧、下移到更新；到最旧/最新后继续按会环回另一端 |
| 方向左/右翻页 | 默认每次跳 4 条（正好一屏），可由 `PageSize` 调整；页边界停在最旧/最新 |

| 不影响手柄插件 | 不修改手柄插件代码、SDL 状态、InputRouter 或其 Hook；退出有一帧 ID=0 屏障清理其普通对话 A pending |

## 三、已经确认的架构

### 1. 记录来源

没有扫描整个游戏目录，也没有在打开时重新解析 MSG 文件。场景游戏线程每次进入 vtable 更新函数时，读取原版当前消息页：

```text
正文地址 = [0x46F660] + [0x46F67C] + [0x46F680]
本页长度 = [0x46F684]
```

正文按原始 CP950/控制码字节复制到插件历史。说话人三项来自 `0x46F675/674/676`。同一页用消息 ID、资源基址、record 偏移、page 偏移和长度去重。

### 2. 历史所有权

历史完全属于插件内存，最大静态容量 256 条，INI 默认启用 128 条。达到上限后只覆盖最旧记录。没有存档写入、磁盘历史文件或游戏资源修改；退出 RPG.exe 后历史自然清空。

### 3. 展示方式

打开时保存原消息 ID、mode、逐字长度/进度、显示缓冲指针、说话人、姓名指针、视觉 target/current 和三项地图/事件输入门。随后：

1. 地图输入门置 0；
2. Event yield/block 置 1；
3. 自由地图时给消息 ID 放临时非零值，供宽屏插件认出“当前有消息 UI”；
4. mode 置无效值，阻止 `0x403E30` 进入推进/选择分支；
5. `0x46F675` 临时置 0，禁止原版消息层画人物；已经加载的剧情人物资源保持原封不动；
6. `0x46F664` 临时指向插件自己的 512 字节缓冲；
7. target/current 置 4；`0x40486E` 包装器纵向画最多四个通用 F-Talk 框，`0x4049FF` 包装器逐条画姓名和正文。

关闭时按反顺序恢复。原消息缓冲从未被覆盖，只临时替换指针，因此逐字显示到一半时打开再关闭也能回到原进度。

### 4. Hook 边界

长期写点共三处：场景 vtable `0x460298` 的第 0 项，以及 `0x40486E/0x4049FF` 两个内部绘制 CALL。三处都保存安装时的当前目标并链式调用；第 1 项 `0x40B050` 绘制函数和宽屏验证的入口机器码保持不变。

没有修改：

- `0x403E30` 消息更新机器码；
- `0x404800` 消息绘制机器码；
- `0x40B087/0x40B08C` 两个 CALL；
- `GetAsyncKeyState/GetKeyState` IAT；
- 手柄插件的对话 A、SDL、输入路由、探索移动或菜单 Hook；
- 宽屏插件验证和识别的 `vtable[1]=0x40B050`。

新增的两个窄 Hook 只改 `0x40486E`（F-Talk draw CALL）和 `0x4049FF`（正文 draw CALL）的 E8 目标；宽屏/手柄现有检查不包含这两个内部 CALL，且非 Backlog 状态完整链回安装前目标。

## 五、成功方案

1. **游戏线程捕获**：避免 worker 与地图卸载并发读取 MSG 指针。
2. **插件内存环形队列**：不改变存档，不依赖地图文件重新解析，不把未来剧情写回游戏。
3. **替换显示缓冲指针而非覆盖原缓冲**：关闭后逐字进度可以精确恢复。
4. **现代无人物列表**：只复用通用 F-Talk 框、NameList 姓名文字和原字体，不触碰人物 SAF/SF2 生命周期。
5. **原版模态门**：复用 Event block 与地图输入 gate，不伪造全局暂停时钟。
6. **vtable[0] 链式 Hook**：不碰手柄插件 CALL；保留宽屏对 world draw 的识别。
7. **SDL 动态发现**：有 SDL 才启用手柄，没有 SDL 不影响 DLL 装载和键盘。
8. **退出释放屏障**：先让消息 ID 保持 0 至下一场景更新，清除手柄插件可能排队的 A，再恢复真实对话。
9. **两处内部绘制窄 Hook**：非活动时完全透传；活动时四框和四条文字共享同一可验证窗口。

## 六、失败方案与禁止回流项

这些路线在设计阶段已否决，后续不要因为“写起来更直观”重新采用：

1. **启动时解析全部 MSG**：无法可靠知道玩家实际看到哪条、变量替换/选择结果和当前说话人，也会把未触发剧情混入历史。
2. **自己用 GDI/DirectDraw 画新窗口**：违反不加资源和复用原 UI；还会与宽屏缩放、字体和 CP950 排版重复实现。
3. **全局 Hook GetAsyncKeyState/IAT**：会改变手柄、标题、战斗、探索和其它插件输入读取，兼容面过大。
4. **修改 `0x40B087/0x40B08C`**：宽屏插件会静态检查这两个 CALL；先加载 Backlog 可能让宽屏 fail-closed。
5. **直接跳过整个 `0x40B150`**：该函数同时把 world manager 登记进绘制队列；跳过会让背景和 Backlog 都不再稳定绘制。
6. **worker 调 `0x403C60`**：资源构造/释放不允许跨到 SDL 线程。
7. **覆盖原 512 字节缓冲**：逐字显示中打开会丢掉尚未显示完的原状态，关闭无法精确恢复。
8. **倒记录时重建人物资源**：`v0.1.0` 实机触发 `FrameID >= TotalFrameNumber`；现代模式永久禁止在浏览中调用 `0x403C60`。
9. **把人物图放进整屏列表**：会让一帧反复装卸多个 `%d-2.SF2`，既不现代也不安全；现行只显示姓名文字和对话框。

## 七、已踩坑

- 初次写入的批处理是 LF 行尾，Windows `cmd.exe` 会把命令拆坏；现已固化为 CRLF。
- 初次手抄 `0x40B150` 第二个 CALL 相对位移写成 `3E`，静态检查器读当前 EXE 发现实际为 `43`，已同步修正源码预检和工具，未进入发布包。
- 原计划 Hook `0x403E30/0x404800`，遍历宽屏源码后发现其预检明确依赖入口与 CALL 不变，方案撤销。
- 原计划整段跳过场景更新来暂停游戏，反汇编确认 `0x40B150` 还负责绘制队列注册，方案撤销。
- 只恢复对话状态不足以防手柄插件的 A pending；现已增加跨一次场景更新的 ID=0 退出屏障。
- 用户实机证明旧版跨说话人倒记录会报 SAF FrameID 越界；根因不是历史正文，而是 `0x403C60` 重建了不同总帧数的人物资源。`v0.2.0` 已彻底删除浏览期人物资源重建。

## 八、测试结论

当前 `v0.2.0` 自动检查结论：

- 所有 C 源码以 `/W4 /WX` 编译通过；
- x86 `/nodefaultlib` 链接通过；
- ASI machine=`0x014C`，PE32，存在 DllMain；
- 导入 DLL 只有 `KERNEL32.dll` 与 `USER32.dll`；
- 没有 SDL、MSVCRT、UCRT、VCRuntime 强制导入；
- 当前参考 RPG.exe SHA-256=`8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f` 通过；
- 说话人、消息更新、消息绘制、场景更新、F-Talk CALL、正文 CALL 与 vtable 全部通过；
- 九个 C/H 文件均有中文块注释，代码文件名为 ASCII；
- INI 默认 B/LB/East/方向键项目通过。
- 最终 ASI 大小、SHA-256 与可复现性以本轮最后构建后的《文件校验清单》为准；
- `docs/backlog` 9 份 Markdown 会在最终构建后与源码包、编译内容包逐文件复核。

实机已完成：旧版底层记录/打开/浏览/退出主链可工作；旧版人物倒换为明确 FAIL。尚未完成：`v0.2.0` 四框整屏位置、姓名列、长文本、多页/选择、FrameID 回归、宽屏同开、手柄同开、无 SDL、切图和读档的人工验收。

## 九、当前阻塞项与下一步

没有源码、地址或编译阻塞。下一步严格按以下顺序：

1. 先只装 Backlog，确认同屏最多四个 F-Talk 框从下向上排列，画面没有任何人物图；
2. 反复倒换多个不同人物记录，确认旧 `FrameID >= TotalFrameNumber` 报错完全消失；
3. 验证左侧姓名、右侧正文、五行长页、上下逐条、四条整页跳转和退出恢复；
4. 加载手柄插件与 SDL3，验证 LB 打开、East 退出、方向浏览，以及 Backlog 内误按 A 后退出不跳句；
5. 删除/移走 SDL3，验证 ASI 仍加载、键盘可用、日志仅提示可选 SDL 不可用；
6. 加载宽屏，验证整屏四框只绘制中央一次，左右不重复；
7. 在标题、战斗、主 Interface、商店、炼化、客栈、存档和电影中逐项确认无法打开；
8. 带回 `Castle_Backlog.log` 和具体对话/地图复现点；只有现代展示人工结果完成后才能更新为实机 PASS。
