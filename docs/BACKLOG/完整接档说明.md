## 3. 已确认的原版对话绘制架构

### 3.1 通用正文框 F-Talk

原版 `0x404800` 消息绘制函数中：

- `0x40486E`：F-Talk.SF2 绘制 CALL；
- 原始目标：`0x407510`。

BACKLOG Hook 这一处，将同一个 F-Talk 对象临时移动到四个纵向位置并依次绘制，结束后恢复原坐标。

### 3.2 有姓名对话额外使用 F-Name

有姓名不是“把姓名塞到正文左边”。原版是独立叠加：

- `0x46F658`：当前 `F-Name.SF2` 对象槽；
- `0x404899`：F-Name.SF2 独立绘制 CALL；
- 原始目标同样是 `0x407510`。

因此 F-Talk 与 F-Name 虽然原版最终都调用 `0x407510`，但它们是两条独立 CALL。若其它 ASI 已经分别在两处建立 wrapper，BACKLOG 必须分别保存当前链目标，不能拿 `0x40486E` 的前置函数去画 F-Name。

本版新增 `g_name_panel_draw`，从真正的 `0x404899` 取得 F-Name 当前调用链目标。

### 3.3 姓名和正文原版坐标关系

原版机器码确认：

- 正文：`X = base + 0x3C`，`Y = base + 0x17C`；
- 左姓名：`X = base + 0x20`，`Y = base + 0x159`；
- 右姓名：`X = base + 0x1E8`，`Y = base + 0x159`。

换算成相对正文：

- 左姓名 X：`-28`；
- 右姓名 X：`+428`；
- 姓名 Y：`-35`；
- F-Name 右侧姓名牌相对左侧横移：`+456`。

所以已经废弃“姓名占正文左侧 96 像素列”的旧设计；正文无论是否有姓名都保留完整原版宽度。

## 4. NPC 多对话后打开崩溃：本版处理

### 4.1 已确认的危险点

旧 0.3 在历史条目有姓名时，会读取：

`0x46F658 -> F-Name object`

然后只用“地址数值处于普通 32 位用户地址范围”判断对象是否可用，接着直接：

- 读取 `object+0` / `object+4` 坐标；
- 把对象交给 `0x407510` 绘制。

这不足以证明对象仍存活。NPC 切换、场景资源回收后，旧地址可能仍然落在一张 `MEM_COMMIT` 堆页中，甚至地址数值完全正常，但小块对象本身已经析构或回收。

### 4.2 原版 SF2 对象生命周期证据

原版 `0x403C60` 切换说话人时会处理旧人物资源和旧 F-Name；F-Name 相关机器码包括：

- `0x403CFC`：读取 `0x46F658`；
- `0x403D08`：调用 `0x4070A0` 析构 SF2 对象；
- `0x403D0E`：调用释放函数；
- `0x403DB3`：为新的 F-Name 分配 `0x84` 字节对象；
- `0x403DD2`：调用 `0x407080` 初始化；
- `0x403DF4`：新对象写回 `0x46F658`；
- `0x403DF9`：调用 `0x4070D0` 加载/建立 SF2 内部字段。

`0x407080 / 0x4070D0 / 0x4070A0` 进一步确认：

- `object+0x30`：SF2 数据基址；
- `object+0x34`：正常加载后与 `+0x30` 指向同一资源；
- `object+0x48`：当前 frame 描述；
- `0x407510` 入口马上读取 `object+0x48`，随后读取 `frame+0x54`；
- `0x4070A0` 析构时会把 `object+0x30` 和 `object+0x34` 清零。

### 4.3 本版安全门

新增 `Runtime_MemoryRangeReadable()`：使用 `VirtualQuery` 检查完整地址范围是否：

- `MEM_COMMIT`；
- 非 `PAGE_GUARD`；
- 非 `PAGE_NOACCESS`；
- 访问属性确实允许读取。

此外 F-Name 不能只靠 VirtualQuery，因为已经 free 的堆小块所在页面仍可能保持 MEM_COMMIT。因此 `backlog_name_panel_object_usable()` 还验证：

1. F-Name 对象完整 `0x84` 字节可读；
2. `+0x30` 非空；
3. `+0x30 == +0x34`；
4. SF2 资源头可读；
5. `+0x48` 当前 frame 至少到 `+0x54` 可读；
6. frame 地址不在 SF2 基址之前。

只有全部成立才调用 F-Name 绘制链。

如果失败：

- 本帧仍画历史姓名文字；
- 不画 F-Name 姓名牌；
- 只记录一次安全降级日志；
- 不调用 `0x403C60`，不重建人物资源。

这让最后一份仍活着的 F-Name 可以继续复用，同时对已析构/明显损坏的对象 fail-safe。

### 4.4 其它同时加固

- 捕获姓名前验证完整 64 字节姓名源范围；
- 捕获正文前验证完整页面正文范围，不再只检查首尾地址数值；
- 播放历史前强制 `length` 必须为 `1..511`；
- F-Talk 对象在 BACKLOG 状态下至少验证前 8 字节可读后才读取坐标；
- Movie 对象读取 `+0x0A` 前验证整段范围；
- UI owner 的存在判断由“地址看起来正常”升级为至少 1 字节真实可读。

## 5. 明确禁止恢复的失败方案

### 5.1 失败：无姓名框 + 96 像素姓名列

旧方案把姓名与正文画在同一 Y，再把正文向右移动 96 像素。

后果：

- 长句提前 96 像素撞到右边界；
- 姓名和原版姓名牌位置不一致；
- 与原版 `0x404800` 布局证据相反。

不得恢复。

### 5.2 失败：浏览每条历史时重新调用 0x403C60

这样虽然容易让原版重新建立 F-Name，但会同时建立人物 `%d-2.SF2`，历史跨人物切换时曾实机出现 SAF `FrameID >= TotalFrameNumber` 越界/崩溃。

本版继续保持 BACKLOG 展示时：

`GLOBAL_DIALOGUE_SPEAKER_ACTIVE = 0`

只画姓名文字和安全可用的 F-Name，不重建人物动画。

### 5.3 放弃：BACKLOG 自己的 SDL 手柄

旧源码自己加载 SDL3、自己打开手柄、自己维护按钮状态。现在正式放弃：

- `sdl_input.c/h` 删除；
- 构建不再包含 SDL；
- BACKLOG 单独安装时无手柄支持。

这样手柄模式、按键语义、鼠标模式都只有 `Castle_PadSupport.asi` 一套状态源。

### 5.4 失败风险：拿 F-Talk 的前置 draw wrapper 画 F-Name

`0x40486E` 与 `0x404899` 是不同 CALL。即使原始目标都为 `0x407510`，其它插件可能只 Hook 其中一处。

本版分别取得两条当前链目标，不再混用。

- `Enabled=1`：总开关。

- `RepeatDelayMs=350`：方向键长按第一次重复等待时间。
- `RepeatIntervalMs=100`：开始重复后的间隔。

### 6.2 `[Keyboard]`

值使用 Virtual-Key 名称但省略 `VK_`：

```ini
Open=B
Exit=B
Up=UP
Down=DOWN
Left=LEFT
Right=RIGHT
```

支持：

- 单个 `A..Z` / `0..9`；
- `F1..F24`；
- `NUMPAD0..NUMPAD9`；
- 常见 `UP/DOWN/LEFT/RIGHT/RETURN/ESCAPE/SPACE/PAGEUP/...`；
- 为旧配置保留十进制/`0xXX` 兼容，但新 INI 不再推荐。

## 7. 鼠标输入

新文件 `mouse_input.c/h` 不装全局低级 Hook，而是链式替换 RPG.exe 当前前台窗口的 WndProc：

- `WM_MOUSEWHEEL`：累计滚轮方向；
- `WM_RBUTTONDOWN`：累计右键按下沿。

语义：

- BACKLOG 未打开：滚轮向上打开；
- 已打开：滚轮向上 = 更旧；滚轮向下 = 更新；
- 已打开：右键退出。

BACKLOG 已打开时滚轮和右键消息被消费，不继续传到底层 UI；关闭状态下滚轮仍继续传给原窗口过程。

如果窗口稍后才建立/成为前台，worker 会约每 0.5 秒重试安装。

## 8. PadSupport 协作

### 8.1 原则

BACKLOG 不加载 SDL，也不 Poll 手柄。只在已加载 `Castle_PadSupport.asi` 时尝试读取它已经维护好的状态。

### 8.2 当前 PadSupport 没有公开导出

当前手柄插件没有公开 DLL export，因此桥接按以下顺序：

1. 先 `GetProcAddress` 查询 `PadInput_Down` 和 `ControlModes_BlocksMapMovement`；未来插件若增加正式导出会自动使用。
2. 无导出时，只扫描 PadSupport 可执行 section，要求两个只读函数的机器码模式全模块唯一。
3. 任一接口无法唯一识别，BACKLOG 手柄协作完全关闭；键鼠不受影响。

桥接不写 PadSupport 内存、不 Poll SDL、不修改 consumed mask。

### 8.3 当前按钮协议

现行 PadSupport `PadButton`：

- South = 0；
- East = 1；
- LB = 9；
- D-Pad Up/Down/Left/Right = 11/12/13/14。

BACKLOG：

- LB：打开；
- LB：退出；
- PadSupport 当前“取消”物理键：退出；
- D-Pad：浏览。

取消键读取 `Castle_PadSupport.ini`：

- `SwapConfirmCancel=0`：East/B 为取消；
- `SwapConfirmCancel=1`：South/A 为取消。

### 8.4 调查/鼠标模式屏蔽

调用 PadSupport 自己的 `ControlModes_BlocksMapMovement()`：

- 普通 Controller 模式返回 0：允许 BACKLOG 手柄输入；
- 调查模式、RT 临时鼠标、Back 常驻鼠标等非 Controller 模式返回非零：BACKLOG 完全忽略手柄输入。

另外有 release barrier：从屏蔽模式返回普通模式后，LB/取消/D-Pad 必须全部松开一次，防止模式中一直按住的按钮在返回第一帧误打开/滚动 BACKLOG。

本轮已经遍历包内全部 Markdown；没有发现其它文档依赖该错误计时接口。

## v0.3.4-test1 当前完整接档

### 用户实机结论与根因

`v0.3.3-test4` 已被实机否定：

1. 真实剧情中打开后无显示。源码在 `g_active && g_opened_over_live_dialogue` 时直接跳过前一层
   `0x40B150`；但 `0x40B16B～0x40B173` 会调用 `0x434500(scene_world,0xBB8)` 登记本帧绘制对象。
   登记被跳过后 `0x40B050/0x404800` 无入口，五个绘制 Hook 自然全部不执行。
2. 剧情结束后打开必崩。`NamePanelPool_Create()` 用裸 `"F-Name.SF2"` C 字符串调用 `0x4070D0`；
   原版 `0x403DA4～0x403DF9` 先以 `0x451A73` 构造游戏字符串对象，再把对象地址传给 `0x4070D0`。
   参数 ABI 不同，资源加载器会把字符串正文误读为对象字段。

### 当前成功方案

- 删除 `name_panel_pool.c/.h`、构建对象和全部运行时调用；Backlog 不创建、不析构任何 SF2。
- 活动态不调用完整 `0x40B150`，只以 stdcall 调用 `0x434500(scene_world,0xBB8)`；逻辑冻结但绘制登记保留。
- F-Talk 继续使用 `0x40486E` 已传入的原版对象。
- 有姓名记录使用 `0x46F658` 最后一只原版 F-Name；绘制前验证对象 0x84 字节、`+0x30/+0x34`
  同一资源、资源头和 `+0x48` 当前 frame 至 `+0x54` 全部可读。
- 历史姓名调用 `0x4048E6` 安装前的姓名文字链；正文调用 `0x4049FF` 安装前的正文链。
- 人物图只在 `0x404859` 跳过；不改人物对象、不调用 `0x403C60`。
- 真实剧情打开时只暂存并替换 `mode=BACKLOG_READ_ONLY_MODE`，让绘制路径内的 `0x403E30` 不推进消息；
  关闭时恢复 mode。其它真实剧情字段不改。
- 自由探索仍建立 synthetic message，但活动期同样只登记 draw，不运行 Event/地图逻辑。

### 永久失败方案

- 私建 F-Name/SF2：ABI 已直接证明错误，禁止恢复。
- 整段 return 冻结 SceneWorld：会连绘制队列登记一起删除，禁止恢复。
- 只画 F-Talk 再手拼姓名列：用户已否定，文字位置不符合原版有姓名布局。
- 倒历史时调用 `0x403C60`：会重建人物 `%d-2.SF2`，历史上已触发 FrameID 越界。

### 本轮踩坑与机械护栏

- `0x434500` 虽由 `0x40B150` 以 ECX=self 调用，但函数体不读取 ECX，并 `ret 8`；现行 typedef 使用
  `__stdcall(object,key)`，不能误写 cdecl/thiscall。
- `0x4070D0` 的第一个显式参数是游戏字符串对象地址，不是 `const char*`。
- 检查器新增 `0x434500` 入口签名、无 NamePanelPool/0x4070D0、活动态含 draw register、旧 return 不存在。

### v0.3.4-test2 多条目崩溃补充

### v0.3.4-test3 自适应布局补充

截图证明完整原版大对话框即使在安全步长 110 下，四条仍然过于拥挤；用户设置 135 没效果是因为
