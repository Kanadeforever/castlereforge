# 架构与实现说明

## 设计目标

本插件把 VN 常见 Backlog 做成《幽城幻剑录》的独立 QOL 能力，同时遵守三条边界：游戏对话框自己画、剧情状态完整恢复、手柄/宽屏插件仍能按原架构工作。

## 模块

```text
plugin.c
  └─ 生命周期与 8ms worker
      ├─ runtime.c：路径、INI、日志、前台门、机器协议预检
      ├─ sdl_input.c：可选 SDL3 动态加载与标准按钮采样
      └─ backlog.c：游戏线程捕获、历史环、浏览、原版 UI 回放、恢复
```

`game_addresses.h` 只放已闭合地址；`platform.h` 只放 Win32/x86 类型和调用约定。业务模块不各自复制魔法地址。

## 线程边界

worker 只读键盘/SDL 和少量只读状态门，用原子计数提交动作。它不复制正文、不调用游戏函数、不加载人物资源。

场景 vtable[0] 包装器运行在游戏线程。它捕获页面、消费动作、切换显示指针，再调用安装前的场景更新函数。若其它插件已经替换 vtable[0]，Backlog 保存其当前指针并按 thiscall 链式调用。现代浏览明确禁止调用 `0x403C60`，避免跨人物 SAF/SF2 的 FrameID 越界。

## 历史环

每条固定保存：页长度、speaker/style/variant、最多 64 字节的原版 NameList 姓名和 512 字节原始页。静态最大 256，INI 有效范围 16～256，默认 128。`head` 指向下一写槽；`offset=0` 永远换算为最新。

没有动态堆分配，避免老游戏内存分配器、CRT 和卸载生命周期不一致。加入姓名快照后，256 条的虚拟数据区约 146 KiB，但 ASI 文件中零区不会按同大小实写。

## 导航

- 上：`offset+1`，到最旧再按回到 0；
- 下：`offset-1`，在 0 再按跳到 `count-1`；
- 左：增加 `PageSize`，越界夹到最旧；
- 右：减少 `PageSize`，越界夹到最新；
- 方向支持延迟与间隔可配的按住重复；
- 退出为单次按下沿，不重复。

## 现代整屏 UI 回放

正文不转成 Unicode，也不由插件重新分行。历史 CP950/控制码被复制到插件缓冲，`0x46F664` 只在查看期间指向它。

原版 `0x404800` 仍是消息层入口，但两个内部 CALL 被窄包装：

- `0x40486E -> 0x407510`：同一个 `F-Talk.SF2` 对象临时改变 Y 坐标，最多在 640×480 中从上到下画四次；
- `0x4049FF -> 0x402EE0`：复用原字体对象、表面、裁剪和颜色，逐条在左侧姓名列与右侧正文列绘制。

当前滚动锚点位于最下方，更旧三条向上排列；记录不足四条时仍向底部对齐。默认 `PageSize=4`，正好整屏跳转。

现代模式不显示任何人物图。查看期间只把 `0x46F675` 临时设 0；已经加载的当前剧情人物对象、`%d-2.SF2`、F-Name 对象和姓名指针均不释放、不重建。姓名来自捕获时复制的 NameList 原文字节。

## 暂停与恢复

查看期间不冻结系统时钟或渲染。只使用原版消息/事件已经存在的模态门：Event yield/block=1、地图输入 gate=0、消息 mode=无效、target/current=4。

关闭采用两阶段：先把消息 ID 清零一段场景更新间隔，随后直接恢复原人物显示标志、姓名指针和全部快照，不进行资源重载。这同时保护手柄插件的普通对话 A pending，也修复旧版人物 FrameID 报错。

## 宽屏兼容

不修改宽屏检查的 `0x40B087/0x40B08C`、`0x403E30/0x404800` 入口和 `vtable[1]=0x40B050`。新增 Hook 只位于 `0x404800` 内部两个未经宽屏占用的绘制 CALL。自由地图查看时消息 ID 用临时非零值，使宽屏提前走“消息只画中央一次”的既有路径。退出屏障期间 ID 为 0，但宽屏侧画会把 target/current 临时清零，仍不会重复画消息 UI。

## 失败关闭

启动必须通过：固定基址、PE32 i386、场景/消息/说话人入口、F-Talk CALL、正文 CALL 和 vtable[1]。任一绘制 Hook 安装失败会恢复此前已装的窄 CALL，不启用 Backlog。SDL 缺失不属于失败，只关闭手柄能力。
