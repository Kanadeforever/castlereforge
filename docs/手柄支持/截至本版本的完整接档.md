## 13. 地图 Y 入口三轮纠错

### 13.1 r17：特殊休整三项动作——FAIL

历史对象：

- Update `0x413850`；
- 第0项 `0x413933 -> 0x431380`；
- 后续确实存在 prepare/alloc/`0x434920` Interface ctor。

它属于**休整/特殊地图三项动作菜单**，第0项“調態”，不是普通探索通用菜单键入口。用户 r17 实测普通地图 Y 完全无法打开菜单。

### 13.2 r18：`0x40CC73 -> 0x406F20` 门控——仍 FAIL

r18 尝试在普通探索状态机中只叠加这一次门控返回，不写 state、不调 ctor。静态上路径自洽，但用户实机仍无法用 Y 打开菜单，而且没有命中 Y 入口日志。

因此 `0x40CC73` 只能作为状态机研究证据，不能继续标为“普通地图已确认菜单键入口”。

### 13.3 r19：直接复用原版 Space 后面的业务事件

用户提出：**可以取巧复用地图 Space 的事件，但不要发送 Space 按键。**

重新反汇编 `0x44A4D0`：

```text
0x44A4DF  cmp eax,0x20
0x44A4E2  jne 0x44A583
0x44A4E8  cmp [0x89F808],0
0x44A4EE  jne 0x44A583
0x44A4F4  cmp [0x468BF0],0
0x44A4FA  je 0x44A583
0x44A500  push 1
0x44A502  jmp 0x44A57B
0x44A57B  call 0x40B230
```

所以原版 Space 的业务动作可以明确表示为 `0x40B230(1)`。

`0x40B230` 自己还会重新检查：

- action 非0；
- `0x89F808==0`；
- `0x89F81E==0`；
- 调 `0x40B340`；
- `0x89F820!=0`。

r19 实现：

```text
worker：Y新按下 → map_y_pending=1
Exploration 游戏线程：
  先运行原版 0x408A70
  → InterfaceShell_OnExplorationGameThread()
  → 再检查 Context / 0x89F808 / 0x468BF0
  → Runtime_MapSpaceEventTarget() 取得原版 Space 当前 CALL 目标
  → 以 action=1 调用该目标
```

明确禁止：

- 发送 `VK_SPACE`；
- `PostMessage` Space；
- SendInput/keybd_event；
- worker 直接调用地图业务函数；
- 直接写 `0x89F818`；
- 手工分配/ctor Interface。

r19 还增加分层 Y 日志：捕获、Context变化、busy、mode=0、最终提交各自可见。

主 Interface r20a 协议护栏：**Space 业务特征 + 动态 CALL 目标 + 1/1 短锚点 + 10/10 ButtonEvent CALL**。

## 14. Shell “钝”的两层根因与 r19 缓冲

### 14.1 r17 的严重迟钝：UiBridge pending 被跨模块清理

r17 日志表现为很多“请求”后才偶尔一次 Event 消费。根因是 Battle 非活动分支每8ms全局 `UiBridge_ClearEvent()`，会把 Interface pending 一起删掉。

r18 引入 owner：

```text
pending = button + code + owner
owner = BATTLE / SAVE_SLOT / CONFIRM_DIALOG / INTERFACE
```

用户 r18 日志已证明这层修复有效：Shell 每次请求后都能紧跟对应 `[UI事件] ...已由原版按钮消费`。

### 14.2 r18 仍偏钝：原版动画门 + 插件丢动画期按键

精确原版 `0x436330`：

```text
cmp [ecx+0x590],8
setg al
ret
```

切换大类时原版会把 `+0x590` 置0；直到动画更新超过8才再次允许根导航。

原版门本身就是旧式 UI 的节奏限制。r18 又先检查 ready，再读取手柄新按下沿，所以动画期间按下会直接消失，进一步放大“钝”。

### 14.3 r19：不跳动画，先缓存明确输入

r19 增加最多8项的动作语义队列：

```text
LB/RB/左右/B 新按下
→ 立即保存 ACTION，不保存 Button 指针
→ 原版动画继续
→ +0x590>8
→ 重新按当前对象查真实 Button
→ 通过 UiBridge owner=INTERFACE 提交
```

B 优先：按 B 会清空尚未提交的旧导航动作，只留下退出请求。

这只能消除插件造成的“按了被吃掉”，不会缩短原版动画。如果实机确认提前按键都能被缓存但视觉仍太慢，下一阶段才研究是否安全缩短 Interface 动画。

### 14.4 r19 全局日志抑制

Runtime 使用64槽固定缓存记录完整 UTF-8 日志指纹。同一词条连续2秒内再次出现时不写；每次重复刷新计时，因此持续快速操作时整个连续阶段只保留第一次。多槽可以处理“RB请求/UI消费”这种交替重复。

日志去重只影响文本文件，不参与任何输入业务。

原版 state5 `0x440610` 每帧对 11 个 Button 经过：

- `0x44066E -> 0x431400` 鼠标边沿；
- `0x4406A8 -> 0x431380` ButtonEvent，而 0x431380 内部还会再次 HitTest/维护历史状态。

r23 因此做双层隔离：`InterfaceInnerStats_HookMouseEdge` 在手柄合成焦点模式对本页按钮返回无鼠标边沿；UiBridge 无 pending 时再通过 `InterfaceInnerStats_FilterVisualOnlyButtonEvent` 跳过 0x431380 的视觉鼠标历史维护。手柄真正 ←/→/Y 的 pending code=2 优先消费，不受过滤；实体鼠标/右摇杆接管会立刻撤销两层隔离。

### 27.3 shared 二维邻居算法

新增 `spatial_neighbor.c/.h`，只共享几何算法，不共享 Battle/阵形业务。

每个候选只属于一个主方向扇区：`abs(dx)>=abs(dy)` 归水平，否则归垂直；再按符号区分左右/上下。水平优先最小 |dy| 后 |dx|，垂直优先最小 |dx| 后 |dy|。这从结构上禁止一个候选同时成为“右”和“下”之类的歧义。

1. 只按符号取方向半平面：左 `dx<0`、右 `dx>0`、上 `dy<0`、下 `dy>0`；
2. 左右优先最小 `|dy|`，再最小 `|dx|`；
3. 上下优先最小 `|dx|`，再最小 `|dy|`。
