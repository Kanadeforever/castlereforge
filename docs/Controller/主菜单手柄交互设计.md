## refactor32 冻结：存档点完整子层与客栈原位返回

### 地图存档点完整输入路由

- 前置剧情 mode=3 的“是否存档”仍由 `SceneChoice` 提交；它确认“是”后，地图事件才建立 `0x89FCD0` 独立包装对象。
- `save_point.c` 每帧从 `wrapper+0x580` 取得标准 SaveSlot，只管理 owner、phase 与 `SaveSlot_Begin/Update/End` 配对，不复制存档业务。
- 槽位/分页由共享 `SaveSlot_Update()` 处理；进入 `SaveSlot+0x5A4` 后切到全局共享的三项动作控制器，不再依赖天书 state7 能力是否开启。
- SaveSlot 自己的直接 popup 仍由 `save_slot.c` 处理；三项动作内部 `action+0x5B4` 的二次 Yes/No 则交唯一 `ConfirmDialog_Update()`，A/B 与方向不再失效。
- wrapper 存在时仍阻断旧 SceneChoice 和底层菜单读取**新**按键；`SceneChoice_MaintainPulse()` 只补发此前已经开始的 LEFTUP，避免确认“是”的鼠标脉冲卡在按下态。
- 展开/收起动画期不投递新输入；包装对象消失或内部 SaveSlot 重建时精确配对 `End/Begin`，不持有旧指针。

### 客栈子界面原位返回

- Inn 在 A 点击真实入口前记录来源项：`0=诸态`、`1=炼化`；“歇息”是剧情流程，不套用子菜单返回规则。
- 必须观察到**同一 Inn owner** 先 inactive、后重新 active，才执行恢复；这样不会把普通点击失败或对象重建误判为一次返回。
- 从诸态退出主 Interface 后，逻辑与视觉都回到诸态；从炼化退出后，逻辑与视觉都回到炼化。返回后的第一颗 A 会重新进入原来源项。
- Inn 自己通过 `inn_claim_navigation()` 与专属 HitTest 完成逻辑/视觉同步；Synthesis 不再 include/call Inn，也不锁存“固定首项”。
- 实体鼠标或右摇杆接管时撤销强制返回显示，保留原版 hover；不移动系统鼠标，也不直接写 Button Sprite。

### refactor31 错误方案（历史反例）

refactor31 把用户报告的“逻辑第一项、视觉第二项”理解成“视觉也迁移到逻辑第一项”，因此由炼化子层要求父层固定 `focus=0`。用户明确纠正：应当迁移并保存**进入子界面前的来源项**，而不是把任一侧强制改成第一项。该 API、锁存和 Synthesis→Inn 耦合均已删除。

### 冻结方向规则

全局输入契约继续固定为 `L=上一/左/减`、`R=下一/右/加`。炼化页面内部 native index 与画面方向相反，仍由 Adapter 换算，不反转用户语义。

## refactor29 历史：客栈、炼化与剧情二选一

### 客栈根层

- 三项真实按钮：`0=诸态`、`1=炼化`、`2=歇息`。
- ↑/↓：在三项之间移动焦点；到顶/到底停止，不循环。
- A：只向当前真实 Button 排 `code=2`，由 RPG.exe 执行对应业务。
- B：客栈根层原版没有取消/退出行为，因此**不调用任何 ButtonEvent**；仅消费 B 防止穿透到底层地图/对话。
- “诸态”打开主 Interface 后，后续所有主菜单手柄逻辑继续由已经 PASS 的 Interface 模块接管；客栈模块停止干预。
- “歇息”后的文本、恢复 HP/MP、关闭客栈均为 RPG.exe 业务，本模块不写 HP/MP。

### 炼化第一层

- ↑/↓：当前页物品行；不把其它页面的“到边界自动翻页”强塞进炼化。
- ←/→：上一页/下一页，触发原版翻页 Button。
- LB/RB：六类别循环，点击顶部真实类别 Button。
- A：点击当前行。原版认为合法时展开第二层；插件不直接构造第二层。
- B：**唯一合法根层退出是顶部 `index0`，即“用器”右侧退出图标**。禁止模拟 RMB。

### 炼化第二层

- ↑/↓、←/→、LB/RB：与第一层相同语义，但使用第二层自己的字段/Button。
- A：总是只点击当前真实物品行。可炼化资格由 RPG.exe 自己判断；不可炼化项目不会打开确认框，也不会锁住手柄。
- B：只点击第二层 `+0x63C` 取消 Button（`code=1`），由原版 `0x410AD0` 收起右侧列表；不是根层退出图标，也不是 RMB。
- 可炼化 A 打开的 Yes/No 继续交已有 `ConfirmDialog`，不复制第三套双按钮逻辑。

### 公共剧情 mode=3 两项选择

这类“是 / 否”来自公共消息系统，而不是菜单 Button 类。`0x403E30` 在 mode=3 调 `0x404600`；原版根据鼠标命中区决定第一/第二项，并把 `0x46F678/0x46F679` 写成 10/9 来绘制自身选择框，再检测左键提交。用户补充截图已经确认**选择框本来就存在**，所以本模块只移动隐藏命中坐标，不能额外显示手形作为第二焦点。现行手柄语义：

- ←/↑：第一项“是”；→/↓：第二项“否”；
- A：在当前**原版选择框**对应的隐藏命中位置发送一次短左键；
- B：先定位“否”，再通过同一原版左键路径提交；
- 实体鼠标/右摇杆接管后停止强制隐藏命中坐标，保留原版自由鼠标操作；选择框继续由 RPG.exe 自己根据真实鼠标位置更新。

### state3 治疗法术目标选择

## 1. 总原则

1. 不先做通用 Yes/No / Quantity / VerticalChoice；
