### 7.5 refactor20a：为什么不再硬校验 `0x40B230` 的 0x23 字节函数体

1. `0x44A4DF` 仍具备 `Space -> 0x89F808 busy -> 0x468BF0 mode -> push 1` 特征；
2. Jcc/短跳的相对位移被 mask 忽略；
3. `0x44A57B` 仍是有效 `E8 rel32`；
4. 从这条 CALL 动态解析当前目标，保存为 Y 的实际业务函数；
5. 根动画门与 10 个真正要 Hook 的 ButtonEvent CALL 仍精确匹配。

因此“函数体被兼容补丁改写”不再导致假阴性；“Space 业务链本身消失/变质”仍会 fail-closed。

### 16.3 state5 原版按钮按下/释放两段协议

## 18. refactor26b state5 鼠标历史字段

五内 `0x440610` 每个 Button 同帧先调 `0x431400`、后调 `0x431380`。两者除了返回边沿码，还分别维护 Button 内部鼠标历史：

- `Button+0x28`：`0x431380` 使用的释放历史。

## 19. refactor26c：法宝第二类确认框真实安装链与五内 release 生命周期

### 19.1 法宝/道具 popup 使用第二类 0x4276F0

state2 弃置/分发 popup 的业务由 `InterfaceItems` 管理，但其原版按钮 Update 属于第二类双按钮类。低层必须安装：

```text
VTABLE_CONFIRM2_UPDATE = 0x00460C40 -> 0x004276F0
0x00427800 -> 0x00431310  Yes HitTest
0x00427819 -> 0x00431310  No HitTest
0x0042782E -> 0x00431380  Yes Event
0x0042784F -> 0x00431380  No Event
```

`UiBridge_InstallConfirmDialogHooks()` 负责四个 CALL，但只有 `ConfirmDialog_InstallHooks()` 被 plugin 实际调用时才会执行。refactor21 有该安装调用；refactor25～26b 大重构遗漏，导致 state2 pending 无消费者。refactor26c 恢复调用。

这不改变页面优先级：`ConfirmDialog_FilterHit/Update` 看到 `InterfaceItems_AnyPopupActive()` 或 `InterfaceSkills_AnyPopupActive()` 时直接让路。

### 19.2 state5 active pulse 必须走完 release

原版外层：

```text
0x44066E -> 0x431400 -> 0x440678 -> 0x43E6F0(1)  press动画
下一游戏帧
0x4406A8 -> 0x431380 -> 0x4406B2 -> 0x43E6A0(0)  release/恢复
```

refactor26c 不新增地址、不直接调 `0x43E6A0`，而是保证一旦 synthetic pulse 已开始，即使焦点鼠标视觉被隐藏/指针接管，也继续在原 state5 CALL 现场推进到 `0x431380 code=2`，让 RPG.exe 自己执行 `0x43E6A0(0)`。
