# R43 与调查模式的关系

R43不改变R42自动最近目标、R41双激活方式、R40 LB/RB轮盘、25点probe或震动协议。唯一交界是RT恢复门：

- 自由地图调查中按RT：仍进入临时鼠标；松RT且调查键保持时可恢复调查；
- 普通剧情中按RT：允许进入临时鼠标，但 `free_map=0`，松RT只能回普通手柄；
- 剧情或其它UI出现时，调查本体仍立即结束并使用释放屏障，不能因为“剧情可用RT”而放宽调查地图门。

普通手柄活动自动隐藏接口删除后，调查仍通过 `Cursor_SetInvestigationSession(1)` 明确取得所有权，因此右杆精调、隐藏命中、resolver确认与震动不依赖已删除接口。

# R42 调查模式设计说明

## 1. 自动最近目标

`AutoFocusNearest=1` 时，Investigation会话第一帧复用 `inv_select_shoulder_target(snapshot, 1)`。会话刚清空，没有当前object，因此按R40规则得到距离第0项。它取得SHOULDER焦点锁、启动25点probe，但不直接点击/震动。

`session_started` 只在active从0到1时置1；所以自动分支只运行一次。右杆同tick移动可立即取消，LB/RB和左杆以后正常接管。设为0时整个分支跳过。

## 2. 确定/取消布局

```ini
[Controls]
SwapConfirmCancel=0
```

- 0：南/A确定，东/B取消；
- 1：东/O确定，南/X取消。

InputRouter保留fixed物理表，再在普通语义表中只交换CONFIRM/CANCEL。ControlModes与Investigation通过Raw语义读取，因此调查激活/取消跟随。鼠标模式确定→左键、取消→右键，也跟随。

RB+ABXY必须不跟随：`InputRouter_ChordPressed()`使用fixed表。X/Y专属动作也直接从fixed表返回。

## 3. 与R41组合

ActivationMode=0表示按住“当前确定键”调查、松开确定键互动、当前取消键退出；ActivationMode=1表示按住LT、按当前确定键确认。两种模式进入时都可自动最近。

RT鼠标中的确定/取消仍对应左右键；RT松开恢复调查后是新会话，会再次按AutoFocus开关处理。

## 4. INI保护

用户中文INI不重建。本轮只新增中文Controls段、中文AutoFocus说明，并把R41的A/B字样精确改成“确定键/取消键”。检查器验证中文关键句、三个默认值和英文模板不回归。

## 5. 安全与验收

自动聚焦不绕过resolver；Swap不修改PadInput/Cursor/Battle地址。实机需组合测试2种Swap×2种Activation×2种AutoFocus，并确认鼠标左右键跟随而RB+ABXY不跟随。

# R41 调查模式设计说明（历史，已实机验收通过）

## 1. 用户操作

默认配置：

```ini
[Investigation]
ActivationMode=0
```

自由地图按住A建立调查；保持A时使用R40的左杆方向轮盘、LB/RB距离轮盘和右杆精调；原版确认新hover后短震。在当前目标已经确认时松开A，提交一次互动并退出。按住A时按B，立即取消并锁住A到物理松开。

兼容配置：

```ini
[Investigation]
ActivationMode=1
```

保持R40：按住LT进入，调查中按A确认，松开LT退出。

## 2. 模式所有权

Runtime只读取0/1配置；ControlModes独占模式；Investigation不读取A/LT的Down状态来决定进入。ControlModes通过四个私有函数统一得到当前调查键的按下沿、持续、松开沿和释放屏障状态，因此A/LT不会演化成两套漂移状态机。

普通手柄态的顺序是 Back → RT → 调查。调查态内部顺序是非自由状态中断 → A模式B取消 → RT覆盖 → 调查键松开 → 本帧目标更新。

## 3. A按下与保持

A按下沿只负责进入。`Investigation_UpdateActive()` 中旧 `PadInput_Pressed(PAD_SOUTH)` 被 `activation_mode==1` 包围，所以默认模式不会在进入第一帧误点隐藏鼠标旧hover。

持续按A时ControlModes每tick捕获全部语义并阻断地图移动；Investigation继续R40目标状态机。A不是连发确认键。

## 4. A松开确认

ControlModes必须在会话仍active时先调用 `Investigation_ConfirmCurrentHover()`。函数依次要求：

1. capability已安装且会话active；
2. 游戏在前台；
3. `pending_object==0`；
4. sequence快照完整且新鲜；
5. `hovered_object!=0`。

通过后只排一次48ms左键。ControlModes随后只EndSession，不ResetClicks。未通过仍退出，不建立跨会话pending，避免晚点击。

## 5. B取消锁存

B取消优先于RT与A松开。取消路径调用释放屏障和完整pointer清理：A仍Down时 `confirm_inhibit_until_release=1`。以后即使B松开，只要A未松，屏障不清；普通状态也没有新的A按下沿，所以无法重进。

如果普通手柄态A+B同帧按下，不建立调查。RT鼠标态的B仍是鼠标右键，不进入本取消分支。

## 6. RT覆盖

调查中按RT先结束Investigation对象状态并进入MouseMode。RT期间A/B保持左右键。RT松开时必须同时满足：之前有恢复意图、配置的调查键仍Down、该键未被屏障锁住，才恢复调查。

A模式恢复时，RT退出会临时把仍按着的A视为鼠标残留并设置confirm屏障；既然状态机已明确裁决恢复调查，就必须撤掉这条临时屏障，否则下一tick会把合法A错误当作残留。

## 7. 冻结和测试

R40左杆/LB/RB/右杆、目标增删、约12°肩键交还、resolver震动均不变。PadInput、Cursor、RPG地址和业务UI不改。实机重点是A松开只点一次、pending时不点旧目标、B锁存、RT恢复，以及ActivationMode=1完整兼容。

# R40 调查模式设计说明（历史，已实机验收通过）

版本：v0.3-refactor40  
日期：2026-08-24  
状态：代码候选，待实机验收  
稳定基线：v0.3-refactor39（角色中心连续方向轮盘用户PASS）

## 1. 目标

在自由地图按住 LT 的调查模式中保留 R39 左摇杆连续方向选择，同时增加：

- LB：按稳定列表选择上一个互动目标；
- RB：按稳定列表选择下一个互动目标；
- A：只在原版 resolver 确认 hover 后调查；
- 右摇杆：继续人工精调；
- B：本轮不新增业务。

肩键用于密集目标、小角度目标、角色身边重叠目标或不想使用右杆时的快速枚举，不替代方向轮盘。

## 2. 不变量

1. 唯一调查 Hook 仍是 `0x4098CB -> 0x409B50`；先执行原函数并原样返回。
2. game thread 是唯一游戏对象读取者；worker 只读 sequence 完整的整数快照。
3. 所有候选仍先通过既有对象/距离/frame预筛，最后由原 resolver 确认真实 hover。
4. 25点透明像素probe、pending click、新方向先取消旧probe、48ms左键桥全部保留。
5. LB/RB 不直接点击、不写 RPG.exe 字段、不调用脚本、不在按键沿空震。
6. 原 resolver 确认新的 `hovered_object` 后，LB/RB 目标必须与左杆、右杆、Back/RT鼠标一样沿统一调查hover链短震。
7. 普通隐藏鼠标没有震动资格；`Cursor_ControllerOwnsPointer()` 不能成为震动门。
8. PadInput、Cursor、ControlModes、Back/RT、菜单/Battle/Shop/SaveSlot全部冻结。

## 3. 快照字段

沿用既有 `InvestigationTarget`，只增加：

```c
u32 world_distance_squared;
i32 resolver_index;
```

`world_distance_squared` 由 game thread 使用 object/actor `+0x10/+0x14` 计算，并对过大坐标差饱和到 `0xFFFFFFFF`，避免 signed overflow。它只服务肩键顺序，不改变原版 type1..4 `<10000` 与 type>=5 绕过规则。

`resolver_index` 是对象在本次 `scene+0x30` 数组中的原始 index，仅用于完全同距同角度的稳定 tie-break。

不保存 `resolver_confirmed`。确认状态是瞬时真值，只能读取最新 `snapshot.hovered_object`。

## 4. 排序

每颗 LB/RB 新按沿从最新快照重建最多96项的临时索引表：

1. 角色世界距离平方小的在前；
2. 距离相同，以角色屏幕位置为中心，从右侧0°起按屏幕坐标顺时针排序：右→下→左→上；
3. 仍相同时按 `resolver_index`。

实现只使用 `u32/i32`、半平面、叉积和插入排序。禁止 `float`、`atan2`、`sqrt`、`qsort` 和任何数学/CRT依赖。

## 5. 循环规则

- RB：当前 index + 1，越过末项回到0；
- LB：当前 index - 1，小于0回到末项；
- 没有当前对象时：RB选择第0项（最近），LB选择末项（最远）；
- 左杆已有对象时：第一颗肩键从该 object 的最新排序位置继续；
- 肩键已有对象时：后续肩键从该 object 继续；
- 右杆 manual override 后存在真实 resolver hover 时：第一颗肩键从该 hover 继续；
- 普通隐藏鼠标 hover 不构成“当前对象”，不得改变首颗RB/LB的最近/最远规则。

长期状态只保存 object 身份，不保存排序数组下标。每次快照重排都按 object 重新映射；当前 object 消失时清除肩键身份和对应 pending probe。

## 6. 焦点所有权

```c
typedef enum InvestigationFocusSource {
    INVESTIGATION_FOCUS_NONE,
    INVESTIGATION_FOCUS_LEFT_STICK,
    INVESTIGATION_FOCUS_SHOULDER
} InvestigationFocusSource;
```

肩键按下后进入 `SHOULDER`，残留左杆不能在下一tick抢回。

- 按肩键时左杆已回中：保持肩键所有权，可连续LB/RB；下一次推离死区立即交还左杆。
- 按肩键时左杆偏置：物理回中，或相对按键时方向明显变化约12°，交还左杆。
- 约12°使用缩小轴的 dot/cross 与 `sin²(12°)≈43/1000` 比较；`dot<=0`直接视为明显转向。
- 右杆本tick实际移动时继续优先，取消自动pending并进入既有manual override；同tick肩键不抢右杆。
- LB与RB同帧一起按下视为无方向，不按读取顺序随机选择。

## 7. ApplyTarget、点击与震动

肩键应用目标的顺序固定为：

```text
保存新object身份
→ 清失败记忆/人工override
→ 记录当前左杆方向
→ 取消旧pending_object/pending_click
→ 若尚未真实hover，则inv_begin_probe(target, 0)
→ 每个新resolver快照推进下一候选像素
→ 原resolver确认hover
→ Investigation_UpdateRumble短震
→ 若A已排队，提交一次Cursor_PulseLeftClick
```

LB/RB 不新增 `PadInput_Rumble()` 调用。震动来自原 resolver 真值变化，因此既不会漏掉确认成功的肩键目标，也不会在空列表、透明失败或未确认时空震。同一个未离开的 hover 不会每8ms重复震动。

## 8. 原版依据

固化68与当前项目文档共同确认：

- `0x4098CB` 调用 `0x409B50`；
- scene `+0x1C/+0x20/+0x2C/+0x30`；
- object/actor `+0x10/+0x14` 参与原版距离链；
- `record+0x73` 非零进入互动候选；
- type1..4 原版距离门为平方距离 `<10000`，type>=5绕过；
- collision `+0x48` 与 frame `+0x54` 参与像素命中边界。

R40 不把排序结果升级成业务真值；原版 `0x409B50` 仍是唯一裁判。

## 9. 实机重点

- 单目标、多目标、同距、重叠、背后、远目标与动态增删；
- RB近→远、LB严格反向及首尾回绕；
- 首颗肩键不受隐藏鼠标位置影响；
- 残留左杆不抢回，回中/约12°交还自然；
- 右杆优先和右杆hover后肩键接续；
- 25点失败、pending A、快速换目标无旧点击；
- 每个新resolver hover有短震，空按键/未确认无震动；
- R39、R38、Back/RT、普通隐藏鼠标、菜单和Battle回归。

机器检查和编译结果不能替代上述实机验收。
