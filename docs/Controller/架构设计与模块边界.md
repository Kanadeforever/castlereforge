# refactor44 SaveAction模块边界

```text
外部插件/游戏本体
  只改原版Button enabled/disabled
              ↓
SaveAction::Update游戏线程
  现有Hit/Event Hook扫描三只Button
              ↓
  单个u32发布：VALID | 低三位mask
              ↓
SaveSlot worker
  归一化焦点 → 上下跳过 → 确认排队
              ↓
现有Event Hook再次扫描并复核
              ↓
RPG.exe原版存档/读档/取消业务
```

边界：

- `save_slot.c`独占三项窗口手柄导航；外部存档插件独占存档策略；
- 游戏线程只发布纯整数，不把Button指针跨线程保存进新状态；
- worker不判断插件来源、槽号或存档业务，只解释已发布mask；
- mask的最高位与低三位一次写入，避免valid/mask半更新；
- 无可用项时关闭强制HitTest，鼠标仍走原版；
- Event消费仍要求mask允许、目标Button身份一致且原版条件再次通过。

# refactor41 模块边界（历史，已实机验收通过）

R41 把“调查如何激活”从固定LT改为配置化，但仍坚持单一所有者：`ControlModes` 是唯一模式裁决者，`Investigation` 只处理已经获准的目标选择与确认，`Runtime` 只提供经过裁剪的配置值。

### Runtime 配置边界

`RuntimeConfig.investigation_activation_mode` 只可能为0或1。Runtime从 `[Investigation] ActivationMode` 读取，默认0并夹取；它不读取A/LT，也不知道当前模式是否active。

### ControlModes 输入翻译边界

四个私有辅助函数把当前配置键翻译为 pressed/down/released/inhibited。所有进入、退出、RT恢复和释放屏障必须只使用这些语义值；禁止重新散落 `lt_pressed/lt_down` 或建立一套平行A状态机。

A模式调查内部优先级固定为：UI/非自由状态中断 → B取消 → RT覆盖 → A松开确认 → 普通调查更新。B必须先于A松开，避免同帧取消/松开时误点；B也先于RT，避免取消键被提前解释为RT鼠标右键。

### Investigation 确认边界

默认A模式的按下沿只建立模式，不能点击。松开沿由ControlModes调用 `Investigation_ConfirmCurrentHover()`；该函数只在 active、前台、无pending、新鲜快照、真实hover五门全部通过时排一次左键。LT兼容模式的旧A按下确认仍在 `Investigation_UpdateActive()`，并由 `activation_mode==1` 硬门隔离。

### 取消和点击生命周期

- B取消：调用完整会话清理和 `Cursor_ResetClicks()`，并武装confirm/cancel释放屏障；
- A松开成功：先排左键，再只调用 `Investigation_EndSession()`，不能ResetClicks；
- UI/实体鼠标接管：继续使用既有释放屏障和无震动清理；
- RT鼠标中A/B仍是左右键，不属于调查取消层。

### 独立包边界

顶层 `docs/Controller` 是权威文档；构建输出统一到仓库根 `build\`（仅 ASI + INI，不再向输出目录复制文档）。源码位于 `src/Controller/source`；检查器位于 `src/Controller/tools/refactor_check.py`。

# refactor40 模块边界（历史，已实机验收通过）

R40 仍只修改 `Investigation`。`PadInput` 继续只提供物理 LB/RB 按下沿和 SDL3 状态；`Cursor` 继续只提供坐标、warp、显隐与可靠点击桥；`ControlModes` 继续独占 Back/RT/LT 模式优先级。肩键循环不进入这三个冻结模块，也不新增 RPG.exe Hook。

### 快照扩展边界

- producer 仍是 `0x409B50` resolver 所在 game thread；在既有目标快照中追加 `world_distance_squared` 和 `resolver_index`；
- consumer 仍是 8ms worker，只读完整 sequence 快照和整数值；
- `world_distance_squared` 只服务 LB/RB 排序，不替代原版 type1..4 `<10000` / type>=5 资格门；
- 排序表只在每颗肩键新按沿的 worker 栈上临时建立，长期状态只保存 object 数值身份，不保存游戏指针或易漂移数组下标。

### LB/RB 稳定顺序

排序严格为：世界距离平方升序 → 同距时以角色右侧为 0°的屏幕顺时针角度 → resolver index。实现使用饱和 `u32` 距离、半平面、叉积与插入排序；禁止 `float/atan2/sqrt/qsort`。RB 向后循环，LB 向前循环；无当前对象时分别从首项/末项开始。

### 焦点所有权

- `LEFT_STICK`：R39 已验收的角色中心连续方向轮盘；
- `SHOULDER`：LB/RB 明确选中的对象，残留左杆不得下一帧抢回；
- `NONE`：会话刚开始、右杆人工精调或肩键对象消失。

肩键按下时若左杆已回中，保持肩键所有权直到下一次推杆；若左杆当时偏置，则物理回中或相对该方向变化约 12°后交还。12°比较使用缩小轴的 dot/cross 与 `sin²≈43/1000`，不引入浮点。

### probe 与震动边界

LB/RB `ApplyTarget` 只取消旧 pending、保存新 object 并调用既有 `inv_begin_probe()`。25 点全部失败前不直接点击；原 resolver 真正确认新的 `hovered_object` 后，既有 `Investigation_UpdateRumble()` 必须短震，随后 A 才可提交。肩键按下沿本身不空震；普通隐藏鼠标仍无震动资格。

# refactor39 模块边界（历史，已实机验收通过）

`ControlModes`、`Cursor`、`PadInput` 的职责完全不变。本轮只修改 `Investigation` 内部“左杆方向 -> 目标”的几何基准与评分算法：game thread 在 resolver 快照中发布当前角色的两个整数屏幕坐标；worker 读取它们作为轮盘中心。`Investigation` 仍不解释 LT/RT 优先级、不写 RPG.exe 业务字段、不绕过原 resolver。

### 角色中心快照边界

- producer：resolver 所在游戏线程读取 `actor+0x10/+0x14` 和 camera，写入 `wheel_origin_x/y`；
- consumer：8ms worker 只读取完整快照中的整数，不保存 actor、scene、collision 等游戏指针；
- 目标矩形和角色中心使用同一 640×480/camera 坐标系；
- 鼠标 warp 只改变 `Cursor` 的实际指针位置，不再改变 LT 左杆轮盘中心。

### refactor39 方向选择边界

只保留前方半平面 `dot>0`，删除 R38 的 ±63.4°硬 cone；用 `cross²/distance²` 选择最贴近摇杆方向的目标，距离只作同角度 tie-break；轻迟滞只用于边界防抖。`left_selected_object`、25 点失败记忆、右杆 manual override 和“新方向先裁决、旧 probe 后推进”顺序继续属于 Investigation 私有状态机。

### R38 震动边界（用户 PASS，冻结）

`Investigation_UpdateRumble()` 只在 `Cursor_MouseModeActive()` 或 `Cursor_InvestigationSessionActive()` 时把 resolver hover 转成短震；普通隐藏鼠标静默。`Cursor_ControllerOwnsPointer()` 不能成为震动资格。真正回到普通手柄模式的高优先级反馈继续由 `ControlModes` 独占。

## refactor35 架构边界补充（历史）

### 主体能力与增强能力必须解耦

Shop 主体沿用 refactor33 已实机覆盖全店型的 `GLOBAL_SHOP_UI owner + SHOP_ACTIVE` 生命周期、4 个原版锚点与 11 个 ButtonEvent。顶栏、当前列与数量窗仍在各自动作点做指针验证；失败只放弃本次动作。Y 信息窗依赖的 Update、close Event 和两处 transition 属于增强能力，拥有独立预检、独立安装结果和 `item_info_enabled`，绝不能反向写 `g_shop.enabled=0`。

## refactor34 架构边界补充（历史；硬门已否决）

### Shop 行 `code=1` 的两段式边界

原版没有独立的“只选中行”Event：同一个 `code=1` 先更新行/说明/交易侧，再打开道具信息。插件仍不得直接写原版 row，因此采用最窄拦截：worker 给合成行事件附加私有 intent，游戏线程的两个信息 transition CALL 只在 `NAVIGATION` 时跳过最后一步；`ITEM_INFO` 和真实鼠标都调用原版。intent 若未被消费会在 pending 消失后的下一 tick 清理，pointer takeover/session end 也清理，不能污染后续鼠标右键。

### 信息窗与数量窗的模态顺序

Shop 每 tick 深度固定为：道具信息 `mode!=0` → 数量窗 active → 双列根层。信息窗存在时只读 Y；数量窗存在时只读其 LT/RT/左右/A/B；根层才读 X/Y/类别/分页/上下/A/B。由此不会再出现信息窗盖着数量窗而下层仍响应手柄。

### 公共 Cursor 的私有所有权

列标题手形是 Shop 主动提供的视觉，因此 Shop 用 `marker_visible` 记录自己是否真正显示过它。数量窗改用隐藏命中点；session end 和 pointer takeover 仅在该位为真时 Hide。这个边界避免 refactor33 新增 Shop worker 在偶发错误生命周期下撤销或制造天书等其它模块的公共手形。

### 活动对象形状门（失败方案）

refactor34 曾要求活动 Shop 同时满足主类 vtable `0x460810`、根 active 和五个固定子对象。用户实机证明这会让所有商店在读键前失败；refactor35 已删除该全局形状门，仅保留动作点局部指针验证与 Shop 私有手形所有权。天书/SaveSlot/Cursor 仍保持冻结。

## refactor33 架构边界补充（历史，已验收）

### `exploration.c`：输入来源与移动业务分离

十字键和左摇杆最终都只缓存原版八方向码，真正消费仍发生在既有游戏线程 Hook。新增 `g_move_force_walk` 只说明“当前方向来自十字键”，不保存速度；走/跑变化继续请求原版 `0x52`。InputRouter 掌握 D-Pad 语义，Exploration Adapter 只做八方向组合和来源优先级。

- 数量窗高于根层；Shop 活动时模态消费菜单动作；Start/R3/Back 仍留给系统/鼠标层；
- pointer takeover 只撤掉 Shop 私有视觉和自己的 pending，不能清其它 owner 事件。

## refactor32 架构边界补充（冻结）

### “共享业务类”与“共享 owner”必须分开

标题、天书、地图存档点都会创建 `0x4245B0` 标准 SaveSlot，所以它们共享 `save_slot.c` 的槽位、分页、A/B、直接确认弹窗和视觉同步；`SaveSlot+0x5A4` 三项动作同样是 SaveSlot 子对象能力，不能再由天书 state7 独占安装。但三者的 owner 生命周期仍然不同：

| owner | 活动证据 | 子 SaveSlot | 生命周期 Adapter |
|---|---|---|---|
| 标题 | 标题全局/状态 | 标题路径持有 | `frontend.c` |
| 天书 state7 | 主 Interface state 与 `Interface+0x654` | `Interface+0x654` | `interface_tome.c` |
| 地图存档点 | 全局 `0x89FCD0` wrapper | `wrapper+0x580` | `save_point.c` |

`save_point.c` 是 **owner Adapter**，不是第二套存档业务。它只允许读取 wrapper、子指针和 phase，调用 `SaveSlot_Begin/Update/End`；禁止知道槽位行、页码 Button、refresh、SaveAction 或文件 I/O。`SaveSlot_Update()` 与 SaveAction Hook 在全项目都只有一套实现；动作 Hook 以独立能力签名 fail-closed，不再连坐天书 ctor。

### 模态与销毁顺序

存档点 wrapper 存在时，包括 phase 1/2 动画期，都是高于其它菜单的 modal。总调度必须先执行 `SavePoint_Update()` 处理对象消失时的 `End`，再读取 `SavePoint_Active()`。active 分支只继续调用深层 `ConfirmDialog_Update()` 与无业务输入的 `SceneChoice_MaintainPulse()`；其它 Context 全部阻断。这个顺序既避免悬空 child/同帧穿透，也让 `action+0x5B4` 的真实 Yes/No 得到唯一控制器。

### 父界面保存来源项

“从哪里进入就返回哪里”属于父 Inn 的导航历史，不属于 Synthesis 的退出业务。Inn 在向诸态/炼化真实入口 Button 排入 Event 前保存 `return_focus`，并以同一 owner 的 inactive→active 证明一次完整子界面往返；返回时由 Inn 自己恢复该索引并取得专属 HitTest。Synthesis 不 include/call Inn；两模块都不允许通过鼠标 warp 或 Sprite 私写伪造视觉。refactor31 的固定 `focus=0` child→parent API 仅作历史错误，不再存在。

### L/R 方向继续属于语义层契约

`input_router.h` 定义用户语义而不是游戏内部 index：L 永远是上一/左/减，R 永远是下一/右/加。页面 Adapter 可以换算 native index，但不能改这条契约；炼化已经实机通过并冻结。

## refactor29 新增模块边界

### `inn.c/.h`
只拥有客栈三项根菜单的焦点与一次性 Event owner。没有炼化业务、没有主 Interface 业务、没有 HP/MP 恢复逻辑。鼠标接管时只撤自己的焦点/pending。

### `synthesis.c/.h`
只负责炼化两层“导航语义 -> 真实 ButtonEvent”。不复制道具数据库、不判断炼化公式、不写当前页/当前行/类别字段。根层退出和第二层返回各走不同真实 Button，禁止 RMB 通用化。

### `scene_choice.c/.h`
只负责公共消息引擎 mode=3 二选一。它不属于 `confirm_dialog.c`：前者是消息引擎鼠标矩形协议，后者是 0x4272C0/0x4276F0 双 Button 类。SceneChoice 允许调用 Cursor 的“显示菜单焦点”能力和 Win32 左键脉冲，但不得直接调用剧情结果函数。

### 调度优先级
`ConfirmDialog -> SceneChoice -> Inn -> Synthesis -> DialogueInput`。原因是“歇息”后客栈对象可能短时间仍存活；剧情二选一必须先消费 A/B/方向，避免同一颗键穿透回客栈根按钮。


## refactor28 历史封存（当时现行）架构增量

### state3 治疗目标为什么仍放在 `interface_skills.c`

它不是一个独立系统，而是原版 state3 Update 的后半段：`+0x5FC` 使用确认完成后，原版按技能性质把 `page+0x768` 置 1，随后同一个页面 Update 优先扫描顶部角色 Button。因此最窄、最可定位的边界是：

`InputRouter 统一语义` → `InterfaceSkills 页面专属目标 modal` → `UiBridge owner=INTERFACE` → `RPG.exe 真实 ButtonEvent`

职责划分：

- `interface_skills.c/.h`：只保存目标焦点索引、处理 ←/→/A/B、识别 `+0x768` 生命周期；
- `ui_bridge.c`：只在 `0x43C933` / `0x43C1F7` 原版 CALL 到来时消费一次 owner-aware pending；没有 pending 时原函数照常执行，所以键鼠不变；
- `cursor.c`：只负责把原版手形移动到真实 Button 中心并处理控制器/实体鼠标所有权；
- `interface_shell.c`：只把目标选择视为 modal，阻止根层 B/LB/RB/换角色穿透；
- `runtime.c` / `game_addresses.h`：只保存/验证地址协议，能力不匹配时 state3 单页 fail-closed；
- RPG.exe：仍独占角色 ID 解析、治疗结算、`+0x768` 清理以及鼠标颜色模式。

### 明确不做

- 不把 Battle Target 算法搬来；
- 不新增“通用角色 Target Manager”；
- 不写 `+0x58C/+0x588/+0x788/+0x78C`；
- 不自己调用治疗结算函数；
- 不为了新状态修改已经 PASS 的 state7/state8 业务 Event。



`InterfaceEquipment` 只拥有 X、↑/↓、A 与本页分页握手；左右/LB/RB/B 回落 Shell，LT/RT 明确吞掉。它只排真实 ButtonEvent，不拥有装备数据事务。

## 14. refactor22 state5 边界

`InterfaceInnerStats` 拥有 X、Y、←/→；B、LB/RB 回落 Shell。五内逻辑焦点是插件私有状态，Cursor 只负责把原版鼠标 icon 显示到当前节点，不成为业务真值。实体鼠标/右摇杆接管优先。

## 15. Battle confirm watchdog 边界

watchdog 只解决“原版拒绝后插件等待事务永不退出”。它不得跳过有效动作的原版视觉门，也不得自己判技能规则。建立前能从 Button 状态判禁用就立即拒绝；建立后只在 Event 已消费且经过最小握手仍未离开相同 Context 时释放插件自己的 pending/watch/settle。

## 16. PadInput 热插拔边界（refactor22，用户 PASS / 冻结）

`pad_input.c` 是唯一允许直接维护 SDL_Gamepad 句柄的模块。业务层不得自己枚举/打开/关闭手柄。

每 tick 的硬顺序固定为：`SDL_UpdateGamepads -> 旧句柄 connected 检查 -> 必要时关闭 -> 低频 GetGamepads/OpenGamepad -> 本帧采样`。没有手柄句柄时也必须继续 `SDL_UpdateGamepads`，因为插件没有 SDL 事件循环替我们刷新设备列表。

断开只清 PadInput 的物理采样缓存，不清 InputRouter/Battle/Interface 的业务状态；重新连接首帧仅做 `prev=current` 同步，第二帧以后才恢复正常边沿。这样“设备生命周期”与“游戏菜单生命周期”保持正交。

## 17. refactor23 历史架构增量（实机已否决部分）

### 17.1 为什么 shared spatial 可以抽，而万能菜单不能抽

`SpatialNeighbor_Find` 输入只有二维点、当前 ID、方向；输出只有邻居 ID。它不读取 RPG.exe、不发送 ButtonEvent、不知道敌我/阵形/角色，因此是真正稳定的可复用算法。

Battle Target 负责“哪些点合法”；阵形负责“A/B交换与取消”。两者调用同一个几何函数，但不共享业务状态。

### 17.2 五内视觉鼠标所有权

state5 增加一个严格的页面级视觉过滤：当 `controller_focus_visible` 且手柄仍拥有指针，合成鼠标只能显示，不得被 state5 自己的真实 Button 当作鼠标业务。过滤仅覆盖本页 11 Button；实体鼠标/右摇杆接管时自动失效。

### 17.3 state6 Context

`INPUT_CTX_INTERFACE_FORMATION`：A=OVERRIDE，B=MERGE，D-Pad 四方向=OVERRIDE，LB/RB=PASS，X/Y/LT/RT=CONSUME。这样 B 可以在交换事务中被页面吃掉，平时仍由 Shell 返回；大类切换不被阵形重复实现。

## 18. refactor24 历史架构增量（当前以第19节为准）

### 18.1 UiBridge 承担“原版 Button 几何”，不承担页面业务

Button 的屏幕矩形属于跨页面稳定基础设施，因此放进 UiBridge 是合理抽象。它完整复刻 `0x431310` 的父坐标、局部偏移、宽高 override 与 Sprite frame fallback。五内和阵形只调用结果，不各自复制地址链。UiBridge 仍然不知道“烈/神/魔”或“某个阵位能否交换”。

### 18.2 SpatialNeighbor 只共享方向几何

shared 算法改为：先按方向正负取半平面，再以副轴对齐优先选邻居。它仍不读取 RPG.exe、不知道合法目标、不提交 ButtonEvent。r23 的 45°扇区被实机否决，不能恢复。

### 18.3 Battle Target 与 Formation 的输入/数据所有权分开

- Battle 决定合法 target set、side mode、当前 cell、屏幕坐标可用性；
- Formation 决定8阵位、交换 pending 与 A/B 原版事件；
- Formation 的空间点来自 RPG.exe 原版8阵位布局表；Battle 的空间点来自 Target 当前屏幕坐标；
- 两者只把点集送给 `SpatialNeighbor_Find`，不共享任何业务 state。

### 18.4 Formation D-Pad 是硬所有权

state6 活跃时四个方向永远属于 Formation，不允许 PASS 到 Shell。这里采用 fail-closed：即使 Formation Adapter 预检失败/页面对象暂未就绪，也要消费方向，宁可本帧无动作，也不能把 ←/→ 解释成切角色。进入页面时还定向清除 Shell 已排队但尚未提交的角色切换动作，防止跨页面残留。

### 18.5 已通过底层冻结

`pad_input.c/.h` 的热插拔已用户 PASS；state3/state4 源码保持字节级冻结；Battle 不可交互 A 由结构护栏保护。r24 的修复不得借机改这些已经验收的层。

## 19. refactor25 历史输入所有权增量（已由 refactor26 取代）

### state4
`INPUT_SUBTYPE_PREV/NEXT` 在 `INPUT_CTX_INTERFACE_EQUIPMENT` 中从 CONSUME 改为 OVERRIDE，页面 Adapter 将其解释为上一页/下一页；不是全局改变 Trigger 语义。

### state5
`INPUT_NAV_LEFT/RIGHT` 从 OVERRIDE 改为 PASS；`INPUT_SUBTYPE_PREV/NEXT` 从 CONSUME 改为 OVERRIDE。因此：

```text
LT/RT -> InterfaceInnerStats -> 原版五内减/加 ButtonEvent
←/→   -> InterfaceShell      -> 原版角色 ButtonEvent
```

页面不复制角色切换逻辑。Shell 角色范围扩为 state1..5；state6 仍被 Formation Adapter 提前消费并清理旧角色队列。

### 冻结
`battle.c` 与 `pad_input.c/.h` 本轮按用户 PASS SHA 保护，页面键位修改不得触碰。

## 20. refactor26 当前输入所有权

### 20.1 角色切换不再复用 D-Pad 语义

InputRouter 从左摇杆 X 轴生成一个独立的“50%水平单次方向沿”：超过 `16384` 只产生一次 -1/+1，保持推住不重复；只有回到现有摇杆中间死区后才重新武装。InterfaceShell 在 state1～5 读取这个语义并继续提交原版角色 ButtonEvent。

因此角色切换与 `INPUT_NAV_LEFT/RIGHT` 完全解耦。D-Pad 左右可以被页面自由占用而不会与换人冲突；state6 Formation 仍明确禁止左摇杆换人。

### 20.2 页面左右统一分页

- `InterfaceItems`：D-Pad 左右调用既有 `items_request_page()`；LT/RT 仍是6子类。
- `InterfaceSkills`：D-Pad 左右调用既有 `skills_request_page()`；LT/RT 仍是技能子类型。
- `InterfaceEquipment`：D-Pad 左右与 LT/RT 都调用同一 `equipment_request_page()`。

页面只请求原版 Prev/Next ButtonEvent，不复制页码状态、不直接写页码字段。

### 20.3 Five Inner 两阶段按钮脉冲

五内不能再把一次手柄加减简化成单独 `ButtonEvent code=2`。页面 Adapter 保存一个很短的私有 pulse：

```text
phase 1 -> 0x431400 返回2，让原版播放按下反馈
phase 2 -> 等到下一轮原版扫描
phase 3 -> 0x431380 返回2，让原版释放/确认并执行业务
```

UiBridge 在 pulse 生命周期内报告 busy，防止换角色/切大类恰好中断原版按钮的按下/释放配对。500ms 保险丝只丢插件私有 pulse，不触碰已经可能销毁的 Button/Sprite。原版手形鼠标焦点隔离与完整 Button 几何继续保留。

### 20.4 冻结边界

`battle.c` 与 `pad_input.c/.h` 仍按用户 PASS SHA 保护。state3/state4 因用户明确新增输入，不做错误的整文件 SHA 冻结，而保护其已通过业务不变量。

## 21. refactor26a：页面最深弹窗与 Layer 所有权不变量

页面改变某个方向键的 Policy 时，页面内部更深层 popup 必须同步读取该动作实际存在的 Layer。state2 在 refactor26 中把左右改成 `OVERRIDE` 供分页使用，因此其页面专属 Yes/No 也必须从 `OVERLAY` 读取，再由 popup 优先消费。

这不等于“popup 和页面共享业务”：它们只共享物理动作的路由层；popup 仍有独立 focus、A/B 与原版 Event。refactor26a 把这条边界机械写进静态工具，禁止再出现 Policy 与业务读取 Layer 不一致。

## 22. refactor26b：合成鼠标必须维护原版历史状态

五内证明了一个新的架构不变量：**Hook 返回值等价不等于输入状态机等价。**

如果原版输入函数除返回 Event code 外还维护对象内部“上一帧状态”，插件就必须同步这些状态；否则外围业务可能正确，视觉/动画生命周期仍会错误。state5 当前明确要求：

1. 合成 press 同步 `Button+0x2C=2`；
2. 同一按下帧的 release-history 同步 `Button+0x28=2`；
3. 下一帧 release 前 `+0x2C=0`；
4. release 消费时 `+0x28=0`；
5. 纯视觉鼠标帧两份历史都保持0；
6. 只有重新证明 Button 仍属于当前 state5 时才允许写，禁止跨页悬空写。

因此以后任何“模拟原版鼠标/键盘”功能都先检查原函数是否同时维护内部历史，不能再只看返回值。

## 23. refactor26c：低层 Hook 安装与页面业务所有权必须分开

本轮暴露了一个重要边界：**“某个页面自己拥有业务”不等于“该页面必须自己安装所有同构低层 CALL”。**

state2 的 Yes/No 业务仍完全属于 `InterfaceItems`，但它的原版类是第二类 `0x4276F0`，四个低层 Button CALL 复用 `UiBridge_HookButtonHitTest/Event`。因此启动层必须保证 `ConfirmDialog_InstallHooks()` 实际执行，把 CALL 接上线；业务层则继续由页面优先级让通用 ConfirmDialog 静默。

正确分层：

```text
plugin/runtime 安装能力
    -> ConfirmDialog_InstallHooks
        -> 第二类原版4个CALL接 UiBridge

UiBridge 只做一次性返回/HitTest分发

InterfaceItems
    -> popup focus / A / B / D-Pad / 安全默认取消

ConfirmDialog 通用候选层
    -> state2/state3 popup 活动时让路
```

五内同时得到另一个不变量：**视觉所有权不能决定已经开始的业务事务是否继续。** Cursor owner 可以即时变化，但一个已经触发原版 press 的 Button transaction 必须以原版 release 为终点；否则视觉状态机只执行半程。

## Public API 边界

`pad_public_api.c` 位于 `PadInput/InputRouter/ControlModes` 之上，只做只读发布。
第三方只能通过 `CastlePad_GetApi` 取得稳定函数表；内部头文件和状态结构不是 ABI。
v1 不开放输入注入、模式修改、Consume 或震动写接口。
