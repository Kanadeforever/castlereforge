## 二、正式功能

### 槽位

- 0：Quick Save，只允许 F5 或 Controller 快捷保存写入，普通菜单只读；
- 1~90：普通手动存档；
- 91~99：Rolling Auto Save，普通菜单只读；
- 页面从原版 8 页×4 扩展为 25 页×4，编号为 0~99；
- 第一页执行上一页跳到 96~99，最后一页执行下一页跳回 0~3。

### 快捷操作

- F5：Quick Save 到槽 0；
- F9 连按 2 或 3 次：Quick Load 槽 0；
- RB+R3：Controller Quick Save；
- RB+Start：Controller Quick Load 请求；
- 键盘和 Controller 共用同一个 Quick Load 连按状态机。

Quick Save 只允许严格自由行动。原版 save gate 即使在自由行动时仍可能拒绝；当前地图已有冻结安全锚点时，Quick Save 可以复用安全 fallback 写槽 0。对话、战斗、菜单、存档界面、剧情 transient 和切图瞬间仍直接拒绝。

### 自动保存

触发源：

- 真正切换地图；
- `IntervalMinutes` 定时。

第一次观察地图或刚完成 Quick Load 时只建立基准，不立即自动保存。换图或到时时如果当前不安全，任务保持 pending，等新地图建立冻结锚点后再写。

槽位选择：

1. 用游戏 File 对象依次检查 91~99；
2. 有空槽时选择最低编号空槽；
3. 全部存在时读取内存中的环形游标；
4. 原版 SaveSlot 成功后，再用游戏 File 层回读刚写入的槽；
5. 只有回读成功才推进并持久化下一游标。

每次最多改一个 TSF，不做 91→92 的批量重命名。

### `multimedia\save\.NEXTAUTOSLOT`

这是自动轮换元数据，不是 INI 配置，也不是游戏进度：

- 与日志共用同一路径构造器，以 `RPG.exe` 为模块基准追加
  `..\multimedia\save\.NEXTAUTOSLOT`；
- 写入前会创建缺失的 `multimedia\save` 最后一级目录；
- 新路径无有效游标时读取 test6 旧 `exe\Save`，正确写入后删除旧文件但不删除目录；
- 文件名以点开头、没有后缀；代码没有额外设置 Windows Hidden 属性；
- 内容固定为三个 ASCII 字节 `091`~`099`，没有换行；
- 文件不存在、长度不是 3、不是数字或不在 91~99 时，安全回到 91；
- 有空槽时仍优先补最低编号空槽，游标不会覆盖空槽策略；
- 自动存档成功但状态文件写失败时，本次 TSF 仍有效，当前进程继续使用内存游标；下次启动可能回到 91，并在日志中明确报告；
- 第一次成功自动存档前文件可以不存在，这是正常首次运行状态。

INI 中不再允许或生成 `[Internal] NextAutoSlot`，ASI 导入表也不再包含 `WritePrivateProfileStringW`。

### 安全 fallback

旧无条件随时存档会把 `0x40A0C0` 强制改成返回 1，已知会在楼梯/多层 Scene Mode 形成坏档。当前方案：

1. 每张地图只在 default Scene Mode 下采样；
2. 原版 Map Tick 先执行，插件后观察；
3. 连续稳定 8 Tick；
4. 冻结稳定窗口第一个样本作为入口级锚点；
5. 原版禁存但允许扩展时，Writer 期间只临时替换 World 前 `0xC8` 字节；
6. Writer 返回立即恢复实时 World；
7. `0xC8` 后 5000 个 GameVar 不回滚。

用户已在磐沙堡楼梯危险点确认旧 AnytimeSave 的这条安全 fallback 能生成可读 TSF，读档回到入口级安全位置而不是形成坏档。这是沿用的实机正向证据，不代表所有特殊场景已全部验证。

### 保留槽双重写保护

对于槽 0、91~99：

- SaveAction Update 期间临时把“存档”按钮设为原版 disabled；
- Update 返回立即恢复按钮状态，避免 UI 对象生命周期污染；
- 菜单和隐藏命令的 SaveSlot 调用层再次拦截保留槽；
- “读档”和“取消”保持可用；
- owner 的 SaveSlot 字段先解引用成真实 `SaveSlot*`，不再把字段地址误当对象；
- 无 PadSupport 时原版 Hit/Event 自然尊重 disabled；
- 有 PadSupport 时只读取 Public API v1，SaveEnhance 自己维护 index1=读档、index0=取消两项焦点；
- 打开窗口的同一个 A 必须先释放，防止立即执行默认读档；
- PadSupport 进入鼠标/调查模式时，SaveEnhance 取消强制焦点并链回原目标；
- 普通槽的 Hit/Event 完整调用安装前目标，不改变 PadSupport 普通存读档行为。

### 声音

INI 只填写单个外置 WAV 文件名：

- 空、非法路径、不存在、winmm 不可用或播放失败时静默；
- `Volume=0` 静音；
- `Volume=1~99` 读取 WAV 到进程堆，只缩放 PCM 8/16/24/32-bit 或 extensible PCM 的内存副本；
- `Volume=100` 直接交给 Windows 原样播放；
- 不修改磁盘 WAV、游戏音量或 Windows 总音量；
- user32 和 winmm 都是运行时可选动态依赖。

## 五、Castle Mod Loader 生命周期

正确顺序：

```text
LoadLibraryExW(ASI)
  -> DllMain 只记录模块并 DisableThreadLibraryCalls
  -> Loader 完成 Locale/Overrides 处理
  -> GetProcAddress("InitializeASI")
  -> InitializeASI 读取配置、预检查并安装 Hook
```

`DllMain` 内不得恢复 test1/test2 的完整初始化。最终 PE 必须导出 `InitializeASI`，否则构建脚本和静态验证器都拒绝产物。

## 八、历史失败与不得恢复的方案

### test1：过宽预检查

三个不必要的 SaveSlot constructor Hook 增加冲突面，整组布尔日志又无法指出具体失败地址。test2 已删除这些 Hook，改为只读三个 owner 并逐地址诊断。不得恢复。

### test1/test2：Loader Lock 内完整初始化

INI、模块查询、VirtualQuery/VirtualProtect 和机器码安装放在 `DllMain`，用户日志停在配置后，全部功能未安装。test3 改用 `InitializeASI` 后实机确认修复。不得恢复 DllMain 业务初始化。

### test3：EXE 目录硬拼 Win32 路径

用 `<RPG.exe目录>\Save\Save091.TSF` 判断自动档，连续自动保存都误选 91。不得再用 EXE 目录硬拼来判断游戏 TSF 是否存在。

### test4：Win32 相对路径探测

改用 `Save\Save091.TSF` 相对路径后，SaveSlot 返回成功，Win32 仍看不到游戏文件层中的槽 91。test5 改为游戏 File 对象。不得恢复 GetFileAttributes/GetLastError/FILETIME 作为 TSF 权威。

### Windows LastWriteTime 选最旧

旧文档曾写“九槽全满后按 LastWriteTime 覆盖最旧”，当前源码没有这样做。游戏 TSF 对 Win32 不可见时无法可靠取得时间，因此当前改用 `multimedia\save\.NEXTAUTOSLOT` 持久化环形游标。

### INI `[Internal] NextAutoSlot`

短暂实现过，但用户明确否定。INI 容易在复制配置、重装或替换时丢失轮换状态。当前必须写 `multimedia\save\.NEXTAUTOSLOT`，不得恢复 INI 写回。

### 用游戏内部 File::Read/Write 保存状态

曾按 `0x441A30/0x441AB0` 调用游戏内部读写函数，机器静态检查通过，但用户实测游戏崩溃。
该候选已通过中文 Git 回退提交撤销，不得在没有完整崩溃定位前恢复。当前只保留已验证可用的
Game File `Open(mode=1)` 来判断 TSF 是否存在；三字节状态文件继续走日志同款 Win32 文本写入。

### `source_alt` 保留槽方案对比与 test7 落地

- 已吸收：owner 字段先解引用成真实 `SaveSlot*`，disabled 逻辑能找到真实窗口；
- 不可整文件照搬：备选源码会恢复 INI `NextAutoSlot`、重新引入 MSVC C2488 裸函数声明错误，
  并直接二次 Hook Controller 已占用的 `0x426365`；
- 手柄迟钝根因已确认：Controller 进入三项窗口时把私有 `action_focus` 初始化为 index2=存档；
  备选 wrapper 只把 index2 的 HitTest 隐藏，却没有把 Controller 焦点迁到 index1=读档，
  因而会出现“没有任何高亮、按 A 无反应、需要多按一次方向”的确定性死焦点；
- test7 没有修改 Controller。SaveEnhance 从 PadSupport Public API v1 读取语义输入，在自己的
  RPG.exe wrapper 中独立维护读档/取消两项焦点；普通槽始终链回安装前目标；
- 当前仍需实机确认鼠标接管、加载顺序和二次确认窗口边界，不把机器 PASS 写成实机 PASS。

### 批量重命名 91~99

一次自动存档会修改多个文件，中途失败可能破坏整条历史。当前每次只让原版 Writer 改一个 TSF，不采用。

### TSA/YCS 精确旁挂

历史实验存在路径语义和写入时机问题，当前正式实现不读取、不写入 TSA/YCS。它们不是本版本依赖。

## 九、兼容与安全边界

- 只支持锁定的 RPG.exe；
- 旧 `AnytimeSave.asi` 与 SaveEnhance 会竞争相同 Hook，必须移除；
- 未知插件先改目标机器码时 SaveEnhance fail-closed；
- Save001~Save159 是外部人工流程档，不能证明原版槽位容量；
- Controller 只通过 Castle_PadSupport API v1 读取状态，不读写私有全局；
- 状态文件异常只影响跨重启环形游标，不应让当前 TSF 保存结果变失败；
- 自动/Quick 的静态验证不证明剧情、战斗、楼梯等运行时门一定正确。
