# Castle_FPSUnlock v1.4 实验版使用说明

## 目标

原版 Legacy Logic 保持约 20Hz；普通探索世界层尝试额外 Render/Present 到约 60FPS。EVE WAIT、
Battle、AI、RNG、SF2 倒计时和完整 GUI Draw Queue不提频。

## 安装

FPSUnlock 不进入正式 build_all。手工测试时把以下文件放到同一 ASI 目录：

```text
Castle_Runtime.dll
Castle_FPSUnlock.asi
Castle_FPSUnlock.toml
```

原始光盘 EXE 还需要 NoCD。旧 FPSUnlock 版本不能并存。

## Runtime 协调

- Runtime Hook 负责代码写入；
- Runtime Render 负责 RenderQueue/Present 门面和额外帧租约；
- Runtime GameState 保护 Camera/Draw/Dialogue/World 资源；
- Runtime Clock 管理 1ms 精度租约；
- Runtime Module 解析系统计时能力；
- Runtime TOML 读取配置；
- Runtime Log 写 `mods/logs/Castle_FPSUnlock.log`。

FPSUnlock 不再读取 `0x44A9C6/0x44A9E6` 的当前 CALL 目标，也不依赖 Widescreen 加载顺序。

## 配置

```toml
[FrameRate]
Enable = 1
TargetFPS = 60
LogStats = 1

[Interpolation]
MaxPredictionStep = 96
```

模板中每个键有完整单位、范围和用途说明。当前目标固定 60；MaxPredictionStep 防止传送和切图
被误当连续运动。

## 安全回退

标题、对话、菜单、Battle、Bink、Camera shake、特殊 world overlay 和不安全游戏状态保持原版
20Hz。没有运动历史时可重复当前世界画面，但不能凭空修改逻辑状态。

## 观察重点

普通自由探索 15～30 秒后，先看日志中的 `ExtraPresent` 是否持续增长。只有额外 Present 确实发生，
才继续评价 Camera 和角色插值视觉。

理想稳态约为：

```text
20Hz 原版 Present + 40Hz 额外 Present ≈ 60FPS
```

本插件仍未完成。任何游戏异常、UI 提频、宽屏错位或逻辑速度变化都应视为失败，详细步骤见
《实机验收说明.md》。
