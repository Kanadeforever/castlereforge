# Castle_FPSUnlock v1.4 构建说明

## 状态

FPSUnlock 仍是未完成实验项目，已经迁入 RuntimeSDK，但不进入根 `build_all.bat`。它必须单独
构建和单独实机验证，不能把可编译误写成正式发行。

## 文件

```text
src\FPSUnlock\source\Castle_FPSUnlock.cpp
src\FPSUnlock\source\Castle_FPSUnlock.def
src\FPSUnlock\templete\Castle_FPSUnlock.toml
src\FPSUnlock\build.bat
```

构建还会直接编译 RuntimeSDK Client 三个 C 单元，不复制 SDK 源码。

## 运行

```bat
src\FPSUnlock\build.bat
```

输出到仓库根：

```text
build\Castle_FPSUnlock.asi
build\Castle_FPSUnlock.toml
```

中间 obj/lib/exp 只进入 `src/FPSUnlock/_build` 并在结束时清理。

## 工具链

- clang-cl 与 lld-link；
- i686-pc-windows-msvc；
- `/W4 /WX /GS- /GR- /Oi- /utf-8`；
- `/nodefaultlib /machine:x86 /entry:DllMain@12`；
- Runtime Client 的无 CRT support 对象；
- 不读取开发者物理编译器路径。

## 必须验证

- PE32/i386、DLL、非零入口；
- `CastlePlugin_Query`、`InitializeASI`、`CastleRuntimeClient_NotifyLoaderReady`；
- 官方 Client 设置 REQUIRE_RUNTIME；
- 配置为 TOML且每键有中文说明；
- 日志由 Runtime 写入 `mods/logs`；
- 不读取 Widescreen 当前 CALL 目标；
- Hook/Render/Clock/GameState/Module/TOML/Log 均来自 Runtime；
- 不出现在 build_all 正式发行树。
