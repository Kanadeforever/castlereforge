# 数据目录说明

> 适用节点：固化68（2026-08-22）。以后每次新增、移动、合并或删除机器数据，都必须同步更新本文、旧路径映射和完整接档。

## 数据是什么

`数据/`保存调查器、解析器和审计器产生的机器可读结果，当前主要是JSON和CSV。它回答“机器核对得到了什么结果、有哪些记录、哪些断言通过”，但通常不保存完整反汇编、图片或原始资源；后者在同主题的`证据/`中。

不要只看文件名或`PASS`字段就给未知字段命名。每份主题JSON的“范围限制／边界／UNKNOWN”与对应证据同样属于结论。

## 新目录结构

```text
数据/

  00_目录索引与路径映射/
  01_版本基线与封包审计/
  02_公共数据加密与数据库/
  03_事件与脚本系统/
  04_场景实体界面与存档/
  05_资源容器与配置/
  06_图像动画与音频/
  07_战斗核心对象与随机数/
  08_战斗公式资源与物品/
  09_战斗状态效果与场域/
  10_战斗动作结果与表现/

```

每个业务主题之下继续按`固化节点或基础阶段/机器结果或表格明细/文件名`保存。也就是说，人类先找主题，再看研究时间线，不再先猜“固化47到底研究了什么”。

## 人类阅读顺序

1. 从本文确定主题。
2. 到对应主题中选择最新相关固化节点；如果需要格式初始规格，再读`基础阶段`。
3. 先读主题JSON中的目标、输入哈希、结论和边界。
4. CSV用于逐记录筛选和排序，不能脱离JSON的字段口径单独解释。
5. 转到`证据/`中的同主题、同固化节点，核对反汇编、资源样本或图片。
6. 若历史文档给出旧路径，用`00_目录索引与路径映射/固化66资料整理版1_资料分类总索引.csv`搜索。

## 目录索引与路径映射

- `固化66资料整理版1_旧路径到新路径映射.json`：原`数据/`和`证据/`共1033个文件的逐项旧路径、新路径、分类理由、大小和SHA-256。
- `固化66资料整理版1_资料分类总索引.csv`：适合人类在表格软件中按主题、节点、类型或原路径筛选。
- `固化66资料整理版1_主题目录机器摘要.json`：各主题、节点和资料类型的数量统计。
- `固化66资料整理版1_工具目录历史输出迁移记录.json`：解释为何`当前样本验证结果.json`从工具目录移入资源容器主题。
- 当前完整包索引在封包最后生成；旧固化节点的“全文件索引”已经归入`01_版本基线与封包审计`，只适用于当时版本，不能用于验证当前目录。
- 固化68会在封包最后新增`固化68_资料分类总索引.csv`、`固化68_主题目录机器摘要.json`和自排除的`本版本全文件SHA与遍历索引_固化68.json`；索引生成后文档冻结，不再改写业务资料。

## 关于整理版删除的JSON

固化64整理版1曾移除7个逐字节完全相同的JSON副本和2个完全相同CSV副本；对应保留路径、大小与SHA-256均记录在原`精简删除与合并映射.json`，现可通过本次旧路径映射定位。另移除的`工具/--help/证据/数据与证据整理映射.json`是旧工具误把`--help`当目录后生成的178字节产物，不含研究结论。

以后即使两个文件SHA-256完全相同，也必须同时满足以下条件才能合并：

- 保留一份可直接找到的实体。
- 人类说明文档列明原路径、现路径、理由、哈希和恢复方法。
- 机器映射逐项记录。
- 不同字节的历史结果一律不得因“看起来过时”而删除。

## 以后新增数据的固定规则

- 不得把新JSON/CSV散放在`数据/`根目录。
- 路径固定为`数据/<主题>/固化N/<机器结果或表格明细>/文件名`。
- 一个文件横跨多个主题时，以主要consumer所在主题为主，并在JSON中列出交叉主题；不能复制多份制造漂移。
- 每完成一个固化节点，都要更新本文的数量、代表性入口、未知边界和旧路径映射。
- 失败记录保留在`01_版本基线与封包审计`，文件名必须明确写`失败`或`FAIL`，不得冒充正式结论。
- 任何当前全文件索引都放在`00_目录索引与路径映射`，生成后正文冻结。
