# 证据目录说明

> 适用节点：固化68（2026-08-22）。以后每次新增、移动、合并或删除证据，都必须同步更新本文、数据说明、完整接档和证据清单。

## 证据是什么

`证据/`保存能让人复核机器结论的材料：反汇编、机器码摘录、文本锚点、资源样本、二进制代码片段、重建图片以及历史回归输出。它回答“结论凭什么成立”。

`数据/`中的JSON/CSV通常是工具整理后的答案；`证据/`是答案背后的原始或近原始材料。两者不能互相替代。

## 新目录结构

`证据/`使用与`数据/`相同的主题分类表；只建立有实体证据的主题目录。当前共有10个非空入口：

1. `01_版本基线与封包审计`
2. `02_公共数据加密与数据库`
3. `03_事件与脚本系统`
4. `04_场景实体界面与存档`
5. `05_资源容器与配置`
6. `06_图像动画与音频`
7. `07_战斗核心对象与随机数`
8. `08_战斗公式资源与物品`
9. `09_战斗状态效果与场域`
10. `10_战斗动作结果与表现`
11. `11_运行时输入时钟与显示`

分类表中的`02_公共数据加密与数据库`当前只有`数据/`侧4份机器结果，没有独立ASM、文本、图片、样本或证据侧结果，因此本包不制造空证据目录。以后取得该主题的原始/近原始证据时，再按同一编号建立目录并同步本文。

## 固化67至68新增证据入口

- `证据/10_战斗动作结果与表现/固化67/反汇编`：4份ASM，覆盖`0xBBD`结束/保持门、四值白名单消费者、FightRole初始化和邻接复制边界。
- `证据/10_战斗动作结果与表现/固化68/反汇编`：5份ASM，覆盖请求分派跳表、`0x67`和`0x68`来源/记账、直接上游和Battle Tick同步。
- `证据/01_版本基线与封包审计/固化68/反汇编`：原版盘符枚举、光驱类型和`MultiMedia\Mov`探测路径。
- `证据/07_战斗核心对象与随机数/固化68/反汇编`：MiscInfo六槽清理差异、RoleDefinition八运行通道回写差异。
- `证据/11_运行时输入时钟与显示/固化68/反汇编`：窗口/DirectDraw呈现分流和Bink默认表面锁定复制解锁。

以上ASM均为固定原版或原版/研究版明确标识的近原始反汇编。它们证明声明的代码区间，不证明未覆盖的间接调用，也不证明尚未执行的兼容补丁有效。

每个主题之下按`固化节点或基础阶段/证据类型/文件名`保存。证据类型固定为：

- `反汇编`：`.asm`，通常由原版Oracle的固定VA区间产生。
- `文本摘录`：`.txt`，包括字符串、源码路径、关键地址或机器码说明。
- `图像证据`：`.png`，包括资源重建和界面状态对照。
- `原始资源样本`：`.SF2`，保持原始字节供重新解析。
- `二进制片段`：`.bin`，固定地址范围的原始代码字节。
- `机器结果`：`.json`，属于证据侧的调用图、资源解析或历史回归记录。
- `表格明细`：`.csv`，证据侧逐项枚举表。

## 人类复核一项结论的顺序

1. 在`数据/`中找到主题JSON并确认输入文件SHA-256。
2. 记下固化节点、关键VA、资源名和声明的覆盖边界。
3. 进入本目录的同主题、同固化节点。
4. 优先读该节点的`反汇编证据清单.json`或相关机器结果；再打开ASM、TXT、PNG、SF2或BIN。
5. 对固定VA证据，核对Oracle身份、区间起止和机器码；对资源证据，核对资源SHA-256、容器来源和解析器版本。
6. 最后回到完整接档，确认该结论是否仍为当前结论、历史失败还是负证据边界。

## 历史路径怎么找

所有1033份原`数据/`和`证据/`文件都保留原文件名和SHA-256，只改变路径。使用：

`数据/00_目录索引与路径映射/固化66资料整理版1_资料分类总索引.csv`

按旧路径、文件名、固化节点或主题筛选即可。机器程序应使用同目录JSON映射。历史Markdown和旧JSON中的旧路径不会被篡改，因为它们本身也是研究历史；映射是现行跳转层。

## 证据可信等级

- 原版Oracle固定字节、原始资源字节和可独立重放结果：最高优先级。
- 由明确工具从上述输入生成且哈希/断言通过的JSON、CSV和重建图：可复核派生证据。
- 历史研究版EXE证据：必须同时注明研究版身份；关键结论应与完全未修改原版比对。
- 负证据：只说明已覆盖搜索面没有命中，不能扩大成“字段无用”“状态不可达”或“永远不会发生”。
- 历史失败与预审记录：用于防止重踩，不得当作当前正式结果。

## 以后新增证据的固定规则

- 不得把新证据散放在`证据/`根目录，也不再创建单一`证据/阶段D/固化N`入口。
- 路径固定为`证据/<主题>/固化N/<证据类型>/文件名`。
- 每个新节点至少提供一份机器证据清单，列明文件、范围、输入身份、SHA-256和证明目标。
- 原始/近原始证据只允许移动和复制校验，不允许为了“好看”改写内容。
- 图片必须在数据或清单中说明来源资源、生成工具和用途；不能只放一张无说明截图。
- 研究版与原版材料在文件名中明确区分；不能把高度相似当成同一文件。
- 每次移动、合并或去重都要在人类说明和机器映射中同时记录恢复方法。
- 每完成一个固化节点，本文、`数据/数据目录说明.md`、`工具/工具目录说明.md`和完整接档必须一起更新。
