固化39：SF2 Layer +0x06..+0x09 结构结论

一、全语料范围
- SF2出现数：672
- 唯一SHA-256：506
- 唯一标准SF2：505
- 已知非标准SAF：1
- 标准SF2 Section0记录：9333
- 29-byte Layer记录：11184

二、关键结构证据
历史文档把 +0x06 与 +0x08 分成两个 i16 未命名字段。固化39重新按原始四字节整体解释：

    +0x06 i32 serialized_metadata_i32_06

11184/11184条Layer中，旧两个i16视图的配对严格只有：
- (-1, -1)：883次；
- (非负低16位, 0)：10301次。

因此按小端有符号32位读取时，全部值严格是 -1 或 0..48（中间部分值未出现）；高16位始终恰好等于低32位值所要求的符号扩展，没有反例。

三、运行时直接读取边界
同版RPG.exe中两套已确认标准SF2 Layer构造/绘制家族：
- 0x407270 -> object+0x50 -> 0x407510 / 0x4075E0 / 0x407AC0；
- 0x428ED0 -> object+0x3C -> 0x4290A0。

这两套canonical直接绘制链均消费Layer +0x00/+0x02/+0x04/+0x0A/+0x0B/+0x0D/+0x0F，但未直接消费 +0x06..+0x09。

四、证据边界
- 已闭合：磁盘结构应保存为一个little-endian signed i32，而不是两个互不相关i16。
- 已闭合：两套canonical直接渲染家族不直接读取该i32。
- 未闭合：作者业务名称/编辑器含义；指针别名、虚表/间接调用或其他非canonical消费者不能凭本轮证据形式化排除。
- 兼容引擎必须原样保留该i32；在没有新证据前不得把它命名为track/layer/parent/scale/transform，也不得因为当前renderer不读取就删掉。
