# 模组目录与配置说明

## 当前布局

```text
游戏根目录\
├─ RPG.exe
├─ CastleModLoader.exe
├─ ddraw.dll                     ← 可选；当前稳定实机方案为 cnc-ddraw
└─ mods\
   ├─ CastleLocaleBootstrap.dll  ← Loader 内部
   ├─ CastleModCore.dll          ← Loader 内部
   ├─ CastleModLoader.ini
   ├─ mods.ini
   ├─ logs\                      ← Loader、Runtime 与各 ASI 日志
   ├─ asi\                       ← ASI + 同名 TOML + Runtime + 依赖 DLL
   └─ overrides\                 ← 文件 Mod
```

用户 DLL 不放 `mods\` 根目录。dev9 保留 `SetDllDirectoryW(mods)` 作为已封存兼容环境，但目录规范不变。

## ASI

从上到下加载。`名称.asi` + `名称.toml` 时 GUI 显示“编辑”。编辑器只接受 UTF-8 或 UTF-8 BOM，并按 Runtime TOML v1 的标量结构检查后原子保存。加载使用绝对路径 + `LOAD_WITH_ALTERED_SEARCH_PATH`，因此 Runtime 和其它依赖仍与 ASI 放 `mods\asi`。

Loader 自己的 `CastleModLoader.ini` 与保存启停/顺序的 `mods.ini` 继续使用 INI，它们不属于 ASI 同名 TOML 编辑器的管理范围。

## Overrides

越靠下优先级越高。只处理读取型文件请求。

## `mods.ini`

保存 ASI 与 Overrides 的启停状态和顺序。GUI 每次启停/拖动/移除都会原子写回。

Core 启动扫描和 GUI“重新扫描”发现新 Mod 时，都会把新条目追加到最后一个同名节的末尾。若节末已有用于分隔下一节的连续空行，新条目会插在这些空行之前：

```ini
[ASI]
BUGFix=1
Castle_Backlog=1

[Overrides]
示例文件Mod=1
```

因此 `[ASI]` 表头下不会再出现错误空行；空行只负责分隔 `[ASI]` 与 `[Overrides]`。已有注释、未知节、条目顺序和 `0/1` 开关继续保留，写回仍采用同目录临时文件、Flush 和原子替换。

## About

`about.h` / `about.cpp` 位于源码目录，不属于 `mods\` 运行时目录；修改 About 文本需要重新构建 `CastleModLoader.exe`，不会改变 `mods.ini` 或 Loader 配置。 about5 的标题栏修订同样只属于 Launcher，不改变任何 Mod 目录语义。
