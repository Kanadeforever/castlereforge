# Castle_Quest 任务制作逐步入门教程

## 先判断你在改什么

如果是在修正原版任务事实，编辑 Base `Qxxx.toml`；如果只是想改玩家看到的目标、备注、Marker，优先写同名 Addon `[[override]]`；如果要在两个原版阶段之间增加 Remastered 人工体验，写 Addon `[[insert]]`。

不要为了体验效果往 Base 新增假 Stage。Base v7 已经没有 `stage_type`。

## 覆盖现有阶段

```toml
[[override]]
stage_id = "find_aping"
player_notes = [
    "阿平可能在家后面的那条路",
    "注意李大夫家右边的小道"
]
```

只写出的字段会覆盖 Base，其余字段继续继承。

## 插入人工步骤

先在 Base 找到两个真实且相邻的 Stage ID，例如 Q004 的 `ask_mother` 与 `world_trigger`，然后：

```toml
[[insert]]
stage_id = "investigate_aji_clues"
after = "ask_mother"
before = "world_trigger"
objective = "向孩子打听阿吉的消息。"
scene = "mp0101"
runtime_event = "33"
world_x = "663"
world_y = "734"
```

两个锚点不相邻时程序硬报错，不会静默插入到错误位置。

## 热重载

Ctrl+F8 是整库事务：manifest、25 Base、25 Addon 全部成功才提交。dev6zd 起成功热重载保留当前进程中已完成的稳定 Addon Stage ID。

## 原版进度纪律

Quest 只读 GameVar/Item/Scene/Event 等原版状态。任何 Base 条件修正都应有原版 EVE/EXE/GameVar writer 证据；不要为了“看起来能走”发明状态值、写 Var 或把可选对白当硬进度。
