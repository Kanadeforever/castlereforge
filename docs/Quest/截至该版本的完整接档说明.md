# 《幽城幻剑录》Castle_Quest v0.1-dev6zd — 截至该版本的完整接档说明

## 1. 本版定位

本版是在 dev6zc 全量 Base 审计之后进行的主项目迁移版。核心工作是：把 Quest 移入 CastleReforge `src/Quest/`；最小正确接入 RuntimeSDK；彻底删除旧 Guidance/人工 Base Stage 体系；让 Ctrl+F8 保留当前进程的 Addon 完成集合；冻结未来 `.state` 由主 SDK 统一管理的边界。

## 2. 永久安全原则

原版 GameState 是剧情唯一权威。Quest 只读 GameVar、Item、Scene、Event、战斗/实体状态，不写原版变量，不改变 TSF。Base 只解释原版事实；Remastered 人工体验只存在于 Addon。

目标游戏基线为原版 `RPG.exe.org` SHA-256 `8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f`，PE32/x86，ImageBase `0x00400000`。Quest 仍使用大量已验证绝对 VA，因此 Integrated 模式也必须确认实际 game_module 基址为 `0x00400000`，Runtime 的 module+rva 只负责补丁所有权，不把整套 Quest 自动变成可重定位模块。

## 3. RuntimeSDK 接入

插件稳定 ID：`org.castlereforge.quest`。导出：`CastlePlugin_Query`、`InitializeASI`、`CastleRuntimeClient_NotifyLoaderReady`。

Standalone：只有同目录完全没有 `Castle_Runtime.dll` 时，Quest 才自己 `VirtualProtect` 安装两个 6 字节 E9 Hook。

Integrated：`0x00409580` ExplorationUpdate 与 `0x004064E0` Present 使用 Hook v1 `ExclusivePatch`，在同一事务中 Begin → Add → Preflight → Commit。Quest 自行建立 trampoline 供 Hook 调原函数，但不直接写 RPG.exe 入口。

Fault：Runtime 文件存在但不可安全使用时，只记日志，禁止偷偷回退私有 Hook。

## 4. 关键运行地址

ExplorationUpdate `0x00409580`；Present `0x004064E0`；WorldPtr `0x00978508`；Camera `0x00978514/0x00978518`；DataCenter `0x008E1C48`；Active Event `0x0089F808`；GET_VAR `0x0044B0D0`；MouseWorld `0x0089F7C0/0x0089F7C4`。

RuntimeEntity：世界 X/Y `+0x10/+0x14`，SF2 controller `+0x6C`，source SCI `+0x70`，SCI Touch EA `+0xEA`，Manual EB `+0xEB`。探索管理器 `this+0x1C` 数量、`+0x2C` RuntimeEntity**。

## 5. 任务数据格式

运行目录 51 TOML：25 Base v7、25 Addon v2、1 manifest v7。Base Stage=146、Canonical=146、Guidance=0、Warning=0、Stage Route=556、实际 Addon Insert=1。

Base v7 不再存在 `stage_type`、`guidance_scene`、`[[warning]]`。Manifest 不再存在 guidance/warning 计数。

Addon `[[override]]` 和 Base 公共字段同名；`[[insert]]` 必须用稳定 `stage_id` 与相邻 `after/before`。

## 6. Q001/Q002/Q004 当前真相

Q001 取鸡汤 Event18 是真实 Var1=0→1 原版阶段。稳定 ID `guide_get_chicken_soup` 因兼容既有数据继续保留名称，但没有 Guidance 语义；Q001 Active 覆盖 Var1=0。

Q002 彩石弹珠 Event37 后是 `Var505=1, Var1008=0, Var1007=1`，因此 `find_doll` 必须显示；dev6zc 已补顶层 Active/Journal，dev6zd 继承。

Q004 营救阿吉主进度是 Var504；Event32 的 Var503 不是阿吉进度，Event33 只提供线索。旧 Base `optional_clues` 已删除；Addon `investigate_aji_clues` 插入 `ask_mother -> world_trigger`，目标 Event33/左侧孩子/663,734。

## 7. Addon 完成状态

当前仍是进程内集合。dev6zd 成功 Ctrl+F8 不清空集合，键只认 `quest_id + stage_id`；同时已删除按 `Available/Unavailable` 猜测存档回退并擦除完成键的旧规则，因此同一进程内完成键只增不减。这样才能保证修改 Base/Addon 条件也不会间接复活已完成人工步骤。

当前限制也必须明确：在主 SDK per-save `.state` 尚未接入前，同一进程读取更早 TSF 时人工完成集合不会自动回滚。正确方案不是重新用 QuestState 猜，而是未来由 SDK 在真实 Save/Load 生命周期中装入对应 TSF 的 `.state`。

跨游戏重启/跨 TSF 不持久化。本版不实现 `.state`。

## 8. 未来 `.state`

计划使用与 TSF 同名的 Remastered 增强状态文件，但文件读写属于主 SDK 的跨项目公共服务。SDK 未来负责 TOML parser/serializer、当前存档识别、模块命名空间、写入排序/并发、临时文件与原子替换。Quest 只保存无法由 TSF/GameState 恢复的人工 Addon 完成等新增事实，绝不镜像原版 GameVar。

## 9. Ctrl+F11

dev6y 修复保持不动：实体命中首选原版 MouseWorld，再使用与 Marker 同源投影；Win32 只作 Fallback。SDK 迁移没有修改鼠标算法。

## 10. 目录与构建

并入主仓后：`src/Quest/`、`docs/任务系统/`。Quest build 引用同级 `src/RuntimeSDK/include` 与 `client`，不复制 SDK。本子项目唯一构建说明为 `src/Quest/readme.md`。

Quest build 只发布 `build/Castle_Quest.asi`、`build/Castle_Quest.ini`、`build/Castle_Quest/`，绝不能清理共享 build 中其它模块。主 `build_all.bat` 后处理需要把 Quest 数据目录与 ASI 一起移动到 `build/mods/asi/`。

## 11. 已知开放项

`mp0705 Event15` 与 `mp0601-2 Event21` 的唯一 SCI 绑定仍没有足够原版证据，不猜对象/坐标。

真实 Windows x86 构建、Integrated/Standalone/Fault 三路实机以及游戏内完整回归仍需用户主仓环境验收。

## 14. 已确认成功方案、失败方案与踩坑汇总

已经确认并继续保留的成功方案：原版 GameState 是唯一剧情真相；Base 只描述原版链，Addon 只做人工体验；Route 归属具体 Stage；自动 Marker 必须依附当前场景真实 RuntimeEntity/Event，`TOUCH_EA` 必须有有效 TouchBox；Ctrl+F11 使用原版 MouseWorld；短 `player_notes` 的项目符号换行修复继续保留；RuntimeSDK Integrated 模式只通过 Hook 事务写游戏代码段。

已经明确退役、不得恢复的失败或高维护成本方案：独立 `routes.toml`；把四小鬼等体验提示伪装成 Base Guidance Stage；`[[warning]]` 失效警告运行系统；用 Var503 充当阿吉任务主进度；把离线 World/FrozenRouteWorld 当自动 Marker 的无条件运行时回退；热重载时直接清空 Addon 完成集合；根据 `Available/Unavailable` 猜测“读取了更早存档”并擦除人工完成键。

当前仍需防止的主要踩坑：Addon 的 `stage_id` 是持久身份，不应因改文案/坐标随意改名；Base/Addon 公共字段必须同名；Insert 的 `after/before` 必须同时存在且在 Base 原始链中相邻；Q002 `find_doll` 证明“Stage when 正确”仍不足够，Quest 顶层 Active/Journal 也必须覆盖该真实可达状态；共享 `.state` 未实现前不能声称跨存档保存人工完成状态。

研究依据方面，dev6zc/dev6zd 的全量校对使用了冻结 v0.6 研究与用户提供的 `任务分析_0.1.5_原版事件空间数据`。该大体量导出不重复塞入 Quest 源码包；现行 `src/Quest/tools/CastleScriptAnalyzer.py` v0.1.5 是只读事实导出器，工具接档文档记录了重新生成与使用边界。
