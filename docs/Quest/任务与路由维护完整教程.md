# Castle_Quest 任务与路由维护完整教程

## 运行文件

每个任务固定一份 Base 与一份同名 Addon。Base v7 保存原版任务条件、Stage 目标和该 Stage 的 `[[stage.route]]`；Addon v2 保存 `[[override]]` 与 `[[insert]]`。运行时无独立 `routes.toml`。

## Route 归属

跨场景导航边直接属于当前 Base Stage。只有已经达到运行安全标准的原版出口边才进入 `[[stage.route]]`。研究层的 1116 条条件化路由图仍可用于取证和恢复，但不是运行文件。

TOUCH_EA 自动 Marker 必须有有效 TouchBox，不允许因为“附近有实体”就退化成实体中心。MANUAL_EB 可使用真实 RuntimeEntity/SCI；确需人工世界坐标时只能使用显式 `manual_world_x/manual_world_y`，不得恢复旧 `FrozenRouteWorld` 思路。

## Addon 与 Route

Addon 当前主要用于展示覆盖和人工步骤，不维护第二份跨场景 Route 真相。人工 Insert 的目标场景、事件和坐标是体验层目标，但不改变 Base 原版路由图。

## Q004 示例

现行插入边为 `ask_mother -> world_trigger`。旧 `optional_clues` 已从 Base 删除，不能再把它用作锚点。

## 修改后的验证

至少检查标准 TOML 可解析、Base/Addon 25 对配对、manifest 数量准确、所有 Insert 锚点相邻、Stage Route ID 在当前 Stage 内唯一、旧 Warning/Guidance 字段不存在，并做 Ctrl+F8 事务回退测试。
