# Castle_Quest v0.1-dev6zd 实机验证清单

## 启动模式

分别测试三条 SDK Client 路径。无 `Castle_Runtime.dll` 时日志必须进入 Standalone，并成功安装 ExplorationUpdate/Present 两个本地 Hook；存在正常 Runtime 时必须进入 Integrated，并记录两个 ExclusivePatch 同事务提交；Runtime 文件存在但损坏时必须进入 Fault，且日志明确说明没有回退私有 Hook。

## 导出与装载

确认 Loader 可调用 `InitializeASI`；RuntimeSDK 能发现稳定 `CastlePlugin_Query`；两阶段 Loader Ready 可调用 `CastleRuntimeClient_NotifyLoaderReady`。游戏退出或显式卸载时不得出现 Hook 指向已卸载 Quest 模块的崩溃。

## 任务数据

启动日志应显示 manifest/Base v7、Addon v2，25 Quest、25 Addon、146 Base Stage、556 Stage Route、1 个 Addon Insert。不得出现 Guidance/Warning 运行统计。

## Q001 开局

Var1=0 时主线应直接显示真实取鸡汤目标；原版 Event18 令 Var1=1 后自然进入下一 Base Stage。这里不应出现任何 Guidance 特殊状态。

## Q002 彩石弹珠

与阿平交谈触发 Event37 后，在 `Var505=1 && Var1007=1` 状态必须显示 `find_doll`：调查孩子附近藏物点并指向 Event41。完成 Event41、Var505=2 后继续进入归还阶段。

## Q004 营救阿吉

Base 不再存在 `optional_clues`。原版 `ask_mother` 与 `world_trigger` 之间应显示 Addon `investigate_aji_clues`，目标指向 mp0101 Event33、左侧孩子、世界坐标 663/734。触发 Event33 后该人工步骤完成并进入原版 `world_trigger`；不写 Var503 作为阿吉进度。

## Ctrl+F8

先完成 Q004 Addon 插入，再只修改 Addon 文案或 Marker 坐标并 Ctrl+F8。热重载成功后该稳定 `quest_id + stage_id` 必须继续保持完成，不应重新弹出。故意写坏一个 TOML 时必须事务回退到上一套有效数据库。

## Ctrl+F11

继续验证 dev6y 已通过的鼠标命中：鼠标放在实际实体上应命中实体，不得恢复为必须偏移一段距离才能命中的旧回归。详情应优先使用原版 MouseWorld `0x0089F7C0/0x0089F7C4`。

## 构建产物

真实 Windows 构建必须是 PE32/x86，且精确导出三个 RuntimeSDK/Loader ABI 名称；根 `build/` 只能增加 Quest 可发行内容，不得出现 obj/lib/exp/pdb 等编译残留，也不得清理其它主项目模块已经发布的文件。
