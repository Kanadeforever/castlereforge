# Castle_Quest RuntimeSDK 迁移与增强状态规划

## 当前迁移结果

Quest 官方版强制依赖 `Castle_Runtime.dll`，不再保留本地 Present/Exploration detour：

```text
0x00409580 ExplorationUpdate → Runtime Schedule GamePhase
0x004064E0 Present           → Runtime Overlay
世界投影                     → Runtime Display.WorldToScreen
公共游戏状态                 → Runtime GameState
配置                         → Runtime TOML
日志                         → Runtime Log
```

Quest 只保留任务领域业务：Base/Addon、任务条件、Stage-local Route、Marker 内容、UI 排版、热键和
Addon Insert 状态机。Runtime 不理解具体任务数据。

## 生命周期

Client 设置 REQUIRE_RUNTIME。IntegratedInitialize 查询 Log/TOML 后初始化任务数据库，再登记
Schedule 与 Overlay。Runtime 缺失或故障时不读任务、不安装 Hook、不创建旁路日志；standalone
ABI 回调只返回 RuntimeRequired。

DllMain 只登记 Client。ModLoader 第二阶段或普通 Loader Entry Gate 进入同一幂等 Bootstrap。

## 显示坐标

Quest 不读取 Widescreen 配置，不固定加 107/240，也不复制 CameraPlan。普通探索时向 Display
提交 worldX/worldY；Widescreen 返回本帧有效 Camera、输出坐标、投影范围和 visibility。对白、
Battle、Hard4:3、Transition 等模式由 Display 决定是否可投影。

## 配置与任务数据

`Castle_Quest.toml` 的标量通过 Runtime TOML 读取。51 个任务数据库 TOML包含数组表和领域规则，
仍由 Quest 解析；当前 Runtime TOML v1 不假装覆盖复杂数据库。

Ctrl+F8 事务式热重载配置与 25 组 Base+Addon，失败时保留上一套完整数据库。稳定
`quest_id + stage_id` 的 Addon 完成键在同一进程中保持。

## `.state` 当前事实

本版不创建、不读取、不写入 `.state`。整个仓库目前也没有 `SaveXXX.state` 的实际消费者。
SaveEnhance 的 `.NEXTAUTOSLOT` 是三字节全局轮换游标，不是 `.state`。

## 未来 State 服务

当 Quest 或 SaveEnhance 第一次需要保存原版 TSF 无法表达的增强数据时，由 Runtime 新增专用
State 服务，而不是 Quest 自己开文件。要求：

- 原版 TSF 永不修改；
- 同名 `SaveXXX.state` 使用 TOML；
- Runtime 单一读写者和内存树所有者；
- `modules.<稳定插件ID>` 命名空间；
- 未知模块和字段保留；
- Save/Load/NewGame 生命周期；
- 并发提交排序和原子替换；
- `.state` 缺失/损坏不阻断 TSF。

Quest 首个计划字段是 Addon Insert 完成集合；Base Stage、GameVar、Item、Scene 等可由原版恢复的
事实不重复保存。因为当前无消费者，本轮不为这项未来能力增加空的 Save/Load Hook。
